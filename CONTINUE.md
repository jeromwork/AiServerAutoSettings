# Продолжение на другом компьютере

Состояние исходников: 1 ноября 2026. Репозиторий содержит переносной код, а не состояние прежнего сервера или компьютера.

## Подготовлено

- Повторный вход теперь ведёт сразу к действиям с сервером: Enter — RDP, 3 — добавить/изменить папки, 13 — подключить сохранённые (имена обновляются), 11 — явно установить/настроить агентов, 2 — открыть приложение. Обязательных вопросов об установке и режиме перед рабочим столом нет. SSH-обслуживание — M и номер сервера. Синхронизация без агента поддержана отдельно; последующая установка подключает MCP к работающей копии без reseed. Выбранные проекты видны в обновляемом пункте S и через V; мышь нажимает оба пункта.
- Консоль поддерживает щелчок по строке [ ] (Win32 mouse input, прежний режим восстанавливается), числа через запятые/точки/пробелы, Git перед worktree, F для поиска в указанной группе папок. Вложенные репозитории теперь обнаруживаются и внутри родительского Git; запрет перекрывающегося seed сохранён. На текущем ПК readonly-поиск метаданных нашёл BackendLaravel и репозиторий админ-панели в группе eastclinic; дата BackendLaravel новее SpdAutomatization, но его оценка осталась частичной. Личные исходники не переносились.
- Консольный выбор проектов без отдельного окна: При пустом списке поиск стартует автоматически, Q повторяет поиск, Enter подключает отмеченные папки (без отметок — поиск), номера меняют отметки, N/P переключает страницы, S также сохраняет, 0 отменяет. Поиск любых Git-репозиториев/worktree в типичных локальных папках, свежие исходники сверху, сохранение галочек без автоматического переноса. Ограничения поиска и отсутствие Git показываются явно.
- Единый запуск через `01-setup-ssh.cmd`, проверка Windows PowerShell 5.1 и OpenSSH, первичный вход по паролю, локальные профили и SSH-ключи.
- Выбор проектов в консоли (WinForms сохранён только как явный -Window), обычные папки и Git worktrees; отдельные рабочие копии; мост Windows-команд и передача первого сообщения агенту.
- Runtime-скрипты и локальные fixture-тесты, без скачанных установщиков, личных профилей, идентификаторов устройств и адреса прежнего VPS.

## Точный незавершённый этап

Последняя живая проверка выполнена самостоятельно после повторных ошибок пользователя. Реальный выбранный проект передан на VPS из уже подготовленного архива (13 127 157 байт), распакован и получен в отдельную Windows receive-only копию: 2480 разрешённых файлов, 19 918 921 байт, ready/fresh hash barrier прошёл. Исходная папка не изменялась. Исправлены CRLF в передаваемых многострочных Bash-командах и ошибочный запрет обычных маршрутов `[id].tsx`: Linux/Windows ignore-экранирование проверено. Один промежуточный SSH 255 при manifest-upload повторён без переупаковки; добавлен единственный автоматический retry только для uploads, не для exec. Повторное подключение тоже прошло без source repack/upload/seed; после исправления ежеминутного rescan и small-file progress allocations финальный повтор занял 67,2 с. Владельческие тестовые клиенты/туннели после проверки закрыты, серверный проект и Windows-копия сохранены. Для работы нужен обычный пункт 13 обновлённого BAT, а не новый выбор папок.

В интерактивной консоли счётчик обновляется в одной строке, новый этап — новая строка; редкий строчный fallback остаётся при перенаправлении. Проверено настоящей приватной Win32-консолью: неизменный ряд, стирание хвоста и строка для следующего приглашения. Готовый архив имеет SHA-256 индекс; проверка повторного индекса заняла 0,15 с, исходники повторно не пакуются. Финальная сверка Windows-файлов сохранена, а обход через native IO ускорен без ослабления исключений/запрета ссылок. Небольшие файлы больше не получают отдельный 1-МБ progress-buffer. Плановый rescan — час при включённом fsWatcher, явная свежая проверка перед действием агента остаётся. Первый замер локальной сверки без callback — 9,2 с; под нагрузкой и с progress время отличается. Индекс не заменяет полную сверку живой копии.

Ниже — история предыдущих сбоев и проверок; утверждения о ещё не состоявшемся переносе относятся к тем этапам. Незавершённой остаётся приёмка двух физических Windows-хостов и настоящей модели/MCP/SDK, а не первый одиночный seed.

После успешной проверки Git пользователь дошёл до создания seed, но PS5.1 File.Open отказал на временном пути длиной 272 символа при существующем каталоге длиной 221. Причина подтверждена прямой native-проверкой: обычный длинный путь не открывается, extended Windows path работает. Добавлен общий Windows.Paths.ps1 для файлового IO архива, JSON/хешей, транспорта, снимков/вложенных файлов принимающей копии и runtime-конфига. Идентификаторы/сохранённые пути не менялись, профили/проекты не переносились, реестр и политики Windows не изменялись. В реальном служебном каталоге проверено create/read/delete только собственного уникального временного файла с путём 269 символов; пользовательские исходники и реальный seed при этой проверке не читались/не переносились. Регрессии воспроизводят state=221 и длинные staging/snapshot/replica paths на настоящем PS5.1, включая hash barrier и транспорт. Следующий шаг — перезапустить BAT и повторить пункт 13; успешный полный перенос ещё не объявляется подтверждённым.

Последний Git timeout теперь воспроизведён именно как в BAT: скрытый PS5.1 с открытым stdin управления и фоновым Console.ReadLine. Git наследовал этот pipe и зависал даже на rev-parse. Invoke-SyncGit теперь выделяет и закрывает свой stdin и удерживает Process.Handle; тот же readonly-вызов завершился примерно за 0,27 с. Это отдельная причина от размера архива; поздний журнал подтвердил отказ до seed/upload. Контрольный readonly-инвентарь текущего выбранного проекта: около 19 МБ разрешённых файлов (2480), не весь размер его каталога; содержимое исходников моделью не просматривалось и seed на VPS не запускался.

Добавлены живые этапы, байты/файлы/проценты, скорость/ETA отправки и время этапа в консоли и журнале. Первичное подключение и долгие операции допускают до 12 ч, отдельная проверка активности — 5 мин; короткий guard агента не расширен. Отправка архива возобновляется с серверного смещения, SHA256 проверяется до публикации; повтор использует готовый архив. Распаковка публикует новую папку атомарно, квитанция позволяет продолжить настройку без reseed. Архив собирается во временный файл с проверкой хеша копируемых данных и очисткой только собственных незавершённых артефактов. Реальные native fault-fixtures проверяют обрыв/продолжение/idle/heartbeat/64-bit; orchestration fixture — отказ после server seed и повтор до настоящего локального hash barrier. Linux/Windows server tests проверяют прогресс, квитанцию, отказ неверному binding/manifest, повреждённый архив и существующую папку. Большой двухчасовой перенос через реальный VPS ещё не проверен. Следующий шаг пользователя — перезапустить BAT и пункт 13; предыдущие выбор/профили сохраняются.

Предыдущий этап: после первой ошибки `Git scope command timed out` журнал содержал только эту строку, без команды, а прямые readonly-команды проходили быстро. Тогда добавлены подробности и 60-секундный seed-лимит; причиной считалась ещё не воспроизведённая задержка. Более поздняя проверка выше установила наследование stdin в managed-процессе. Подключение локального проекта не требует GitHub/GitLab; история/remote/учётные данные не переносятся. Успешный перенос пользовательского проекта после поправок ещё не подтверждён.

Дополнение после сообщения пользователя об ошибке RDP: сбой воспроизведён на действующем VPS. Основной desktop-check проходил, но повторный bootstrap падал в проверке clipboard: chansrv восстановил один собственный Unix socket с 0660, тогда как checker требовал 0600. Bootstrap теперь повторно проверяет и сужает права только двух собственных сокетов в приватной 0700-папке перед проверкой, без перезапуска рабочего стола. На VPS применена эта поправка и выполнена предусмотренная установщиком подготовка звука. Повторные bootstrap/audio завершились с кодом 0; с текущего Windows прошли проверенный SSH loopback→Unix-туннель и pinned RDP/TLS handshake. Это не подтверждение GUI-входа, звука или модельной приёмки.

Родитель BAT теперь одновременно дренирует stdout/stderr управляемых компонентов, сохраняет их в приватный журнал и показывает причину/путь при ошибке вместо ссылки на невидимое сообщение. Для протокола дочерних компонентов явно задан UTF-8. Выбор повторного подключения при пустом списке остаётся в меню проектов и объясняет варианты 1/2. Для загрузки новых функций меню нужно один раз перезапустить BAT; профили/ключи и серверные приложения настраивать заново не требуется.


Реализованы серверный каталог проектов, явное присоединение дополнительных host-подписок без seed, общий MCP-каталог устройств, обязательная адресация projectId/hostId/taskId и координация задач в Windows. Общий блок AGENTS.md/CLAUDE.md указывает на инструкции проекта без автоматического выбора последнего подключённого ПК; правила владельца сохраняются. Добавлен loopback preview в меню BAT. Старые сохранённые невыбранные кандидаты без binding и их последующий выбор проверяются отдельно.

Локально прошли: две подписки к одному источнику реальным закреплённым Syncthing в Linux (оба приёмника — Linux), повторное attach, сохранение более свежего сервера, добавление/удаление и исключения. На настоящем PowerShell 5.1 проверены два исполнителя одной среды, фоновый процесс с сопутствующей командой той же задачи, отказ чужой задаче, освобождение после stop/завершения и неверная цель. Два Linux Unix-брокера остаются одновременно подключёнными; старые вызовы без binding отвергаются. Preview проверен настоящим PS5.1 с fixture SSH и занятым локальным портом. Это не сквозная проверка физических Windows-ПК через VPS.

Следующий шаг приёмки — **один проход обновлённого BAT на двух реальных Windows-компьютерах с одним VPS и синтетическим проектом**, оставив оба BAT открытыми. Первый ПК повторно подключает/создаёт проект; второй выбирает «Присоединить» по тому же projectId. В официальном UI войдите в выбранный агент при необходимости, перезапустите MCP и откройте новую сессию серверной папки. Попросите агента показать windows_devices и поочерёдно выполнить разрешённый Write-Output 'remote-agent-model-smoke' на точных hostId с отдельным taskId. Затем создайте/удалите безопасный файл на VPS и подтвердите обе receive-only копии; отключите один BAT и убедитесь, что запрос к его hostId получает отказ без перенаправления. Исходные папки должны остаться неизменными. Пароли/MFA вводятся только человеком в штатном окне.

До этого не подтверждены: живые SSH-туннели двух ПК, восстановление после сна/разрыва на физической сети, работа реального эмулятора/USB/SDK, личный вход и действия модели, звук RDP и полная VPN-совместимость. VPS, production, пользовательские исходники и VPN в этой сессии не изменялись. Модельная приёмка отдельно от transport_smoke; fixture-тесты её не заменяют.

Не переносите прежние ключи, профили, аккаунтные файлы и настройки VPN. Не запускайте старые acceptance-сессии с жёстко заданными локальными путями: они намеренно не включены. Для работы достаточно README и меню установщика.

## Проверки этой поставки

Фактические результаты упаковки записаны в [PACKAGE-CHECKS.md](PACKAGE-CHECKS.md). Дополнительные `test-*` предназначены разработчику: часть требует Python, Linux/bash либо самостоятельно скачанный официальный архив Syncthing. Для обычного запуска установщика эти тестовые зависимости не нужны.

## Несколько людей

Привязки и выбор проектов ограничивают автоматическую синхронизацию каждым компьютером, но не обеспечивают изоляцию владельцев: Linux-учётная запись remoteagents, рабочий стол и конфигурации агентов пока общие. Каталоги проектов/узлов не имеют owner-ACL. Отдельные серверные учётные записи/окружения для отца и сына пока не реализованы; не выдавать текущую настройку за раздельный личный доступ. Сын может выбрать свой отдельный проект для своего компьютера, и он не подключается к компьютеру отца автоматически.

## Обновление: общий аккаунт, автоматический MCP

Пользователь выбрал общие приложения и разные проекты без отдельных Linux-пользователей. В режиме управления вход в RDP автоматически подключает сохранённые проекты, Agents=0 не отключает мост, установка приложений обновляет MCP без reseed. Инструкции устанавливаются глобально и для проекта: единственный узел выбирается автоматически, несколько требуют уточнения; цель фиксируется в задаче и не зависит от RDP. Codex регистрируется при наличии CLI; Claude — в user scope при наличии CLI.

Сквозная проверка на действующем VPS и Windows прошла: transport_smoke=true, status_smoke=true, server_edit_to_windows=true, fresh_barrier_command=true, fixture_cleanup_synced=true; код 0 (журнал 225729-d74728ce.log от 01.11.2026). Проверены адаптер, брокер, чтение Windows и две серверные правки. model_acceptance=false: поведение модели в UI, два физических Windows-ПК и установленный Claude этим не подтверждены. Служебный мост и синхронизация проверки остановлены после её завершения.
