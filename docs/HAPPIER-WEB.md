# Happier с нашего сервера (план А, решение владельца 16.11.2026)

## Зачем

Облачная страница Happier (`cloud.happier.dev`) в браузере:
- держит в памяти только 3 последних чата, остальные через 3 минуты стираются и при открытии грузятся заново;
- на скрытой вкладке браузера рвёт соединение (`visibilitychange` в `apps/ui/sources/sync/sync.ts`), при возврате
  переподключается и догружает пропущенное — секунды и десятки секунд;
- лимиты подписок видны только в настройках и у поля ввода, для Claude с setup-token — пусто.

Владелец: никаких расширений браузера, всё встроено. Поэтому наш сервер раздаёт **официальный подписанный
веб-интерфейс Happier** со встроенной добавкой, а кнопка «Открыть Happier» в RemoteAgents открывает его через канал.
Аккаунт, чаты и мобильное приложение остаются в облаке Happier (`api.happier.dev`), свой сервер Happier не ставится.

## Как устроено

```
Браузер ── http://127.0.0.1:47831 ── канал EXE (sing-box) ── сервер 127.0.0.1:<port> ── служба happier-web
                                                                                         ├─ /            официальный ui-web + добавка
                                                                                         ├─ /_remoteagents/health
                                                                                         └─ /_remoteagents/quotas
Страница ── напрямую https://api.happier.dev (HTTP + Socket.IO, CORS `*` проверен 16.11.2026)
```

- **Адрес сервера Happier**: необязательный `serverComponents.happierWeb.serverUrl`; иначе активный
  профиль `~/.happier/settings.json` (`activeServerId` → `servers.<id>.serverUrl`), иначе облачный API.
  Файл только читается, vendor-код не импортируется. Адрес задаётся штатно: `window.__HAPPIER_WEB_RUNTIME_CONFIG__ = {serverUrl: "https://api.happier.dev"}`
  до бандла (есть в релизе ui-web v0.2.21). Без этого UI считает сервером сам origin.
- **Origin постоянный**: `http://127.0.0.1:47831` (loopback — secure context, WebCrypto работает). От origin зависят
  `localStorage` и вход. При наличии локального ключа лаунчер выполняет автоматический вход (ниже);
  сохранённый вход в любой аккаунт имеет приоритет.
- **Добавка** (`<script>` в `<head>` до бандла, отдельный файл, без зависимостей):
  1. runtime-конфиг сервера (выше);
  2. `localStorage.HAPPIER_SYNC_TUNING_JSON` слить с `{sessionTranscriptRetentionRecentKeepCount: N, sessionRealtimeProjectionMode: "disabled"}`
     (N из конфига, по умолчанию 8) — штатный ключ Happier (`apps/ui/sources/sync/runtime/syncTuning.ts`);
  3. `document.visibilityState` всегда `visible`, `hidden` всегда `false`, события `visibilitychange`,
     `webkitvisibilitychange`, `freeze` перехватываются на `window` в фазе capture. `pagehide` не трогать;
  4. одноразовый вход через штатную форму `/restore/manual`, если получен корректный `#ra-login=`;
  5. плашка лимитов: тонкая полоса сверху вне React-корня, данные `/_remoteagents/quotas` раз в 60 с, отступ под неё
     у страницы, чтобы не перекрывать интерфейс. Нет данных — честно «нет данных», не 0%.
- **Почему свой код** (конституция §2): готового режима «держать чаты онлайн» и показа лимитов setup-token в Happier
  нет; правим не Happier, а только добавляем маленький скрипт к его официальному релизу.

## Обновление ui-web

Отдельный таймер (по умолчанию раз в 6 ч): последний не-prerelease релиз `ui-web-v*` с GitHub `happier-dev/happier` →
проверка `checksums-…txt.minisig` закреплённым ключом `RWQ85PZ7FyiukYbL3qv/bKnwgbT68wLVzotapeMFIb8n+c7pBQ7U8W2t`
(из `scripts/release/installers/happier-release.pub` Happier) → SHA256 архива → безопасная распаковка (без `..`,
ссылок, абсолютных путей) → вставка добавки → проверка (index.html отдаётся, добавка на месте) → атомарная смена
`current`. До публикации проверяются маркеры маршрута `restore/manual`, поля
`restore-manual-secret-input`, кнопки `restore-manual-submit` и контракта auth/storage в JavaScript.
При исчезновении любого маркера обновление отклоняется с причиной `UI auto-login contract missing`
в журнале updater; текущая версия продолжает работать. Это сохраняет работающий вход вместо молчаливой
поломки после обновления. Проверка маркеров — предохранитель от удаления контракта, а не доказательство
совместимости произвольной новой реализации; поведение проверяется браузерным тестом на закреплённом UI.
Хранятся `keepReleases` (по умолчанию 2) последних версий; хешированные файлы прежних версий тоже
раздаются, чтобы открытая вкладка догрузила старый chunk. Сбой обновления не трогает работающую версию.

## Лимиты

Один опросчик на сервере, страницы читают только кэш.
- Аккаунты Claude: managed `agents.claude` (`~/.config/remoteagents/claude.env`), `~/.claude/.credentials.json`,
  подключённые профили Happier (`~/.happier/servers/*/daemon/connected-services/homes/claude-subscription/<profile>/claude/claude-config/.credentials.json`).
  Повторяющиеся токены — одна строка. Подписи `acc1` → `20$`, `acc2` (также native/default) → `100$`; остальные — имя профиля или «Claude сервера».
- Claude со scope `user:profile`: `GET https://api.anthropic.com/api/oauth/usage` (как в Happier), раз в 30 мин.
  Только `user:inference` (setup-token): запрос `POST /v1/messages` с `max_tokens: 1` и чтение заголовков
  `anthropic-ratelimit-unified-{5h,7d}-{utilization,reset}`, `…-status`, раз в `claudeProbeSec` (по умолчанию 600).
  Запрос тратит ничтожную часть лимита; выключается `quotas.claudeProbe: false`.
- Codex: `~/.codex/auth.json` (OAuth), `GET https://chatgpt.com/backend-api/wham/usage`, раз в 5 мин.
- Gemini (Antigravity/`agy`): облачные методы (`fetchAvailableModels`, `retrieveUserQuota`) для Gemini 3.8 Flash
  отдают 100% остатка при реальных тратах, поэтому остаток берётся из `/usage` самого agy.
  `server/agy_usage_scrape.py` (cron, раз в 10 мин) запускает agy в tmux, вводит `/usage`, разбирает проценты
  «Weekly/Five Hour Limit Remaining» и время сброса и пишет `~/.cache/remoteagents/agy-usage.json` (0600).
  Опросчик читает этот файл; снимок старше 30 мин → «нет данных», а не 0%. Картинки (Nano Banana) не показываются.
  Токены agy скрипт не читает и не пишет: вход держит agy (вход не делать через `gemini` CLI с тем же аккаунтом — слетает).
- Строка показывает ОСТАТОК (100 − занято); жёлтый ≤ 20%, красный ≤ 5%. В JSON `usedPercent` остаётся «занято».
- В строке каждого окна видно время и дату (`18:40 17.11`); возраст данных остаётся только в подсказке.
- 429/`Retry-After` — пауза больше; 401/403 — статус «нужен вход», не 0%. Токены не попадают в JSON и журналы.
- Ответ: `{"schema":1,"accounts":[{"id","provider","label","status","fetchedAt","windows":[{"id","label","usedPercent","resetsAt"}]}]}`.

## Конфиг

Сервер (`serverComponents`, ставит root reconcile, входит в экспорт):

```json
"happierWeb": {"enabled": true, "port": 47831, "updateIntervalHours": 6, "keepReleases": 2,
               "keepChats": 8, "defaultPermissionMode": "yolo",
               "claudeAccountLabels": {"acc1": "20$", "acc2": "100$"}, "quotas": {"enabled": true, "claudeProbe": true, "claudeProbeSec": 600}}
```

При запуске Web и затем каждые 5 мин `happier_web_settings.cjs` согласует настройки активного
аккаунта через установленный Happier CLI: его шифрование и compare-and-swap для `/v2/account/settings`.
YOLO выставляется в `sessionDefaultPermissionModeByTargetKey` и в defaults пользовательских backend-профилей.
Добавка также оборачивает штатный `resolveNewSessionDefaultPermissionMode` по имени экспорта Metro:
это обходит встроенный профиль с `default`, который иначе имеет приоритет над настройкой аккаунта.
Подписанные upstream-файлы и списки встроенных профилей не переписываются. Изменения идут в
зашифрованные настройки аккаунта и native cache CLI; `~/.happier/settings.json` не содержит этих полей.
Обычный выбор прав внутри чата остаётся доступен; восстановленный черновик сохраняет свой выбор.
Подписи connected-service профилей записываются в `connectedServicesProfileLabelByKey`, включается
`featureToggles.connectedServices`. В панели появляется кнопка «Аккаунт чата», открывающая штатный
выбор подключённых профилей на форме нового чата (оба должны иметь статус connected в relay).
Если CLI несовместим, нет входа или сети, Web продолжает работать; reconcile повторится через 5 мин.
После установки нового кода: `systemctl --user restart remoteagents-happier-web.service`, затем
перезагрузить страницу. Секреты и `.env` этим механизмом не изменяются.

Компьютер (`happier`, конфиг вставкой):

```json
"happier": {"localWeb": {"enabled": true, "port": 47831, "serverPort": 47831}}
```

- Канал EXE поднимает постоянный вход `127.0.0.1:<port>` → сервер `127.0.0.1:<serverPort>` тем же способом, что вход
  SSH/Syncthing. Порт не перевыбирается при каждом запуске (иначе меняется origin). Занят — диагностика, кто держит
  порт, и запасной путь.
- «Открыть Happier» (трей и окно): `GET http://127.0.0.1:<port>/_remoteagents/health` (таймаут ~1,5 с, ожидаемый JSON)
  → открыть локальный адрес; иначе — прежний облачный `webappUrl`. `account.WebUrl` не подменяется.

## Автоматический вход

Кнопки трея, окна и мастера используют один resolver. После успешного health локального адреса он
читает `<home>\secrets\happier-account.key` (home — `%LOCALAPPDATA%\RemoteAgents`). Ключ должен иметь
канонический формат `HappierKey.Create()`: base32 от 32 байт, 52 символа, группы по пять, последняя — два;
пробелы/CRLF по краям файла убираются. Только такой ключ добавляется к локальному URL:
`http://127.0.0.1:<port>/#ra-login=<ключ>`. При отсутствующем, недоступном или неверном ключе и для
облачного запасного адреса URL остаётся прежним. URL с ключом и ошибки запуска браузера не журналируются.

Добавка в head синхронно убирает фрагмент через `history.replaceState`, сохраняя путь и query,
и кладёт ключ в sessionStorage только этой вкладки. Она проверяет legacy `auth_credentials` и
`auth_credentials__srv_…` (официальный `scopedStorageId`): любой сохранённый token, включая другой
аккаунт/сервер и token-only credentials, отменяет автоматический вход. Чужой вход не заменяется.
Для новой вкладки без входа выполняется один переход на `/restore/manual`, затем ключ удаляется
из sessionStorage до ввода. Через native setter + событие input заполняется React-поле
`restore-manual-secret-input`, после обновления React нажимается `restore-manual-submit`.
Поле очищается после нажатия. Нормализация, подпись запроса и сохранение credentials выполняются
исключительно кодом Happier: `normalizeSecretKey → authGetToken → login`; добавка credentials не пишет.
Ручной экран в этом бандле не имеет параметра для ключа; вызовы внутренних Metro-модулей не используются.

Фрагмент не передаётся HTTP-серверу и не входит в Referer; серверу не нужен секрет восстановления
(см. `accounts/server-account.mjs`). API получает штатный challenge, publicKey и signature, а не ключ.
После входа сам Happier хранит секрет в localStorage браузера — автоматический переход даёт ту же
экспозицию в браузере, что ручное восстановление ключом. До обработки фрагмент доступен браузеру;
после head-добавки его нет в текущем адресе/записи истории. Ключ не кладётся в query, DOM-атрибуты или журналы.

Отказ storage, несовместимая форма, таймаут ожидания формы (20 с) или отказ API оставляют обычный UI.
Переданный ключ годен для handoff 30 с, повторной навигации/попытки после reload нет, аккаунты автоматически
не создаются. Если файла ключа на ПК нет, остаётся обычный ручной вход ключом или QR.

## Компьютер

- `localWeb` — необязательный строгий объект; при наличии обязательны `enabled`, `port`, `serverPort`,
  допускается общая публичная подсказка `hint`. Порты — целые 1024–65535. Отсутствие объекта выключает вход.
- Клиентская схема принимает также описанный выше `serverComponents.happierWeb`, чтобы полный
  серверный экспорт применялся одним конфигом; серверные файлы/экспорт этой клиентской задачей не меняются.
- Транспорт читает `profile.happier.localWeb`, для прежней/ручной установки — `happier.localWeb`;
  явное выключение в profile имеет приоритет. Поле входит в ревизию для штатного reload.
- Фиксированный порт резервируется до остальных входов, API и блоков проб/SOCKS. При конфликте
  только `happier-web` исключается из конфига; статус и журнал содержат порт, доступные PID/путь процесса
  и действие владельца. Освобождение порта подхватывается при следующем запуске/перезапуске канала.
- Все кандидаты используют общий selector `active`; OpenSSH несёт вход через существующий `ssh -D`.
- Общий resolver трея/окна делает GET без системного прокси и редиректов, проверяет HTTP 200 и
  JSON-объект с логическим `ok: true`, ограничивает ответ 4096 символами. Таймаут 1,5 с охватывает
  заголовки и тело, проверка идёт вне UI-потока. При отказе открывается прежний облачный URL.
  Если облачного адреса нет и локальный недоступен, левый клик показывает окно программы.
  `account.WebUrl` и API-адрес не подменяются.

## Что проверить на Windows (вручную, после «да» владельца)

Вход в тот же аккаунт на `127.0.0.1:47831`, машины и чаты видны; Socket.IO доходит до WebSocket; скрытая вкладка
не рвёт соединение; 8 чатов переключаются без загрузки; плашка лимитов; перезапуск EXE и обновление ui-web не
меняют origin; занятый порт → облачная страница. Ограничение: экономия памяти браузера, сон компьютера и выгрузка
вкладки остаются — для `127.0.0.1` стоит добавить исключение «всегда активен».

## Уточнения серверной реализации (16.11.2026)

- Код: `server/happier_web.py`, `happier_web_release.py`, `happier_web_verify.cjs`,
  `happier_web_quotas.py`, `happier_web_common.py`, отдельная добавка `happier_web_addon.js`.
  Прежний Tampermonkey-вариант удалён. Официальные бандлы не переписываются.
- Данные рабочего пользователя: `~/.local/share/remoteagents-happier-web/` (0700).
  `releases/ui-web-vX.Y.Z/web/` — распакованная статика; рядом оригинальный архив,
  checksums, minisig и `release.json`. `current` и `previous` — атомарно заменяемые
  относительные ссылки. `state/quotas.json` — кэш 0600 в каталоге 0700.
  Неуспешная подготовка/проверка не меняет `current`; следующий запуск убирает
  оставшийся неподключённый каталог своей версии. Для отката рабочий пользователь
  запускает `python3 -I /usr/local/lib/remoteagents/server/happier_web.py rollback`.
  Следующее штатное обновление снова выбирает последний stable UI.
- User units: `remoteagents-happier-web.service`,
  `remoteagents-happier-web-update.service` (oneshot) и одноимённый `.timer`.
  Таймер: первый опрос через 10 минут, затем `updateIntervalHours` после завершения,
  случайная задержка до 5 минут. Node (`nodejs` в Debian/Ubuntu) нужен только для
  подписи, npm-пакеты не нужны. Reconcile загружает UI лишь при отсутствии локальной
  установки, проверяет health и восстанавливает units. `enabled:false` останавливает
  службу, таймер и выполняющийся updater, сохраняя данные.
- Опросчик — один поток внутри HTTP-службы: так не нужен второй набор units и
  межпроцессная передача секретов. Аккаунты перечитываются каждые 15 с, но запросы
  выполняются по индивидуальному расписанию 1800/300/`claudeProbeSec` секунд.
  `Retry-After` (секунды или HTTP-date) переживает перезапуск через кэш; 429 даёт
  как минимум удвоенный интервал. Последние удачные окна сохраняются при ошибке,
  вместе с возрастом и явным статусом. Перенаправления API запрещены, чтобы Bearer
  не ушёл другому origin. Refresh OAuth остаётся штатным CLI, токены только читаются.
  Повторяющиеся токены объединяются, предпочтительна подпись профиля Happier.
  Учитываются материализованные локальные профили, а не ещё не скачанные облачные
  credentials. Битый JSON одного источника не мешает остальным.
- Setup-token probe: модель `claude-haiku-4-5`, одно сообщение `Hi`, `max_tokens:1`,
  заголовки OAuth beta и Anthropic version. Реальный ответ провайдера в этой задаче
  не проверяется; при отказе показывается ошибка/«нужен вход», проценты не выдумываются.
- Плашка меняет padding страницы по собственной измеренной высоте, без transform
  React-корня и без верхнего z-index над модальными окнами. Проценты, статус и возраст
  видны в строке; время сброса и следующего опроса — в подсказке.
- Серверные границы: port 1024–65535; keepReleases 2–10; keepChats 1–100;
  updateIntervalHours 1–168; claudeProbeSec 60–86400. Значения по умолчанию прежние.
  Серверный фрагмент схемы — `server/happier-web.schema.json`; reconciler соединяет
  его с общей схемой без изменений файлов клиентской C#-части.
- Для offline/Docker-проверки `REMOTEAGENTS_HAPPIER_WEB_RELEASE_DIR` или
  `happier_web.py update --release-dir DIR` задаёт каталог с официальными архивом,
  checksums и minisig. Подпись тем же закреплённым ключом и SHA256 обязательны;
  обхода проверки и загрузки кода из релиза нет. При обычной работе используется GitHub.
  Путь стенда: `python3 server/tests/autodeploy/happier_web.py --release-dir DIR`.
  Контейнер запускается без сети, репозиторий подключается read-only; для сборки
  Ubuntu-образа нужны только пакетные репозитории. Общий runner включает его по
  `SERVER_HAPPIER_WEB_E2E=1` с указанной переменной каталога.

### Развёртывание из одного конфига

В мастер-конфиге включаются **оба** компонента: `serverComponents.happier` (CLI/daemon)
и `serverComponents.happierWeb` (страница). См. `server/server-components.example.json`.
Настройки выдачи `server/config-export.example.json` указывают `serverConfig` на публичный
снимок этого применения: повторно перечислять серверные настройки в выдаче не нужно.
`remoteagents config export` переносит оба компонента и строит `happier.localWeb`:
`enabled` и `serverPort` из happierWeb, локальный `port` по умолчанию равен серверному.
Явный `happier.localWeb.port` в настройках выдачи сохраняет уже выбранный локальный origin.
`serverUrl` допускает HTTP(S) origin без пути, query и credentials; явный адрес имеет
приоритет над native-профилем. При выдаче добавки native settings перечитываются, поэтому
смена активного сервера Happier не требует перезапуска веб-службы.

Контейнерный тест экспортирует конфиг штатной командой с обоими включёнными компонентами,
удаляет исходный контейнер, затем применяет полученный файл на чистом контейнере.
У обоих контейнеров сеть выключена и память ограничена 1500 MiB; контейнеры работают
последовательно. UI устанавливается из локального официального подписанного архива.
Happier daemon в этом тесте — подставной CLI/API; настоящие vendor installer, вход и
соединение с облаком этим стендом не проверяются. Клиентский Windows-канал и открытие
страницы относятся к параллельной клиентской задаче, здесь проверяется выдаваемый конфиг.

На общем сервере перед full suite, Chrome и docker build/run проверяется `free -m`:
при available < 2000 MiB — до 20 ожиданий по 60 с, затем явный skip. Тяжёлые проверки
идут по одной, с nice 10. Стенд удаляет контейнеры, временный экспорт и образ;
Chrome-тест завершает только собственную группу процессов.

### Проверка автоматического входа

`timeout 420 python3 -m unittest discover -s server/tests -p test_happier_web_login.py -v` проверяет официальный подписанный ui-web v0.2.21 в `/usr/bin/google-chrome`
через CDP pipe из Node без npm. Архив берётся из `REMOTEAGENTS_HAPPIER_WEB_RELEASE_DIR` (по умолчанию
уже скачанный `/tmp/happier-uiweb-research`); если его нет, скачивается закреплённый релиз с GitHub.
Подпись закреплённым ключом и SHA256 обязательны. При памяти ниже 2000 MiB этот целевой тест
сразу сообщает об отказе запуска, без ожиданий. Все внешние HTTP-запросы перехватываются до навигации,
WebSocket блокируется, внешний DNS выключен. Подставной `/v1/auth` проверяет Ed25519-подпись challenge;
настоящие аккаунты и запросы настоящему auth API не создаются.

Сценарии: новый вход и credentials от самого UI; очищенный фрагмент и сохранённый query; существующий
другой аккаунт и token-only вход другого сервера; неверный ключ; повтор без ключа; отказ auth и reload
без второй попытки. Проверка интерфейса и криптографии настоящая, ответ API подставной; Windows/живое
облако этим тестом не проверяются. Для выкладки нужны штатное обновление серверной добавки через
`serverComponents` и новая сборка EXE из main после принятия ветки.

Для точечного запуска URL-проверок лаунчера: `timeout 420 ~/.dotnet/dotnet run --project app/launcher/tests/PortableTests.csproj -c Release -- --happier-web`.
По правилу владельца от 16.11.2026 агент запускает только затронутые тесты один раз в конце,
общим бюджетом до 5–7 минут. Полные `server/tests/run.sh` и `app/launcher/tests/run.sh`
выполняет тот, кто вливает ветку в `main`. Ошибки вне правки фиксируются в отчёте без ремонта окружения.
