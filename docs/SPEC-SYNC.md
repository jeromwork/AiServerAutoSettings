# Требования: синхронизация как в Dropbox и Яндекс Диске

Решение владельца, 6 ноября 2026. Заменяет одностороннюю модель для новых подключений.

## Что меняется

| Сейчас | Нужно |
|---|---|
| Сервер `sendonly`, Windows только принимает | Обе стороны `sendreceive` |
| Правки на Windows не попадают на сервер | Правки идут в обе стороны |
| `.stignore` как белый список файлов, новые файлы появляются только после свежего снимка | Список исключений: всё синхронизируется, кроме исключённого |
| Отдельная служебная копия | Выбранная папка пользователя синхронизируется на месте |
| Подключение держит окно BAT | Подключение держит приложение в трее |

Движок остаётся Syncthing. Канал остаётся SSH-туннелем, пока этап VPN не добавит другой маршрут.

## Безопасность данных

- Секреты, ключи и `.git` не передаются ни в одну сторону. Набор исключений берётся из существующей политики `server-sync.py`.
- Первое подключение не удаляет файлы ни на одной стороне.
- Конфликт сохраняет обе версии (`.sync-conflict-*`) и показывается пользователю.
- Версии удалённых и изменённых файлов хранятся на обеих сторонах 30 дней (срок задаётся в настройках).
- Действующие подключения переводятся на новую модель только по команде владельца, по одному, с резервной копией настроек.
- Перед командой агента проверка свежести дополнительно требует отсутствия неотправленных правок и конфликтов.

## Приложение: функции

### Синхронизация

1. Двусторонняя передача, новые файлы видны без ручных действий.
2. Пауза на 30 минут, 2 часа, до включения; для всех папок и для одной.
3. Исключение файла или папки, выборочная синхронизация подпапок.
4. Ограничение скорости.
5. Автозапуск, переподключение после обрыва и сна.

### Трей

- Значок: синхронизировано, идёт передача, пауза, нет подключения, ошибка, конфликт.
- Прогресс: процент, объём, скорость.
- Меню: папки со статусом, последние файлы, пауза, ошибки и конфликты, открыть папку, настройки, журнал, выход.
- Уведомления об ошибках, конфликтах и обрыве, без потока сообщений о каждом файле.

### Контекстное меню

Регистрация в `HKCU`, без прав администратора. Команды передаются запущенному приложению через именованный канал; если оно не запущено, запускается.

| Где | Пункт |
|---|---|
| Папка не подключена | Синхронизировать с сервером |
| Папка подключена | Показать статус; Приостановить или Возобновить; Отключить, файлы останутся; Открыть журнал |
| Файл или подпапка внутри подключённой | Исключить из синхронизации или Вернуть; Показать версии |
| Фон внутри подключённой папки | Показать статус |

Пункт скрыт или недоступен, если не подходит к текущему состоянию. В Windows 11 пункты пока находятся в разделе дополнительных параметров.

## Очередность

- **Выпуск 1:** всё, что выше.
- **Выпуск 2:** значки состояния на файлах и папках в Проводнике, пункт верхнего уровня в меню Windows 11.
- **Выпуск 3:** файлы только на сервере со скачиванием по открытию (Windows Cloud Files API). Syncthing этого не умеет, нужен отдельный компонент.

## Критерии приёмки выпуска 1

На двух настоящих Syncthing (автотест):

1. Новый файл с сервера появляется на Windows-стороне, и наоборот.
2. Правка и удаление проходят в обе стороны, удалённая версия восстанавливается.
3. Одновременная правка даёт конфликтную копию, и приложение её показывает.
4. `.env`, ключ и `.git` не передаются.
5. Первое подключение с разным содержимым сторон ничего не удаляет.
6. Пауза останавливает передачу, возобновление догоняет.
7. Обрыв показывается как нет подключения и восстанавливается автоматически.

На Windows (проверяет владелец):

8. Контекстное меню появляется, подключает папку и показывает верный статус.
9. Значок и меню трея соответствуют реальному состоянию.
10. После перезагрузки и сна приложение восстанавливается само.
