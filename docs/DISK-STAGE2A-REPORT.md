# Диск: этап 2А, клиентский жизненный цикл

16.11.2026, ветка app/disk-solid. Изменения не выкладывались, не сливались и не пушились.
Все engine fixtures работают во временных HOME под /tmp; живые ~/Disk, RemoteDisk, службы
и компьютеры не использовались. Действующий контракт — DISK-CONTRACT.md, редакция 2.

## Что реализовано

- **H02**, клетки 5a/5e/10d/14c: Upload создаёт `rd-upload-v1-<UUID N>` до POST; журнал
  удерживает тот же ID при неизвестном исходе, включая эквивалентную запись Windows-пути
  и изменение регистра. Повтор неподтверждённого Upload сообщает «Ожидает сервер».
  Установщик ждёт настоящее предложение;
  после 30 секунд — «Ожидает сервер», без новой папки/ID/регистрации. Unshared legacy ID
  нельзя превратить PATCH в новое разрешённое предложение. Видимая коллизия — отказ с текстом
  «Имя занято на сервере». Невидимый серверный отказ остаётся ожиданием, пока локальный REST
  не даст предложение/подтверждение: удалённого доступа к серверному журналу в Q10 нет.
- **H03, Q3/Q4**, 6a–c/7a–e: наблюдатель пропавших корней по монотонным часам, grace 30 с,
  повторная проверка config/FS перед DELETE только регистрации. Недоступность базы/тома,
  ошибки доступа, ссылки/файлы, новый процесс/поколение, неверное время сбрасывают наблюдение.
  Доступная пустая база ПК позволяет отсоединить последний удалённый проект. Старые external/
  nested mappings отсоединяются с сохранением данных. Удаление файлов при сохранённом корне
  остаётся двусторонним. Переименованная/перенесённая копия автоматически не загружается.
  Внутри базы убирается старое оформление; BoundPath отличает перемещённый ini от актуальной
  привязки. При пустом event poll локальная сверка восстанавливает удалённую P без REST-регистрации
  и чтения db/status. Переименованная P остаётся обычной папкой, даже если пуста; снимается
  только оформление. После переноса LocalCopy старая P также восстанавливается.
  Перед DELETE подтверждённый ID сохраняется в каталоге заглушек: неизменённое предложение
  Syncthing может не прислать снова. Неподтверждённый Upload туда не попадает.
  Неизвестное внешнее место назначения не разыскивается по дискам.
- **H07/Q7**, 3b/11b: LocalCopy и отдельное «Объединить с сервером» по серверному ID.
  Установщик непустую копию не принимает; native merge сохраняет обе конфликтные версии.
  Чужой desktop.ini сохраняется. Перенесены полезные части a175d75.
- **H09/Q5**, 4a–e: Keep проверяет весь инвентарь и свежую готовность обеих сторон,
  local/global версии и availability сервера для каждого пути, затем повторно сверяет SHA-256
  до и после detach. Уникальные ignored, .git/vendor/.stversions, пользовательские ignore rules,
  конфликтные и поздние данные — отказ со списком. Рецикл/отмена не имеют permanent fallback.
  Если Корзина перенесла лишь часть файлов, регистрация восстанавливается на паузе: удаления
  из оставшегося корня не отправляются серверу. Инвентарь для такого recovery есть и в журнале.
  Это сверка локального индекса и инвентарей; удалённое чтение содержимого по SSH не применяется.
- **H11**, 11a/13a–e: mandatory include первым после BOM; дубликаты удаляются, пользовательские
  строки/CRLF сохраняются. Даже отрицательный GET после ошибки POST не разрешает удалить
  исключения: отложенный writer может ещё применить регистрацию. Правила — единый disk/stignore.txt этапа 1. Миграция existing shared
  registrations, включая ручной Tray: пауза на время изменения ignores, затем исходная пауза;
  staggered 30 дней и maxConflicts=-1. Повторная PowerShell-миграция не пишет config и не
  прерывает обмен лишними pause/resume; она также использует общий mutex операций.
  Ручные настройки самого Syncthing вне программы способны
  изменить policy до очередного события/reconcile; программа не объявляет такой промежуток
  доказанно защищённым первым scan.
- **H13**, 4e/5b/5f/5g: только прямые дети базы, повторная проверка до действий;
  runtime C#, AcceptFile/PowerShell и импорт конфигурации дают одинаковое ограничение.
  Корень тома не является собственным ребёнком; старый внешний путь из каталога заглушек
  не перетирает актуальное предложение внутри базы.
  Единственное исключение запрета на соседние файлы — **ConfigBundle.cs**:
  один вызов DiskChoice.DirectWindowsChild и исправленный комментарий к нему.
  Иначе импорт продолжал бы принимать внешние пути. Предупреждение legacy disk.external
  предлагает перенос внутрь базы, вместо обхода через ручное добавление внешнего пути в Tray.
  Остальные перечисленные владельцем файлы соседней сессии не менялись.
- **H17 (зарегистрированные папки)**, 2a/8a/8b: подтверждённое notSharing → долговечная
  retired-запись до DELETE; данные сохранены, старый pending игнорируется, повторный Upload
  отсоединённой копии не выполняется неявно. Пауза не маскирует подтверждённое снятие.
  Без истории подтверждения notSharing остаётся ожиданием, без выдуманного tombstone.
- **H08**, 14c/14d: атомарный журнал Accept/Keep, Flush(true), фазы и config-before;
  общий mutex для PowerShell/C#. Recovery не повторяет Корзину, проверяет ID/path/peer,
  восстанавливает регистрацию либо заглушку; неизвестный исход Accept сохраняет исходный ID.
  Повреждённый журнал останавливает изменения. Добавлена история завершённых операций C#.

## Что остаётся за пределами этой части

Серверный реестр и Q1–Q10 не менялись. Пустая непринимаемая P не имеет db/completion:
полная свежесть pending-каталога (2b), три клиента одновременно, смена базы/identity/custom-home,
запрет downgrade helper, внутренние Windows имена и видимый статус всех конфликтов относятся
к последующим частям. Keep уже блокирует найденные conflict-файлы.

Linux fixtures доказывают переходы движка/REST/FS, а не реальный Explorer Windows, WinPS 5.1,
межтомную Shell-операцию, штатную Корзину или её переполнение. Для этого остаётся Windows smoke
после отдельной приёмки/разрешения на работу с выбранным компьютером. Новых гарантий обнаружения
секретов по содержимому нет. Уцелевший вне базы desktop.ini сам по себе не является статусом.

Проверка инвентаря использует документированный [db/file REST](https://docs.syncthing.net/rest/db-file-get.html).
Служебный marker принимается только с ожидаемым именем SHA-256(ID) и корректной структурой
из [Syncthing v2.1.7](https://github.com/syncthing/syncthing/blob/v2.1.7/lib/config/folderconfiguration.go);
посторонние файлы в .stfolder не считаются служебными.
