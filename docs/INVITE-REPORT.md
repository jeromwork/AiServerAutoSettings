## Что сделано

- `create` выдаёт один персональный EXE: штатный release PE остаётся побайтно
  неизменным, приглашение и Windows sing-box помещаются в overlay с маркерами,
  точной длиной и SHA-256. Публикация раздаёт тот же EXE, один GET, с удалением
  по сроку. Предупреждение «секретный, как пароль» сохранено.
- Перед регистрацией применяется существующий серверный каталог
  `~worker/.config/remoteagents/transport-catalog.json`, снимки канала и кэшей.
  Параметры и пути исходных секретов берутся из конфига.
- `--vpn on` по умолчанию: сначала проверка пути HTTPS, затем штатный TUN и
  проверка его маршрутов/DNS/HTTPS, затем ra-enroll и собственный ключ.
  После обычной проверки своим ключом начальный режим снимается.
  `--vpn off` не включает VPN. Чужой VPN сохраняет прежнее окно выбора.
  Ошибка нашего VPN не отменяет попытки регистрации по маршрутам приглашения.
- Второй RemoteVPN.exe не требуется: тот же commandManaged-компонент из
  `components-vpn.json` включён в основной бандл. Используются существующие
  Vpn.Tun, watchdog, очистка маршрутов, мастер установки и автозапуск лаунчера.
- После подключения — только дерево папок с предвыбором из приглашения,
  ленивым раскрытием, местными и серверными папками. Выбор и двустороннее
  применение используют прежние DiskTreeSelection / DiskTree / InviteDisk.
- Пропуск удаляется из рабочей копии. Установленный EXE сохраняется без
  нагрузки; скачанный файл удаляется, если возможно, иначе его повторное
  использование блокируется квитанцией/одноразовостью на сервере.
- Обновлены схемы, установка серверного кода, простая инструкция и приёмка:
  [INVITE.md](INVITE.md). Внутренние dotnet-сборки в test_invite.py получили
  timeout 300 секунд вместо 60; отдельные команды проверок ограничены 120 с.

## Проверки и точные ограничения результатов

**Полный `timeout 120 app/launcher/tests/run.sh` запущен ровно один раз.
Итог команды — 124 (общий таймаут), а не успешное завершение всего скрипта.**
Серверная группа успела закончить все 62 теста за 117,401 с без ошибок;
завершились также PowerShell-группа и тесты дерева. Остальные группы и
проверки .NET выполнены отдельно с лимитом 120 секунд. Полный скрипт повторно
не запускался. В runner независимые проверки выполняются двумя группами;
общие .NET-проекты собираются последовательно.

| Из серверных — приглашения | **15 прошли**: одноразовость, гонка (ровно 1 из 2), срок, revoke, ограничения SSH, pinning, собственный ключ, маршруты, публикация, overlay |

Стенды SSH слушали только loopback, имели временные HOME/ключи/конфиги.
Проверен недоступный прямой путь → HTTP-прокси и отдельно → закреплённый
SSH-hop. Каталог применён, VPN-компонент включён заглушкой **до** регистрации.
Режим off не включает компонент; чужой VPN не трогается; ошибка VPN допускает
маршруты. Проверки Windows→Linux подают CRLF, включая сам закрытый ключ пропуска.
