# Серверные компоненты из одного конфига

Серверные настройки отделены от клиентских `disk`, `bridge`, `happier`: за сервер
отвечают `serverComponents`, `agents`, `desktop`, `projectViews`, `sessions`, `ssh`.
Они проходят тот же EXE → PowerShell → root reconcile и входят в экспорт.
[Пример без доступов](../server/server-components.example.json). В первом запуске EXE
`server.login: root` и новый hosting-пароль создают canonical worker; движок сам
передаёт root-reconciler его рабочий login. В прямом server-apply уже указывают
рабочего пользователя. Без учётных данных агентов пример ожидаемо показывает waiting.

| Раздел | Поведение |
|---|---|
| `serverComponents.disk.enabled` | Syncthing 2.1.7 с проверкой SHA256 из существующего установщика, отдельная user-служба, обнаружение папок; `discoveryIntervalSec` 2–60, по умолчанию 2 |
| `serverComponents.bridge.enabled` | Проверяемые файлы MCP, регистрация для установленных Codex/Claude, сохранение каталога компьютеров и пользовательских SSH-ключей |
| `serverComponents.happier.enabled` | Официальный stable installer; `version` закрепляет релиз; служба `remoteagents-happier.service` с общим HOME и авторизацией Claude из EnvironmentFile |
| `agents.codex` | `enabled`, закреплённая `version: "0.166.0"`, `auth` — ссылка на полный `auth.json`. Старый проверяемый установщик требует canonical `remoteagents` и root-owned `managed-user-v1`, созданные bootstrap; чужой пользователь не присваивается |
| `agents.claude` | `enabled`, `channel: "stable"` или точная `version`; `auth` — полный JSON credentials, `token` — OAuth token. Token хранится в пользовательском файле 0600; managed wrapper `claude` и Happier получают его без shell-eval |
| `desktop` | `enabled`, `backend: "desktop"` ставит существующий desktop-bootstrap (его ограничение Ubuntu 24.04 amd64 остаётся). `native` сообщает blocked: установщика нет |
| `projectViews.enabled` | При true честный blocked: исходника установленного на 109 root-скрипта в репозитории нет; его нужно перенести отдельно |
| `sessions` | `cleanupEnabled`, `idleHours` (0–720, default 2), `intervalMinutes` (1–1440, default 15); user timer вызывает существующий `close-idle-chats.py` |
| `ssh` | `keepaliveIntervalSec` (default 30), `keepaliveCountMax` (default 3); проверка эффективных настроек sshd и reload/запуск службы |

Отсутствующий раздел не включает компонент. `enabled:false` отключает управляемые
службы Диска/Happier, не удаляя данные. Мост — stdio MCP, постоянного демона у него
нет. Отключение серверного моста не отзывает доступы компьютеров. Клиентская
регистрация нового компьютера по-прежнему выполняется установщиком компьютера.

CLI без секрета ставится, но часть остаётся `waiting: CLI установлен; нужен вход`.
Codex предлагает `codex login --device-auth`, Claude — `claude auth login`, Happier —
вход в аккаунт. Отсутствующий agent auth не останавливает установку CLI и сохранение
снимка для самопочинки. Наличие файла авторизации означает установку предоставленных
учётных данных; без отдельного запроса к провайдеру действительность подписки/токена
не обещается. MFA и первичный интерактивный вход остаются у владельца.

## Идентичности и самопочинка

`identity` в `serverComponents.{disk,bridge,happier}` и `telegramGateway` — ссылка
на секрет со строкой JSON. Формат — объект **фиксированные относительные пути →
содержимое UTF-8**; произвольные пути, `..`, symlink и архивы отвергаются. IO делает
рабочий пользователь: root не пишет через контролируемые им каталоги.

При первой установке идентичность создаётся обычным установщиком и сохраняется
в root-only снимке. При следующих применениях отсутствие `identity` означает
сохранение уже управляемой идентичности. Для переноса останавливают исходный сервер: два узла с одинаковым Syncthing
device ID, VPN-login или Happier machine identity не должны соперничать.
При переносе явно переданная identity
восстанавливается до запуска компонента и генерации новых сертификатов.

- Диск: `config.xml`, `cert.pem`, `key.pem`, `ports.json` в `.local/share/remote-disk`.
  Поломанный XML/REST и потерянные сертификаты восстанавливаются из последнего
  работоспособного снимка. Device ID сохраняется. Штатные изменения папок и peers
  попадают в следующий снимок после здоровой проверки.
- Telegram: TLS-пара, `state/settings.json`, `state/keys.json`. Валидные добавления
  и отзывы клиентских ключей подхватываются следующей сверкой. При импорте identity
  TLS-пара сохраняется даже при другом адресе VPS: старый SAN остаётся, поэтому для
  прежних клиентов сохраняйте публичное DNS-имя сертификата и перенесите его DNS.
- Мост: пользовательские `.ssh/authorized_keys`, `id_ed25519[.pub]`, записи каталога
  `.local/share/remote-agents-nodes`, MCP-конфиги `.codex/config.toml`, `.claude.json`
  и существующие общие инструкции handoff. Новый ключ подключения, выданный после снимка,
  добавляется к восстановленным ключам. `config revoke` сохраняет явный список
  отзывов `.ssh/remoteagents-revoked.json`; восстановление не возвращает отозванные
  приглашения. Полный экспорт добавляет в переносимую identity и свой новый
  SSH-ключ, поэтому именно этот файл открывает восстановленный сервер. SSH host keys ОС не являются пользовательским
  ключом моста: новый VPS имеет собственный ключ хоста, который закрепляется как
  часть нового подключения.
- Happier: `.happier/settings.json`, `access.key` и соответствующие файлы в
  `.happier/servers/<id>`; daemon-state/PID/logs не переносятся.

Root timer каждые 30 с сверяет подтверждённую сеть, зависимости, пользовательские
конфиги, код, units и авторизацию. Linger обеспечивает запуск user manager после
перезагрузки. Служба/таймер, удалённый managed unit, битый конфиг и пропавшие
пакеты возвращаются из сохранённого конфига. CLI и Syncthing binary ставятся снова,
если отсутствуют. Загрузка пакетов зависит от доступности репозиториев и proxyOut.

Полный переносимый файл выдаётся только явным root-вызовом
`remoteagents config export --include-server-secrets --output …`;
`--master-password-stdin` шифрует секретные строки enc1. Обычный экспорт и копия
«для ИИ» содержат ссылки без значений. Не печатайте полный файл в терминал/чат.

## Сеть и начальные загрузки

Изменение `serverNetwork.inbounds` на управляемом сервере (добавить/заменить/убрать,
включая удаление самой ссылки) запускает пяти­минутную транзакцию. Перед рестартом
проверяется sing-box config, ставится rollback timer, сохраняется старый config и
состояние защиты. Только **новый SSH** и проверка `inboundPorts` подтверждают входы.
При отказе SSH таймер/boot recovery возвращают прежние входы. Reconcile не заменяет
pending и не подтверждает собственный SSH. Чужой sing-box не получает managed receipt.

До TUN начальные apt/curl идут через HTTP/SOCKS5h из `proxyOut`; root bootstrap
получает URL с учётными данными только через in-memory pipe и SSH stdin. Apt/curl
не получают пароль в аргументах и логах. Для HTTP тот же механизм подходит pip;
для SOCKS pip требует PySocks, о чём сообщает план. Начальных pip-загрузок здесь нет:
cryptography устанавливается пакетом ОС. Проверка реального внешнего IP после TUN
по-прежнему отключает HTTP_PROXY и обращается напрямую через системную маршрутизацию.

## Что не является конфигом

Проекты в `~/Disk`, их `.git`, `.env`, зависимости, базы данных, содержимое папок
Syncthing, индексы БД Syncthing, browser profiles и переписки не экспортируются.
Для них нужна отдельная резервная копия и восстановление данных. Сохранённый
config.xml может ссылаться на такие папки; файл конфига не заменяет их содержимое.

Native desktop, project views и личные ручные изменения внешних backend-сервисов
не превращаются в воспроизводимую установку без исходников/параметров. Для миграции
109 сначала явно описывают выбранные компоненты и передают их реальные секреты;
обычный plan со схемным примером не извлекает произвольные секреты ручной установки.
