# Отчёт потока D: окно и оркестратор (задача CONFIG)

Ветка `app/config-d`, worktree `~/work/wt-config-d`. Коммиты: `8041c81` (код), `7786b85` (тесты), этот отчёт.
Сервер, Windows-компьютеры, мост и `~/.ssh` не трогались. PowerShell-файлы (поток C) не менялись.

## Что сделано

1. **Запуск EXE** (`Program.cs`, `ConfigWindow.cs` → `StartWindow`).
   - Человек запустил уже настроенную программу (без аргументов `--…`) → маленькое окно «RemoteAgents настроен» с большой
     кнопкой «Включить» и ссылкой «Не сейчас». После «Включить» трей показывает уведомление «RemoteAgents работает, значок в трее».
   - Если программа уже работает, повторный запуск передаёт в трей `--setup-check --started`, и трей показывает то же уведомление.
   - Автозапуск (`--tray --home`, ключ Run) работает как раньше, без окна. Флаг `--started` передаётся через `StartLauncher`
     и при запуске скачанного EXE.
   - Программа не настроена → окно «Вставьте конфиг» поверх всех окон (`TopMost`). Существующий мастер открывается ссылкой
     «Пройти по шагам», подготовка бандла у обоих окон одна.
2. **Окно `ConfigWindow`** (ширина 520 пикселей, высота подстраивается под видимые части).
   - Источники конфига: поле для текста или ссылки `https://` (только https, в том числе после перенаправлений; лимит 1 МБ;
     принимается только JSON), перетаскивание файла на окно или поле, «Открыть файл…», единственный `*.json` с
     `"remoteagents-config"` рядом с EXE.
   - Поле «Название компьютера»: по умолчанию «Компьютер <пользователь>». Если человек его не менял, берётся `device.name` из
     конфига. Название уходит в `Bridge` как `deviceName`.
   - **«Собрать конфиг с ИИ»** (дополнение координатора). Кнопка копирует запрос из встроенного ресурса
     `app/launcher/config-ai-prompt.md` (`EmbeddedResource`, имя `RemoteAgents.ConfigAiPrompt.md`) и показывает подсказку
     «Вставьте в чат ИИ (ChatGPT, Claude, Gemini)…». Файл-заготовка содержит ссылку на `docs/CONFIG.md` на GitHub и требования:
     выдать только JSON, секреты оформить ссылками `{"secret","hint"}` с пустыми значениями в `secrets`, не просить пароли в чате
     и предупреждать, если человек их туда пишет. Окончательный текст доработает координатор.
   - После «Запустить»: разбор (`ConfigBundle.Parse`) → мастер-пароль (спрашивается один раз; при неверном пароле — повтор)
     → конфликты → `Store` → план → пустые секреты через `SecretPrompt.Ask` с объяснением и `hint`, до начала выполнения
     → выполнение.
   - Для каждого раздела из конфига своя строка: значок (•/⏳/✅/❌), полоска во время работы, текущее действие из
     `ProgressFile`, причина ошибки (полный текст — во всплывающей подсказке) и «Повторить». Если раздел «Сервер» повторяют
     успешно, запускаются и разделы, которые его ждали. Ниже сразу виден журнал с временем каждого раздела.
   - Затем дерево папок: общее ленивое дерево (`DiskFolderTree`, вынесено из `SetupWizard`). Отметки берутся из
     `profile.disk.folders`, выбор записывается обратно в профиль. При «Готово», если выбор изменился, запускается действие
     `Disk`, затем `Activate`, после чего программа уходит в трей с уведомлением.
   - Конфликты: окно со списком «сейчас / в конфиге», у каждого пункта выбор «Взять из конфига» / «Оставить как есть»
     (по умолчанию «Оставить»). Кнопка «Скопировать для ИИ» кладёт в буфер ссылку на `docs/CONFIG.md`, текущий конфиг,
     вставленный конфиг (оба без секретов), список расхождений и просьбу вернуть исправленный конфиг. Остальные разделы
     применяются как обычно.
3. **Оркестратор** (`ConfigApply.cs`).
   - Чистая логика (входит в тесты): `ConfigSections` (разделы, срезы профиля, канонический хеш, `Accept` для конфликтов),
     `ConfigPlan.Build/Ready` (план по разнице), `ConfigEngine.Execute`, `ConfigRequests` (запросы существующих действий из
     профиля), `ConfigProfile` (`config.json` → `profile`, хеши применённых разделов в `state/config-applied.json`, обратная
     синхронизация после «Подробно»), `ConfigAi`, `ConfigSource`, `ConfigText`.
   - Раздел попадает в план, если он описан и при этом изменился с последнего успешного применения или живая проверка
     `Inspect` не подтверждает его готовность. Если план включает сервер, в него попадают и все описанные разделы, которые
     от него зависят. Повторное применение того же конфига даёт пустой план («Ничего не изменилось»).
   - Порядок (соглашение, раздел 4): `Bootstrap` → `Server` → одновременно `Connection`, `Bridge`, `Account`, `Disk`, `Vpn`
     и параллельно им цепочка `Proxy` → `Lan`.
     - Неудачный `Bootstrap` не останавливает `Server`.
     - Если `Server` не прошёл, остальные разделы получают ❌ «ждёт доступа к серверу» и не запускаются.
     - Отсоединённые установки на сервере показываются ⏳; окно следит за ними (`FollowPending`) и после завершения выполняет
       `ResumeAccount` или повторяет раздел.
   - `WizardRunner.Run` — общий раннер `build/Wizard.ps1` с чтением `ProgressFile`. Через него теперь работают
     `SetupWizard.Run`, `ServerOperations.Invoke` и движок, дублирования нет.
   - Пароли root и hop передаются только через `PasswordRelay`. Для нового аккаунта Happier ключ кладётся в хранилище
     секретов, а профиль переключается на `mode: same` с ссылкой на этот ключ, поэтому повторное применение не создаёт второй
     аккаунт.
4. **Настройки из трея**: «Настройки…» и пункт «Нет связи — вставить новый конфиг…» открывают `ConfigWindow.Settings`.
   - Поле «Название компьютера» и кнопка «Сменить»: название сразу уходит в `Bridge` с `deviceName`.
   - Вкладка «Конфиг»: текст из `ExportForAi`, отформатированный; кнопки «Скопировать», «Применить» (применяются только
     изменившиеся разделы, тем же движком), «Сохранить конфиг в файл…» (с мастер-паролем, введённым дважды, или без пароля)
     и «Подробно…» (прежние разделы мастера; после закрытия профиль подтягивается из того, что они настроили).
   - Вкладка «Папки»: то же дерево и «Применить выбор».
   - Переключатель VPN в трее меняет `profile.vpn.enabled`. Раз в 5 минут вызывается действие `Sync` — замена бывшего
     `InviteSync`.
5. **Приглашения удалены**: `Invitation.cs`, `InvitationOverlay.cs`, `InviteWindow.cs`, `RefreshPackage.cs`,
   `tests/InvitationTests.cs`, `tests/OverlayTests.cs`, строки в `PortableTests.csproj`, ветки в `Program.cs`, `TrayContext.cs`,
   `SetupWizard.cs`, `EntryPoint.cs` (`--selftest-invite-overlay`) и `UpgradeInstaller.cs` (`CopyBase` заменён на `File.Copy`).
   - `InviteHop` переименован в `HopRelay` (`--hop-relay`, формат файла прежний): транспорт по-прежнему нуждается в нём для
     паролей hop по маршрутам.
   - Проверка: `grep -i "invitation|InviteWindow|InviteHop|RefreshPackage|rainvite|invite-hop|invite"` по
     `app/launcher/*.cs`, `tests/*.cs`, `*.csproj`, `tests/*.py` находит совпадения только в `test_first_run.py`, где они
     стоят как запрещённые слова.
6. **Заглушки** потока A: `app/launcher/ConfigStubs.cs` с сигнатурами из раздела 3. Код в нём закрыт `#if !PORTABLE_TEST`,
   тесты от него не зависят. Координатор удаляет файл при слиянии.

## Что нужно от других потоков при слиянии

**A (формат и секреты)**

- `Store(home, p, acceptSections)`: D передаёт ключи верхнего уровня профиля (`device`, `server`, `vpn`, `happier`, `bridge`,
  `disk`, `proxyOut`, `lan`, `components`). Если ключа нет в списке, этот раздел профиля остаётся прежним.
  Профиль хранится в `config.json` → `profile`. D сам дописывает туда `device.name`, `disk.folders` и `happier.mode/key`
  (через `Configuration.Edit`), а `Export` должен отдавать их.
- `Conflicts`: строки вида `<ключ профиля>: сейчас X / в конфиге Y`, где ключ — `server`, `happier` или `disk`. Русские
  заголовки («Сервер…», «Аккаунт Happier…», «Диск…» или «Папки…») D тоже распознаёт (`ConfigSections.ProfileKeyOfConflict`).
- `Parse`: значение `"<есть, скрыт>"` в `secrets` должно означать «оставить сохранённое» и не попадать в `Missing`, потому что
  вкладка «Конфиг» показывает текст из `ExportForAi`.
- `Materialize`: секреты-файлы (`server-key`, `hop-key`, `lan-<имя>-ovpn`) класть в `secrets/config/<имя>`
  (`ConfigRequests.SecretFile`) или поменять эту одну функцию.
  Отдельный `SecretVault.Get` D не нужен: значения паролей D берёт из `ParsedConfig.Secrets` или `SecretPrompt`.
- Разрешить в схеме необязательные `proxyOut.ipCheckUrl` и `lan[].host`, `lan[].port`, `lan[].login`.
- Удалить `ConfigStubs.cs`.

## Известные ограничения

- Хеш раздела не учитывает значения секретов: сменился только пароль — нажмите «Повторить».
- Раздел `lan` описывает полный список сетей: сети, которых нет в конфиге, удаляются (`LanRemove`).
- Если у ключа нет прав root, а пароля root в конфиге нет, `Proxy` и `Lan` пишут в журнал команду для администратора; окно
  посреди выполнения ничего не спрашивает.
- Слежение за установкой на сервере (`FollowPending`) может пересечься с ручным «Повторить» того же раздела.
