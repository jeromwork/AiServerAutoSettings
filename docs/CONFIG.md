# Конфигурация RemoteAgents, версия 1

Этот документ предназначен владельцу и ИИ-агенту, который готовит настройки. Машиночитаемая схема —
[`config.paste.schema.json`](../app/launcher/config.paste.schema.json), пример без доступов —
[`config.paste.example.json`](../app/launcher/config.paste.example.json). Контракт взаимодействия потоков —
[`CONFIG-CONTRACT.md`](CONFIG-CONTRACT.md).

**Агент не читает `secrets/`, ключи, значения переменных окружения и содержимое Bitwarden. Не просит человека
писать пароль в чат.** Для ввода вызывает `secret set` с понятным объяснением, для переноса — `secret import`.
Статус узнаёт через `secret status`. Для обсуждения использует только экспорт «для ИИ». Не вставляет секреты
в `hint`, название компьютера, адреса, имена секретов, аргументы команд, журналы или сообщения об ошибках.

Доступ передаётся полным конфигом. Получатель файла без мастер-пароля получает доступ сразу; закрытый конфиг
передают отдельно от мастер-пароля. Мастер-пароль не сохраняется. Здесь нет одноразовых приглашений.

## Общие правила

Конфиг — строгий JSON-объект UTF-8, не более 4 МиБ, с `"kind":"remoteagents-config"`, `"schema":1`.
BOM и переводы строк CRLF допустимы. Комментарии, повторные ключи, неизвестные поля, неверные типы и версии
отклоняются. `hint` — необязательная публичная строка-подсказка в структурных объектах; она не выполняется как код.
В словарях `entries`, `hops`, `secrets` ключи имеют специальный смысл, произвольных полей-подсказок там нет.

Отсутствующий раздел оставляет предыдущие настройки. При первом сохранении существующей установки подхватываются известные настройки сервера, моста, Happier, компонентов,
серверного прокси, а также публичные `RemoteDisk/base.txt` и `selection.json` соседней стандартной установки.
Существующие SSH/Happier/proxy-ключи переносит сама программа в vault, агент их не читает.

При сохранении заданные свойства объектов объединяются
с предыдущими, массивы заменяются целиком. Ссылка `{"secret":"имя","hint":"откуда человек берёт секрет"}`
заменяется целиком; значение хранится в `secrets`, не внутри `server`/`happier`/`proxyOut`/маршрутов.
Пустое значение или отсутствие значения означает запрос человеку; уже имеющееся значение vault сохраняется
при вставке публичного конфига. Для явной очистки используют `secret set` с пустым вводом.

Имя секрета: до 64 знаков; первый — строчная латинская буква, цифра или буква Unicode, остальные также могут
содержать `.`, `_`, `-`. Заглавная ASCII-латиница запрещена; кириллица, включая «Офис», допустима. Имена
`protected`, `kdf`, `check`, `hint` зарезервированы. Не помещайте пароль в имя секрета.

Схема в EXE скомпилирована из того же декларативного описания, что опубликованный JSON Schema; тест сравнивает
их. Дополнительные смысловые проверки: имена секретов, соответствие `kind` маршрута, безопасные пути Disk,
метаданные шифрования и формат конвертов. Это позволяет проверять до распаковки бандла без внешнего валидатора.

## Поля

| Поле | Назначение |
|---|---|
| `kind` | Всегда `remoteagents-config`. |
| `schema` | Целое `1`. Поле `version` из старого `config.json` не является полем переносимого конфига. |
| `hint` | Публичное пояснение до 2048 знаков. |
| `device.name` | Человеческое имя компьютера, 1–80 знаков без перевода строки; движок передаёт его мосту как `deviceName`. |
| `server.address` | IP или DNS-имя SSH-сервера, без логина, URL, команд и пробелов. |
| `server.port` | SSH-порт 1–65535; при отсутствии применяется 22. |
| `server.login` | Пользователь SSH: до 32 строчных латинских букв, цифр, `_`, `-`; начало — буква или `_`. |
| `server.hostKeys` | До 32 открытых ключей хоста в формате `ssh-ed25519 AAAA…` / другого поддержанного OpenSSH типа, без адреса и переносов строк. Необязательно; проверку доверия выполняет SSH-движок. |
| `server.key` | Ссылка на текст закрытого SSH-ключа. Не путь к файлу. |
| `server.rootPassword` | Ссылка на пароль первоначального входа/администратора; подсказка по умолчанию — пароль из письма хостинга. После успешной установки рабочего ключа восстановительный экспорт должен использовать этот ключ. |
| `server.routes` | До 32 вариантов маршрута; порядок сохраняется, пробует движок. |
| `server.routes[].kind` | `direct`, `proxy` или `hop`. У `proxy` обязателен объект `proxy`, у `hop` — `hop`; чужие для выбранного вида объекты запрещены. |
| `server.routes[].proxy.type` | `socks` или `http`. |
| `server.routes[].proxy.server`, `.port` | Адрес/порт локального или доступного SSH-прокси. |
| `server.routes[].proxy.login`, `.password` | Публичный логин и ссылка на пароль прокси; поддержку аутентификации маршрута обеспечивает транспорт. |
| `server.routes[].proxy.checkUrl` | Необязательный собственный HTTPS URL проверки, без userinfo. |
| `server.routes[].hop.host`, `.port`, `.user` | Адрес, порт (по умолчанию 22), пользователь SSH промежуточного сервера. `host` и `user` обязательны. |
| `server.routes[].hop.hostKey` | Необязательный открытый ключ хоста промежуточного сервера. Проверку доверия выполняет движок. |
| `server.routes[].hop.key`, `.password` | Ссылки на закрытый ключ и/или пароль промежуточного сервера. |
| `connection.enabled` | Желаемое включение связи. Проверенную готовность сообщает движок. |
| `bridge.enabled` | Включить управление компьютером. |
| `bridge.allowShell` | Разрешить shell через мост; не включать без решения владельца. |
| `happier.mode` | `same` — существующий аккаунт, `new` — новый аккаунт. |
| `happier.label` | Подпись аккаунта, 1–80 знаков. |
| `happier.serverUrl`, `.webappUrl` | Собственные адреса API и веб-интерфейса, только HTTPS без логина/пароля в URL. |
| `happier.key` | Ссылка на секретный ключ аккаунта. Для нового аккаунта ключ создаёт слой применения; не придумывать его. |
| `disk.base` | Корень Disk на принимающем компьютере; на другом компьютере пользователь может выбрать другой. |
| `disk.folders` | До 256 относительных путей выбора: `Проект` или `Проект/docs`. Первый сегмент — проект непосредственно в Disk; последующие — выбор содержимого этого проекта, не новая вложенная папка проектов. `/` — разделитель; абсолютные пути, `..`, пустые сегменты, `\`, запрещённые Windows-имена исключены. Защищённые файлы и каталоги дополнительно исключает RemoteDisk. `[]` означает убрать весь выбор и требует решения при конфликте. |
| `vpn.enabled` | Желаемое включение VPN. |
| `vpn.checkUrl` | Собственный HTTPS URL проверки внешнего адреса. |
| `vpn.dnsServer` | Адрес DNS, передаваемый VPN-движку. |
| `vpn.bootstrap.channel` | Ссылка на секрет, содержащий целиком JSON канала (объект sing-box с данными доступа). |
| `vpn.bootstrap.entries` | Словарь `имя-узла → ссылка на секрет`, содержащий JSON `client.json` узла целиком. Имя узла совместимо с транспортом: 1–48 латинских букв/цифр/`_`/`-`, начало — буква/цифра; зарезервированные Windows-имена запрещены при материализации. Unicode допустим в имени самого секрета, например `vpn-entry-Узел`. |
| `vpn.bootstrap.hops` | Словарь имён SSH-переходов с полями `host`, `port`, `user`, `hostKey`, `key`, `password`, как у серверного hop. Имена узлов — как у `entries`. |
| `proxyOut.type`, `.server`, `.port` | Тип (`socks`/`http`), адрес, порт серверного выхода в интернет; обязательны, если раздел задан. |
| `proxyOut.login`, `.password` | Публичный логин и ссылка на пароль серверного прокси. |
| `proxyOut.checkUrl` | Собственный HTTPS URL проверки выхода; подтверждение/откат остаются в сетевом движке. |
| `lan` | До 64 определений локальных сетей. |
| `lan[].name`, `.kind` | Имя сети и `openvpn`. Публичное имя может быть Unicode; системное имя 1–7 строчных латинских знаков согласует движок с `Get-WizardLanName`. |
| `lan[].ovpn` | Ссылка на текст `.ovpn` с включёнными сертификатами/ключами. Ссылки на соседние файлы не переносимы; они должны быть встроены в профиль. |
| `lan[].login`, `.password` | Публичный логин и ссылка на пароль сети. |
| `lan[].host`, `.port`, `.checkUrl` | Узел и порт живой проверки LAN, собственный HTTPS URL проверки выхода; сетевой движок уточняет допустимость адреса. |
| `components.transport.enabled` | Включение компонента связи. |
| `components.disk.enabled` | Включение компонента RemoteDisk. |
| `components.control.enabled` | Включение компонента моста. |
| `components.vpn.enabled` | Включение компонента VPN. |
| `secrets.<имя>` | Текст секрета, `enc1:…` при мастер-пароле, либо `""`. Пустые и неиспользуемые именованные записи сохраняются при полном экспорте. |
| `secrets.protected` | Только `master-password`; отсутствие означает открытые значения. |
| `secrets.kdf.name` | Только `pbkdf2-sha256`; используется вместе с `protected`. |
| `secrets.kdf.iterations` | 200000–2000000. Экспорт создаёт 200000 итераций. Верхний предел ограничивает затрату времени на недоверенный ввод. |
| `secrets.kdf.salt` | Base64 случайной соли 16–64 байта; экспорт создаёт 32 байта. |
| `secrets.check` | Зашифрованная строка `remoteagents` для проверки мастер-пароля. |

В `config.json` программы уже есть служебные `schema`, `version`, `transport`, `wizard` и т. п. Их нельзя вставлять
как переносимый конфиг. Переносимое желаемое состояние хранится там в `profile`, без раздела `secrets`.

## Стандартные имена секретов

| Имя | Что вводит человек / импортирует программа |
|---|---|
| `server-key` | Закрытый SSH-ключ доступа этого конфига. |
| `server-root-password` | Первоначальный пароль root из письма хостинга. |
| `hop-key` | Закрытый ключ SSH промежуточного сервера. Для нескольких hop допустимы собственные имена. |
| `hop-password` | Пароль SSH промежуточного сервера. |
| `happier-key` | Ключ аккаунта Happier из его настроек. |
| `proxy-out-password` | Пароль серверного прокси. |
| `route-proxy-password` | Пароль прокси маршрута к SSH; имя — соглашение, ссылка может использовать другое имя. |
| `vpn-channel` | JSON канала связи целиком. |
| `vpn-entry-<имя>` | JSON `client.json` VPN-узла целиком. |
| `lan-<имя>-ovpn` | Текст OpenVPN-профиля с встроенными ключами/сертификатами. |
| `lan-<имя>-password` | Пароль локальной сети. |

Пример безопасной заготовки агента:

```json
{
  "kind": "remoteagents-config",
  "schema": 1,
  "device": { "name": "Ноутбук" },
  "server": {
    "address": "server.example.invalid",
    "port": 22,
    "login": "root",
    "rootPassword": { "secret": "server-root-password", "hint": "Пароль из письма хостинга" }
  },
  "bridge": { "enabled": true, "allowShell": false },
  "secrets": { "server-root-password": "" }
}
```

## Ввод без раскрытия агенту

```text
RemoteAgents.exe secret set server-root-password --why "Пароль root из письма хостинга"
RemoteAgents.exe secret status
RemoteAgents.exe secret import server-key --from env:RA_SERVER_KEY
RemoteAgents.exe secret import server-key --from bitwarden:идентификатор-объекта/ssh-key
RemoteAgents.exe secret import proxy-out-password --from bitwarden:идентификатор-объекта/password
```

`set` показывает отдельное WinForms-окно со скрытым вводом; многострочный ключ можно вставить или выбрать из файла.
Отмена не меняет значение. В терминальном Linux-варианте ввод скрыт, redirected stdin не принимается. Пустой ввод
сохраняется как «нет». Вывод агенту — только «сохранено»/«отменено» либо общая причина отказа, без значения.
Коды: 0 — успех, 1 — отмена/ошибка источника/хранилища, 2 — неверные аргументы. `status` показывает объединение
имён vault и ссылок в конфиге: `есть`/`нет`, с отметкой `ссылка в конфиге`.

У `import` имя назначения обязательно. Переменную читает сама программа, агент не выполняет `echo`, `printenv`
или аналогичные команды. Bitwarden CLI `bw` (нативный `bw.exe` на Windows) должен быть установлен и уже разблокирован владельцем; программа
запускает `bw get item`, не печатает его stdout/stderr и не выполняет вход/разблокировку за человека. Поддержаны
`password`, `username`, `totp` (содержимое поля seed, не вычисленный код), `notes` и точное имя пользовательского
поля; повторные пользовательские поля с одним именем отклоняются. Таймаут процесса 15 с, размер ответа 4 МиБ.

Подключение команды к CLI EXE и такое же серверное поведение выполняют потоки D и B соответственно.

## Мастер-пароль и экспорт

`enc1:` — Base64 от `IV[16] || AES-256-CBC(PKCS7, UTF-8(value)) || HMAC-SHA256[32]`.
HMAC покрывает `IV || ciphertext`. PBKDF2-HMAC-SHA256 от мастер-пароля и соли создаёт 64 байта: первые 32 для AES,
следующие 32 для HMAC. Каждый секрет и `check` получают независимый случайный IV. Сначала проверяется HMAC,
затем расшифровывается CBC. Пустые значения остаются пустыми. Другие значения при `protected` обязаны быть `enc1`.
`kdf`/`check` без `protected`, смешение открытых и защищённых значений, повреждение и неверный пароль отклоняются.
Только `secrets.protected` определяет режим: без него даже буквальное значение с префиксом `enc1:` считается открытым текстом. Это проверка содержимого, не сетевой проверенный статус.

`Parse` не пишет на диск. `Unlock` проверяет `check` и **все** непустые секреты, возвращает новый объект;
при ошибке — `InvalidDataException("Неверный мастер-пароль")`, без частичного применения. `Locked`-объект нельзя сохранить.

`Export(home, null)` собирает полный открытый конфиг; с непустым мастер-паролем — защищённый. Включаются значения
vault и пустые записи отсутствующих ссылок. `ExportForAi` заменяет каждое значение секрета на `"<есть, скрыт>"`
или `""`, убирает метаданные мастер-пароля и маскирует известные значения также в публичных строках-подсказках.
Это единственный экспорт, пригодный для чата/буфера агента. При его обратной вставке маркер означает пустое
значение и не перезаписывает уже имеющийся секрет.

## Хранилище и материализация

`secrets/vault.json`: `schema:1`, `protection`, `values` (`имя → строка`), до 256 имён и 4 МиБ файла. На Windows `protection:dpapi-current-user`,
каждое значение защищено Windows DPAPI текущего пользователя, без UI и без machine scope. Файлы/каталоги получают
DACL только текущего пользователя. На Linux `protection:plaintext-linux`: значения открыты, каталоги 0700, файлы 0600.
Файл одного режима не принимается в другом режиме. Перенос выполняют полным экспортом, не копированием vault.

**Агент под тем же пользователем технически способен прочитать Linux-файл и расшифровать DPAPI на Windows.**
Это защита от случайной утечки в чат/логи/контекст и от других пользователей, а не изоляция от кода того же пользователя.
Поэтому правило «не читать секреты и не просить пароль в чат» обязательно даже при DPAPI.

`Store` сохраняет `profile` и vault под тем же коротким mutex, который используют launcher и PowerShell. Отсутствующий
раздел сохраняется; конфликтующие `server`/`happier`/`disk` пропускаются, пока их имена не переданы в `acceptSections`.
Секреты пропущенного раздела тоже не заменяются. `Conflicts` возвращает строки с префиксом раздела и «сейчас / в конфиге»;
не выполняет живых проверок и не объявляет раздел готовым. Проверки выполняет движок.

После сохранения и заполнения недостающих ссылок вызывают `SecretVault.Materialize(home)` отдельно. Метод сначала
проверяет весь план и наличие всех ссылок, затем атомарно заменяет каждый файл. Секретные файлы создаются с закрытыми
правами **до** записи текста. Симлинки/Windows reparse points, выход за `home`, коллизии выходных файлов запрещены.
Переводы строк ключей и `.ovpn` приводятся к LF здесь; значения vault и парольные строки сохраняются без изменений.

| Ссылка в profile | Выход относительно `home` | Потребитель / адаптация |
|---|---|---|

| `server.rootPassword` | `secrets/server-root-password` | D читает внутри приложения и передаёт через `PasswordRelay`, не argv/журнал. |
| `happier.key` | `secrets/happier-pending.key` | `Wizard.Common.ps1:Invoke-WizardAccount`; действующий `happier-account.key` заменяет сам шаг с проверкой/откатом. |
| `proxyOut.password` + публичный `login` | `secrets/proxy-out.json`, объект `username`, `password` | `Wizard.Network.ps1:Get-WizardProxySecret`. |

| `server.routes[i].proxy.password` + `login` | `secrets/route-<i>-proxy.json`, поля `username`, `password` | Путь `routes[i].proxy.credentialsFile`; C/D должны передать в поддерживающий auth транспорт. |
| `vpn.bootstrap.channel` | `secrets/channel.json` | `transport.channelPath`, `Transport.Common.ps1:Read-TransportSettings`; привязку пути делает C/D. |
| `vpn.bootstrap.entries.<узел>` | `secrets/entries/<узел>.json` | `Transport.Common.ps1`, `Update-Entries.ps1`; JSON `client.json` целиком. |
| `vpn.bootstrap.hops.<имя>` | `secrets/vpn-hop-<hash>`, `.known_hosts`, `-auth.json` | Та же структура, что серверный hop, карта `hops.<имя>`; hash — первые 24 hex SHA256(UTF-8 имени). |
| `lan[i].ovpn` | `secrets/lan/<hash>.ovpn` | `Wizard.Lan.ps1:Get-WizardLanPayload`, `Wizard.Network.ps1:Add-WizardLan`; карта `lan[i].file`. |
| `lan[i].password` + `login` | `secrets/lan/<hash>-auth.json`, поля `username`, `password` | D/C передают JSON через `secretPipe`, не включают значение в RequestFile/argv. |
| Все выходы | `secrets/materialized.json` | Закрытый манифест **без значений**: `schema`, `files`, `serverKeyFile`, `serverPasswordFile`, `happierKeyFile`, `proxyOutFile`, `channelPath`, `entries`, `routes`, `hops`, `lan`. Это карта для C/D, не входной переносимый конфиг. |

При изменении действующего SSH-ключа прежний файл сохраняется, новый путь берётся из `serverKeyFile` манифеста;
движок проверяет вход и только потом переключает публичный SSH-профиль. Служебный `.json`/скрипт/EXE не может быть целью ключа.

Материализация не меняет работающий transport/config, не запускает сеть и не удаляет прежние файлы: они могут
нуждаться для отката действующего подключения. Движок использует текущий манифест и текущие ссылки, не подбирает
случайно оставшиеся ключи/пароли. Сначала решает конфликты, затем сохраняет/материализует только принятые разделы.
После успешного bootstrap слой применения обновляет `profile.server.login`/`key`, убирает `rootPassword` и сохраняет
созданный рабочий ключ в vault и очищает прежнее значение root-пароля (`SecretVault.Set(home, имя, "")`). Это нужно сделать до восстановительного экспорта; A не угадывает успех по наличию файла.
