# План: аналог Яндекс Диска без сборки

Автор плана: Claude. Исполнитель: Codex `gpt-6.1-sol`, high. Приёмка: Claude проверяет код и результаты сам, затем владелец на Windows. `.exe` только после того, как всё работает.

## Схема

```text
Папка Windows ⇄ Syncthing (127.0.0.1) ⇄ один SSH-туннель ⇄ Syncthing (127.0.0.1) ⇄ ~/Disk/<имя>
```

Старый установщик, снимки, проверка свежести, мост и привязки проектов здесь не используются и не меняются.

## Шаги

| № | Что | Готово, когда |
|---|---|---|
| 1 | Журнал и его отправка на сервер | Первая строка видна на сервере до запуска всего остального |
| 2 | Серверный Syncthing без root | Запуск в изолированном HOME работает, старые Syncthing не затронуты |
| 3 | Syncthing на Windows, SSH из существующего профиля | Подключение и знакомство устройств автоматические |
| 4 | Двусторонние папки, версии, исключения | Обмен с этими настройками проходит на двух настоящих Syncthing |
| 5 | Трей | Значок и меню соответствуют реальному состоянию |
| 6 | Контекстное меню, именованный канал | Папка подключается правым кликом |
| 7 | Проверка владельцем на тестовой папке | Критерии 8–12 из `SPEC-SYNC.md` |
| 8 | Перевод настоящих проектов | По одному, по команде владельца |
| 9 | Упаковка в `.exe` | Только после шагов 7 и 8 |

## Приёмка Claude перед передачей владельцу

1. Прочитать код: никаких адресов и имён в коде, секреты не пишутся в журнал, старые подключения не затронуты.
2. Самостоятельно перезапустить проверки Linux.
3. Проверить коммит сканером секретов.
4. Описать владельцу, что проверено реально и что проверяется только на Windows.

## Ограничения

Без `sudo`, `systemd`, изменений сети, `sing-box`, других проектов и старых подключений. Push делает только Claude после приёмки.
