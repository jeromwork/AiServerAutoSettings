# Диск в Проводнике

Дата: 13.11.2026. Ветка: `app/explorer-disk`, исходная точка `0637c03` (`app/folders-status`).

## Реализация

Использованы только HKCU, `desktop.ini`, штатные значки Windows, System.Drawing и `SHChangeNotify`. COM-расширений, overlay-обработчиков, cfapi и MSIX нет. Передачу файлов выполняет прежний Syncthing; выбор применяется прежним `ConfigSession.ApplyDisk` → Wizard → `Select-Disk.ps1`.

В существующей схеме **каталог проектов** задаётся `profile.disk.base` / `RemoteDisk/base.txt`, по умолчанию `%USERPROFILE%\Disk`. Поле `config.disk.home` задаёт **служебный каталог Syncthing**, по умолчанию `%LOCALAPPDATA%\RemoteDisk`. Существующие значения не переименованы и не смешиваются: оформление получает каталог проектов, REST и receipts — настроенный служебный каталог.

### Состояния и обновление

- `DiskExplorerPresentation.cs`: чистая проекция снимка `DiskSyncStatus` в значок, InfoTip и действия. Облако — блёклая штатная папка и серое облако; передача — стрелки; завершение — зелёная галочка; ошибка/пауза/offline/ожидание — жёлтый знак с правдивой причиной. Локальная папка имеет штатный значок без отметки.
- `DiskExplorerController.cs`: фоновый цикл 2500 мс без перекрытия, включая закрытое главное окно. `DiskSyncMonitor.cs` разделяет краткоживущий REST-снимок с вкладкой папок; запрос подмножества путей использует тот же снимок. Окно хода читает снимок контроллера, своего REST-опроса не имеет.
- Наличие реально настроенной папки проверяется по пути и выбранному серверу. Неудачное снятие выбора не превращает продолжающую синхронизироваться папку в «локальную»: `DiskExplorerObservation.cs` сохраняет фактическую привязку, при недоступности REST — последнюю подтверждённую привязку с ошибкой состояния.
- Инвентаризация сервера идёт прежним `DiskTree` не чаще раза в минуту. Новое подтверждённое имя получает пустую заглушку при следующем цикле. Неудачная сверка не выдумывает серверное наличие; неполный ответ не удаляет ранее известные факты.
- Собственный `desktop.ini` содержит `[RemoteAgents]`, `Owner=RemoteAgents.Disk.v1`, `Placeholder`, исходный ReadOnly и отметку создания каталога. UTF-16LE с BOM, Hidden+System; папка получает ReadOnly. Одинаковые текст и атрибуты повторно не записываются. После изменения обновляется конкретная папка через `SHChangeNotify`.
- `DiskExplorerNative.cs` создаёт ICO с размерами 16/32/48/256 в `%LOCALAPPDATA%\RemoteAgents\icons`. У состояний разные имена файлов. Чужой `desktop.ini` полностью сохраняется, оформление пропускается с записью в журнал.
- Заглушка с пользовательским файлом становится локальной копией. Пустой маркер не считается локальными данными для inventory/union. Подпапки и их `desktop.ini` оформление не изменяет.

### Меню и действия

`DiskExplorerRegistry.cs` регистрирует пять owner-marked команд в `HKCU\Software\Classes\Directory\shell\RemoteAgents.Disk.*`. `AppliesTo` ограничивает операции точными путями проектов, добавление — путями вне корня. Повторная сверка не переписывает неизменные значения. Команды дополнительно проверяют путь и состояние.

`Program.cs` использует прежний single-instance named pipe и передаёт `--home`, `--disk-shell`, действие и путь. Команда не запускает установку и не открывает окно настроек. `DiskShellBatchQueue` собирает поэлементные вызовы 550 мс, максимум 2 с от первого элемента, удаляет дубликаты и применяет общий выбор один раз. `SerialRunner.TryStart` не вытесняет уже ожидающую операцию настроек.

- «Скачать на компьютер» / «Синхронизировать»: изменяют `DiskChoice`, применяют его существующим движком, открывают окно хода.
- «Добавить в Диск»: создаёт существующий `DiskExternalChoice` с именем исходной папки. `Sync-DiskExternal` проверяет занятость имени до изменения конфигурации и создаёт junction после подтверждения настройки. Receipt хранит целевой путь; снятие выбора размыкает только своё неизменённое соединение, исходные файлы сохраняются.
- Внешний источник оформляется отдельно по явно зарегистрированному физическому пути, без обхода junction, родителя и соседних каталогов. Поэтому видимый в Диске junction получает то же оформление источника. Чужой значок и reparse ancestors источника защищены.
- «Оставить только на сервере»: сначала проверяется возможность безопасной очистки, затем снимается выбор и применяется прежним путём. Только после успешного применения, повторной проверки и подтверждения фактического отсутствия пути в `config/folders` содержимое отправляется в Корзину штатным `Microsoft.VisualBasic.FileIO.FileSystem`. После этого остаётся помеченная заглушка.
- «Ход синхронизации…» и одноимённый пункт трея открывают небольшое окно: проект, полоса/процент, оставшиеся файлы/объём, общие приём/отдача по разнице `inBytesTotal`/`outBytesTotal`, «Открыть папку», «Подробнее…».
- Пункт трея «Папки» открывает каталог Диска в Проводнике. Существующая вкладка «Папки» сохранена.

### Условия отправки в Корзину

`DiskEvictionSafety.cs` и `DiskEvictionProof` требуют:

1. Подключённый правильный сервер, завершённое локальное состояние без ошибок, need и receive-only изменений; принудительный штатный scan перед проверкой.
2. Completion сервера ровно 100%, нулевые `needBytes`, `needItems`, `needDeletes`, `remoteState=valid`.
3. Для каждого пользовательского файла — совпадающие local/global версии, размер и `blocksHash`, наличие файла именно у сервера, отсутствие ignored/invalid/deleted/mustRescan. Физическое содержимое сверяется с `blocksHash`; совпадения размера/mtime недостаточно.
4. Полный SHA256-инвентарь без reparse-переходов до и после применения. Новые/изменённые файлы блокируют очистку.
5. Перед Корзиной — прежний peer, фактически отключённый путь и неизменная папка. Отмена Корзины не заменяется безвозвратным удалением.

При отсутствии любого подтверждения файлы остаются, а сообщение объясняет причину. Наличие `.git`, `.env`, `vendor`, `.stversions` и других исключённых/неиндексированных данных обычно блокирует очистку **всего проекта**: серверная completion не подтверждает сохранность этих файлов. Это намеренное выполнение условия «при сомнении не удалять». Корзина не является атомарной транзакцией с одновременно пишущими в проект сторонними программами.

### Исключения Syncthing и очистка

`disk/stignore.txt` получил только корневой `(?i)/desktop.ini`. Накопительная история сохранена и дополнена нормализованным хэшем `c20a596f615c0a62ffd6e5a1e8a9dd8c3a06420b26d312b29b9d8dced0632eb8`.

Одного изменения шаблона для уже подключённых папок недостаточно. `Ensure-DiskExplorerIgnores.ps1` обновляет только известный базовый шаблон или точную собственную selective policy, сохраняет её suffix и receipt. Штатный REST `db/ignores` записывает и загружает исключения; затем проверяются ответ REST и сохранённый файл. Чужие правила не переписываются. Контроллер получает `{path, sha256}` доверенной политики и перед оформлением проверяет неизменность её файла. Без такого подтверждения подключённая папка не получает `desktop.ini`. Подготовка выполняется при смене привязки/выбора и затем с минутным интервалом, а не в каждом 2500-мс цикле.

`build/bundle-files.txt` и `Get-WizardRuntimeFiles` включают новые помощники в ZIP и локальную копию runtime.

`Disk.Explorer.ps1`, `Remove-DiskExplorer.ps1`, `Install-RemoteDisk.ps1 -Uninstall`, `build/Uninstall.ps1`, `Setup.Common.ps1`, `Uninstall.cs` снимают свои HKCU-пункты, метаданные обычных и зарегистрированных внешних папок, возвращают исходный ReadOnly и удаляют свои известные ICO. Чужие файлы, атрибуты и значки сохраняются. Uninstall дожидается остановки трея; Dispose контроллера отменяет опрос и завершает текущую запись метаданных до освобождения instance mutex.

Выключение Диска снимает оформление, сохраняя junction внешнего источника для последующего включения. Uninstall и снятие внешнего выбора размыкают собственный junction, не удаляя исходник. Пустые каталоги-заглушки при удалении оформления остаются обычными пустыми папками.

## Syncthing Tray: проверка готового компонента

Проверены официальные исходники поставляемого SyncthingTray v2.1.9: `initSyncthingTray(windowed)` вызывает `settings.launcher.autostart()` даже в оконном режиме, а при `windowed` возвращается до создания TrayIcon. Поэтому запуск с основным ini небезопасен для условия «без второго Syncthing».

`DiskDetailsLauncher` копирует ini в `RemoteDisk/tray/details/syncthingtray.ini`, отключает `syncthingAutostart` и автозапуск дополнительных tools, запускает тот же EXE с `qt-widgets-gui --windowed --new-instance` и WorkingDirectory `details`. QtUtilities сначала выбирает portable ini из WorkingDirectory. Повторное нажатие активирует уже открытый процесс окна. Данные подключения сохраняются из поставляемого ini; значения секретов не попадают в журнал.

Основания: [SyncthingTray main](https://github.com/Martchus/syncthingtray/blob/v2.1.9/tray/application/main.cpp#L135), [настройки](https://github.com/Martchus/syncthingtray/blob/v2.1.9/syncthingwidgets/settings/settings.cpp#L134), [QtUtilities portable ini](https://github.com/Martchus/qtutilities/blob/master/resources/resources.cpp#L430). Проверка исходников не выдаётся за проверку процесса на настоящей Windows.

Хэши файлов проверяются в формате штатного индекса: [REST JSON Syncthing](https://github.com/syncthing/syncthing/blob/v1.30.0/lib/api/api.go#L1868), [BlocksHash](https://github.com/syncthing/syncthing/blob/v1.30.0/lib/protocol/bep_fileinfo.go), [размеры блоков](https://github.com/syncthing/syncthing/blob/v1.30.0/lib/protocol/protocol.go), [completion](https://docs.syncthing.net/rest/db-completion-get.html). Собственный код здесь только проверяет доказательства перед локальной файловой операцией; синхронизацию не реализует.

## Проверки

Чистая исходная точка `0637c03` проверена полным `app/launcher/tests/run.sh` в отдельном временном worktree: **exit 0**, 76 серверных тестов, portable двух продуктов, CONFIG по 134 проверки, настоящий SSH/sing-box CONFIG/e2e, тестовый ZIP. Worktree после проверки удалён.

В обоих итоговых прогонах используется `SKIP_LAUNCHER_EXE=1 PYTHONPATH=/tmp/folders-status-test-isolation`. Это прежняя внешняя фикстура из FOLDERS-STATUS-REPORT: `PENDING` подменяется временным каталогом исключительно в `test_lan_vpn.SafetyTests.test_timer_failure_prevents_network_mutation`; код VPN, утверждения теста и живой `/var/lib/remoteagents` не изменяются. Обычный запуск без фикстуры на этом исполнителе сохраняет известный `PermissionError` LAN-теста и зелёным не объявляется.

Общий последовательный прогон новой ветки завершился **exit 1** в известном нестабильном `transport/test-engine-loopback.py`: request-файл исчез до `chmod`. До этой точки прошли новые disk-проверки, остальные предшествующие offline-команды и все 76 серверных тестов. Один ранний запуск под нагрузкой также дал `remote commands were serialized`. Отдельный повтор **неизменённой** команды `python3 transport/test-engine-loopback.py --without-disk` завершился **exit 0**.

Оставшиеся после loopback команды из `run.sh` выполнены последовательно отдельным временным runner: сами команды, assertions и таймауты не изменены. Проверка упаковки обнаружила отсутствующие три новых PS-файла в allowlist; исправлен `build/bundle-files.txt`, после чего `test_build.py` прошёл все 12 тестов. Оставшийся хвост завершился **exit 0**: bridge/boundary/operations, portable RemoteAgents и RemoteVPN (277 проверок модели, по 53 metadata и shell/safety), CONFIG по 134 проверки, настоящий SSH/sing-box CONFIG/e2e (87 с), тестовый ZIP и явный SKIP EXE build/publish. Это составная проверка всего набора, **не** заявление о нулевом коде единственного запуска `run.sh`.

Параллельный предварительный прогон исходной и новой версий столкнулся на фиксированных портах transport-liveness; в последовательном прогоне этот тест прошёл. Производственные транспортные файлы и его тесты не правились. EXE build/publish отключён во всех прогонах через `SKIP_LAUNCHER_EXE=1`.

## Ручная приёмка на Windows 10 и 11

1. На настоящем Windows PowerShell 5.1 проверить новую и повторную установку оформления с обычным и настроенными каталогами проектов/состояния, включая пробелы, кириллицу и конечный `\` в `--home`.
2. Проверить все пять значков в режимах 16/32/48/256, InfoTip, изменение процента, ошибку, offline/возврат связи и отсутствие новых записей desktop.ini при неизменном состоянии. Проверить атрибуты папки/ini и обновление кеша Explorer.
3. Добавить проект на сервере после запуска трея: получить заглушку при следующей минутной сверке. Положить в неё свой файл: получить локальную копию и обычное умное объединение при «Синхронизировать».
4. Проверить меню на заглушке, локальной/подключённой папке и вне Диска, несколько выбранных папок, одну общую операцию Apply и окно хода. В Windows 11 команды находятся в «Показать дополнительные параметры» — это ожидаемо.
5. Проверить download/sync, совпадение config/selection с вкладкой «Папки», исчезновение/ошибку REST и неудачное отключение: продолжающая работать папка не должна стать «локальной».
6. На одноразовом проекте проверить освобождение с неполным сервером, локальными изменениями, ignored данными и обрывом связи — файлы остаются. Для полностью подтверждённой папки проверить штатную Корзину, отмену, сохранность данных и пустую помеченную заглушку. Проверить восстановление файлов из Корзины.
7. Добавить внешний источник: junction с правильным именем/target, никаких обходов инвентаризацией; проверить занятое имя и broken junction. Проверить оформление исходника/ссылки, чужой desktop.ini, выключение/включение и uninstall с сохранностью исходных файлов.
8. Открыть «Подробнее…»: одно окно, отсутствие второго значка и второго Syncthing; проверить конкретно поставляемый ini и `--help`. Счётчик процессов сравнивать до/после. Оконный процесс закрыть независимо от трея.
9. Проверить выключение Диска и Uninstall при работающем опросе: собственных меню/ини/ICO нет, исходный ReadOnly восстановлен; чужое оформление и вложенные desktop.ini сохранены.

## Ограничения

- Настоящие Windows 10/11, Explorer, Windows PowerShell 5.1, Корзина и оконный Syncthing Tray здесь не запускались. Linux, PowerShell 7, подмены и компиляция не заменяют эту приёмку.
- Статические verbs используют `MultiSelectModel=Document`: legacy Explorer поддерживает до 15 элементов для такой поэлементной команды. [Документация Microsoft](https://learn.microsoft.com/en-us/windows/win32/shell/how-to-employ-the-verb-selection-model). COM для обхода этого ограничения не добавлялся.
- «Оставить только на сервере» для внешнего источника отказывает в очистке, сохраняет источник и объясняет, что снять его выбор можно на вкладке «Папки». Это защищает исходную папку вне Диска от неожиданного удаления.
- REST без необходимых полей/хэшей, ignored/unindexed данные, чужие правила игнорирования или невозможность подтвердить отключение приводят к сохранению локальных данных. Чужой desktop.ini сохраняет свой значок без нашей подсказки.
- При сломанной установке без текущего бандла C# fallback снимает доступное своё оформление и меню; безопасное размыкание junction без helper/receipt не имитируется.
- При остановленном трее состояние Explorer больше не обновляется. Серверные заглушки появляются после успешной сверки, а не по событию push.
- EXE не собирался и не выкладывался. На рабочие компьютеры и живой сервер изменения не устанавливались. Транспорт, VPN, мост и Happier не изменены; их проверки выполнялись только в общем наборе.
