# План: два EXE с общей конфигурацией

Статус: код задачи G и Linux-проверки готовы; приёмка Windows ожидается. Дата: 10 ноября 2026. Правила: [CONSTITUTION.md](CONSTITUTION.md), [PLAN.md](PLAN.md).

## Два EXE (задача G)

Решение от 10.11.2026 заменяет прежний план одного EXE. Реализация —
[LAUNCHER.md, «Два EXE»](LAUNCHER.md#два-exe). Нижние этапы сохраняются как история общей архитектуры.

1. Один C# проект собирается с ProductName=RemoteAgents / RemoteVPN. Раздельны mutex, IPC, Run,
   бандлы, backup EXE и журналы; общий config обновляется под существующей блокировкой.
   RemoteVPN зависит от проверенного transport RemoteAgents, своего транспорта не запускает.
2. Добавлен автоматический первый запуск с существующим SSH askpass и Setup-All; сохранённый профиль
   проверяется настоящим SSH перед пропуском ввода. Полная старая установка идёт через прежний
   Migrate с watchdog. Это установка новой **Windows**, сервер должен отвечать прежним требованиям
   disk/control (рабочий пользователь и канал VLESS); bootstrap пустого VPS в эту работу не входит.
3. Headless встроенного Syncthing заменяет второй GUI, использует прежний state; восстановление
   Run/GUI включено в rollback. Для ранее принятой миграции GUI снимается также при обновлении.
4. Процессы перестали быть VPN-конфликтами; активные адаптеры/default/split-default — факты конфликта.
5. Устранён пробел после connected: broker проверяет обратный путь, PS читает heartbeat,
   control-компонент проверяет его PID/свежесть и перезапускает managed-мост после отказов.
6. Start.cmd — три строки с двумя `start`; постоянной консоли нет, вспышка cmd возможна.
7. release/ содержит оба PE EXE и Start.cmd; Git разрешает их, канонический Syncthing ignore не исключает.
8. Обновление/backup/health rollback используют пространство своего продукта. Portable-тесты гоняются
   для обоих вариантов; Windows selftest-upgrade дополнен проверкой неприкосновенности соседнего продукта.

### Приёмка владельцем: сначала изоляция, затем ноутбук и стационарный

1. Сохранить имеющиеся рабочие EXE/бандлы и убедиться, что текущий control доступен с сервера.
   Не выполнять рабочую миграцию через мост: её остановка завершает текущие команды моста.
   Все следующие действия выполнять локально человеком.
2. В обычном PowerShell 5.1 создать новый временный Home; запустить из release оба EXE
   с `--tray --home <этот Home>`. Ожидание: два своих трея, разные PID/IPC, общая конфигурация;
   без серверного профиля честный красный/неизвестный transport. VPN сам не включается и Run не меняется.
   Не копировать в тестовый config реальные порты/включённые disk/control, не включать TUN.
3. В отдельных новых временных каталогах выполнить
   `RemoteAgents.exe --selftest-upgrade <каталог>` и `RemoteVPN.exe --selftest-upgrade <другой каталог>`.
   Дождаться JSON-результатов (несколько минут из-за настоящего 120-секундного таймера). Проверить `ok=true`.
   Эти тесты используют синтетические модули, не производственный transport и не Run.
   Закрыть только тестовые треи через соответствующие EXE `--exit --home <тестовый Home>`.
4. На ноутбуке первым проверить переход локальным двойным щелчком RemoteAgents.exe. Не вводить
   существующие настройки заново. Убедиться в наличии независимого rollback до переключения,
   свежих transport/disk/control и heartbeat. Проверить с сервера windows_devices и status именно ноутбука.
   Не подтверждать вручную при ошибке; дождаться автоматического отката и восстановления старого control.
5. После принятия проверить отсутствие GUI `syncthingtray --wait` и Run RemoteDisk. Один процесс
   `syncthingtray.exe syncthing serve ...` допустим — это engine без иконки. Проверить меню папки,
   Syncthing web, добавления папки и передачу тестового файла в Disk.
6. Проверить RemoteVPN сначала без включения: запуск/повторный запуск не вызывает UAC и не меняет сеть.
   Для проверки конфликта при активном Happ убедиться, что указан его реальный адаптер/маршрут.
   С выключенным Happ, но оставшимися старым channel/sing-box и службой Amnezia ложного конфликта нет.
   Само включение TUN выполнять лишь после проверки независимости моста и локального доступа к откату;
   UAC подтверждает человек. Проверить DNS/HTTPS, выключение и удаление только своих маршрутов.
7. При локальном доступе проверить краткий разрыв сети: heartbeat устаревает, статус перестаёт быть
   зелёным, мост переподключается. Для сценария «процесс жив, канал мёртв» использовать изолированный
   стенд/контролируемый отказ reverse forwarding; не удалять рабочий серверный сокет ноутбука удалённо.
8. Запустить новую пару EXE поверх работающей: у каждого сохраняются config/secrets и соседний процесс.
   Проверить ручной downgrade с отказом по умолчанию; проверить `--rollback` каждого в изоляции.
   Выход/обновление RemoteVPN не должны останавливать control/transport/disk.
9. Повторить пункты 4–8 на стационарном после устойчивой проверки ноутбука. Мастер чистой машины
   проверять в отдельной Windows-учётной записи или VM с новым LOCALAPPDATA; не переименовывать
   рабочий Home ради имитации чистоты. Сначала отменить ввод пароля, повторить запуск; затем установить,
   повторно запустить второй EXE и убедиться, что настройки не запрашиваются. Проверить отказ SSH и
   недоступный сервер: успех не показывается, исходная установка не теряется.

## Проблема

Сейчас всё разбросано: `SETUP.cmd`, `04-disk.cmd`, `05-control.cmd`, задачи планировщика, трей Syncthing,
отдельный канал sing-box, мост, Happ. Каждый раз приходится вспоминать, что запускать, а при обрыве — где чинить.

## Решение: тонкий EXE + сменные модули

```
%LOCALAPPDATA%\RemoteAgents\
  RemoteAgents.exe          лаунчер: трей, автозапуск, надзор, обновление. Меняется редко.
  bundle\current.txt        имя активной версии модулей
  bundle\<версия>\          модули: PowerShell-скрипты, sing-box.exe, components.json, selftest.ps1
  config.json               настройки пользователя (без секретов, со схемой и версией)
  status\<компонент>.json   честный статус каждого компонента
  logs\                     журналы, пишутся всегда
```

- **Лаунчер** (C#, .NET Framework 4.8 — есть в каждой Windows 10/11, файл маленький, рантайм не нужен) ничего
  не знает о VPN, дисках и мостах. Он читает `components.json` из активного бандла, запускает компоненты,
  перезапускает упавшие, показывает в трее их статусы и меню.
- **Модули** — то, что меняется часто: скрипты и бинарники. Исправление = новый бандл, а не новый EXE.
- **Обновление по воздуху**: на сервере `publish-bundle.sh` собирает `dist/<версия>.zip` и `manifest.json`
  (версия, sha256, размер, минимальная версия лаунчера). Лаунчер только по явной кнопке «Проверить
  обновления» (фонового таймера нет) забирает манифест и архив **через SSH к своему серверу** (тот же самоисцеляющийся канал; домен не
  нужен), проверяет sha256, распаковывает в `bundle\<версия>`, запускает `selftest.ps1`, переключает
  `current.txt`, перезапускает компоненты. Если компоненты не стали здоровыми за 2 минуты — автоматический откат
  на прежнюю версию. Новый лаунчер приезжает в том же бандле и подменяет себя через переименование.
- **Портабельность**: в EXE вшит начальный бандл, поэтому первый запуск работает без сети. Нет настроек — мастер
  (сервер, пароль один раз → ключ), есть старые профили — импорт без вопросов.

## Компоненты первого выпуска

| Компонент | Что делает | Основа (не пишем своё) |
|---|---|---|
| transport | Держит связь с сервером: несколько путей, сам выбирает лучший, переключает | sing-box (selector + clash API) |
| disk | Синхронизация папок `%USERPROFILE%\Disk` | Syncthing + syncthingtray |
| control | MCP-мост управления компьютером | `Start-WindowsControl.ps1` |
| updater | Обновление бандла | встроен в лаунчер |

Все обращения к серверу (диск, мост, обновления) идут через локальные входы `transport`:
`127.0.0.1:2222` → SSH сервера, `127.0.0.1:22001` → Syncthing сервера. Поэтому при смене пути ничего
перенастраивать не нужно.

## Транспорт: автовыбор пути

- Кандидаты строятся из конфига: прямые (SSH, VLESS-Reality) и через узлы-входы (`transport/entry/install-entry.sh`:
  Hysteria2, Hysteria2+salamander, TUIC, Trojan, Reality, ShadowTLS, VLESS-WS, VLESS-WS через CDN, SSH-переход).
- Один постоянный sing-box. Рабочие входы ведут в `selector`; лаунчер/демон переключает его через clash API без
  перезапуска (живые сессии не рвутся).
- Проверка «замёрзания» обязательна: ТСПУ пропускает первые 16–30 КБ и останавливает поток. Поэтому живость —
  это 64+ КБ без остановки, а не ping.
- Расход: активный путь — 64 КБ раз в 2 минуты (лимитная сеть — раз в 5); полный рейтинг — при смене сети и раз в
  30 минут по 256 КБ на путь (лимитная сеть — только 3 лучших). Всё настраивается в `config.json`.
- Память по сетям: отпечаток сети (шлюз + имя сети) → последний рейтинг; при подключении сразу берётся лучший.
- Системный VPN (TUN без Happ) — отдельный следующий этап, только с исключением локальных сетей и OpenVPN и с
  автооткатом. В первом выпуске TUN нет: OpenVPN и локальные сети не затрагиваются.

## Безопасный переход на существующих компьютерах

Реализован независимый `build/Rollback.ps1` через задачу «RemoteAgents rollback» на 10 минут.
Сначала проверяются временные входы транспорта и SSH true, затем отключается (не удаляется) старый канал,
поднимаются рабочие входы и добавляется обратимый SSH-блок. Исходные control/ и JSON профилей сохраняются;
совместимая добавленная копия моста имеет прежний отдельный автозапуск. Подтверждение требует transport,
SSH true, Syncthing connected и аутентифицированный ответ Windows executor через мост; автоматически — после трёх зелёных минут. Повторный запуск
не продлевает дедлайн. `--uninstall` вызывает тот же откат. Подробно: [LAUNCHER.md](LAUNCHER.md#переход-существующего-компьютера).
Код и Linux-проверки готовы; выполнение на реальной Windows и ноутбуке ещё не принято.

## Решения владельца 9 ноября 2026 (вечер)

- **Обновление — ручное.** Не обновлять в фоне. Новая версия = скачали новый `RemoteAgents.exe` и запустили:
  он находит установленную версию, корректно останавливает её, ставит свой бандл, сохраняет настройки, журналы и
  память путей и продолжает работу. Старая установка без нового EXE работает дальше как есть.
- **Путь виден и выбирается в трее.** По щелчку на иконке: текущий путь, скорость, когда проверен; список путей
  с состоянием; «Автовыбор» (по умолчанию) или закрепить конкретный путь.
- **Входы, прыжки, ретрансляторы и CDN задаются без правки кода:** список в `config.json` и команды
  добавить/удалить/включить/выключить (и пункты в трее). Можно держать 2–4 VPS; по умолчанию всё проверяется
  автоматически, выбирается лучшее. CDN — любой (Cloudflare, российские CDN), как тип пути «WebSocket через домен».
- **Системный VPN (TUN) входит в этот выпуск отдельным компонентом**, по умолчанию выключен, включается в трее.
  Пути — те же, что проверены. OpenVPN и локальные сети исключаются из туннеля. Если уже работает другой VPN
  (Happ, другой TUN/WireGuard), приложение не управляет им, а показывает окно: какой VPN найден (процесс/адаптер),
  и предлагает либо отключить его самостоятельно, либо оставить его и не включать наш. Живая проверка TUN — в
  следующей версии, не на ноутбуке, где работают MCP-сессии.
- **Сборка** — на сервере; Windows-компьютеры для сборки не нужны. Тесты на ноутбуке не должны трогать основной
  мост: новые компоненты проверяются на отдельных портах, переход — только с автооткатом.

### Утром: переход ноутбука (с автооткатом через 10 минут)
1. `build/build-exe.sh` на сервере → `build/out/RemoteAgents.exe` (скопировать на компьютер).
2. На компьютере: `RemoteAgents.exe --install` — окно «RemoteAgents — переход»; при сбое всё вернётся само.
3. Добавить узел: `powershell -File %LOCALAPPDATA%\RemoteAgents\bundle\<версия>\transport\Edit-Transport.ps1 -AddEntry sparfum -Ssh sparfum`,
   затем `...\Update-Entries.ps1`. Старые маршруты канала импортируются автоматически (исправление H);
   дополнительные узлы, отсутствующие в старом канале, по-прежнему задаются пользователем.
4. Тестовый каталог убрать: `RemoteAgents.exe --exit --home %LOCALAPPDATA%\RemoteAgentsTT`, удалить папку.

## Живой прогон 10.11: стационарный

Результат владельца: Windows 10, PS 5.1, раздача с телефона + Happ TUN; переход не прошёл preflight,
