# Шлюз Telegram при настройке сервера

В этой ветке перенесена только серверная часть `app/tg-gateway`. Её запускает
`server/server-apply.sh` из раздела `telegramGateway` мастер-конфига —
см. [SERVER-APPLY.md](SERVER-APPLY.md). Автоматический вызов из мастера EXE
и C#/PowerShell-операции установки относятся к отдельному заданию B;
здесь они не переносились.

Код устанавливается в `~/.local/opt/tg-gateway`, служба — systemd **--user**,
без root и sudo. Публичный IPv4 определяется по default таблицы main;
системный TUN не влияет на выбор. При NAT/отсутствии публичного IPv4 задайте
`TG_GW_PUBLIC_HOST`; `TG_GW_PORT` позволяет выбрать порт явно. По умолчанию
выбирается свободный 8444–8499, затем порт сохраняется. При обновлении старого
unit порт переносится из него; ключи и подходящий сертификат сохраняются.
Если хост изменился, старый сертификат архивируется, новый нужно передать клиентам.

Для выдачи данных клиентскому серверу от пользователя службы:

```bash
~/.local/bin/tg-gateway-keys add client-name --json
```

Результат — `base_url` с секретом, `ca_pem` и SHA-256 `sha256`.
Сохраните их сразу: секрет повторно не выдаётся. Клиент должен доверять
переданному PEM; проверка TLS остаётся включённой. Отзыв без перезапуска:
`~/.local/bin/tg-gateway-keys revoke client-name`.

Шлюз не зависит от установки Node.js/Happier или подключения аккаунта.
`accounts/bootstrap.sh` и остальные `server-*.sh` остаются отдельными
установщиками. Проверка службы и `/health` доступна через `install.sh --check`.

Подробности, переменные и тесты: [server/tg-gateway/README.md](../server/tg-gateway/README.md).

Тесты шлюза также включены в общий `bash server/tests/run.sh`.
