# Задача INVITE: подключение компьютера по приглашению

11 ноября 2026, решение владельца. Делать в отдельном worktree от `app/windows`, ветка `app/invite`.
Правила: `docs/CONSTITUTION.md` (особенно §1 — ничего не вшивать, §3 — секреты отдельно, §5 — честный статус, §6б — CRLF).

## Что нужно владельцу

Сервер уже настроен администратором через обычный мастер RemoteAgents.exe. Чтобы подключить ещё один
компьютер (свой ноутбук и т. п.), администратор на сервере запускает одну команду и получает ссылку
и ZIP. На новом компьютере человек открывает ссылку, скачивает ZIP, распаковывает, запускает
`RemoteAgents.exe` — и компьютер подключается сам, без ввода адреса сервера, пароля root, ключей и обходов.

## Жёсткие границы

- **Одно рабочее место.** Никаких новых пользователей Linux: компьютер подключается к тому же
  рабочему пользователю (сейчас `remoteagents`), тому же диску, тем же агентам и подпискам.
  Разделение людей, пулы подписок, переключение подписок — НЕ делать.
- Мастер администратора (первоначальная настройка сервера) не ломать и не усложнять.
  Приглашение — отдельный вход.
- Ничего не делать на Windows-компьютерах владельца и не менять живую конфигурацию сервера
  (sshd, authorized_keys рабочего пользователя, службы). Все проверки — на изолированных стендах
  (свой sshd на loopback, одноразовые HOME). Установка на живой сервер — только после приёмки владельцем.
- Commit в ветку `app/invite` можно, push и merge — нет.

## Сервер: команда `remoteagents invite`

```
remoteagents invite create --name "Ноутбук" [--hours 24] [--happier same|new:ИМЯ] [--folders a,b/c]
remoteagents invite list
remoteagents invite revoke <id>
```

1. **Одноразовый пропуск** штатными средствами OpenSSH (§2 конституции, минимум своего кода):
   - служебный пользователь `ra-enroll` без пароля и shell (создаётся при первом запуске, идемпотентно);
   - на каждое приглашение новая пара ed25519; открытая часть в `~ra-enroll/.ssh/authorized_keys` с
     `restrict,expiry-time="…",command="<enroll-скрипт> <id>"`;
   - enroll-скрипт читает из stdin ровно один открытый ключ ed25519, под `flock` проверяет, что
     приглашение не использовано и не истекло, дописывает ключ рабочему пользователю с меткой
     `ra-device:<имя>` (через одну узкую sudo-строку только на этот скрипт), помечает приглашение
     использованным и удаляет строку пропуска. Ответ — короткий JSON.
2. **Файл приглашения** `invite.rainvite` (JSON, версия схемы):
   адрес и порт сервера, ключи хоста сервера (pinning), рабочий пользователь, список маршрутов в формате
   маршрутов мастера (коммит 8254876: напрямую / локальный прокси / промежуточный SSH-сервер; берутся из
   текущих настроек сервера или параметров команды, не из кода), закрытый ключ пропуска, срок действия,
   выбор Happier (`same` или `new:ИМЯ`), необязательный набор папок диска.
   Секрет Happier в приглашение НЕ кладётся: после регистрации компьютер уже имеет SSH-доступ и
   получает нужное с сервера тем же путём, что сейчас делает мастер.
   Если маршрут через промежуточный сервер требует ключ/пароль — он попадает в приглашение; в выводе
   команды предупредить, что ZIP секретный, как пароль.
3. **ZIP**: актуальный `RemoteAgents.exe` из `release/` + `invite.rainvite`. EXE не перепаковывать.
4. **Ссылка на скачивание**: прямой HTTP к основному серверу у части провайдеров режется (ТСПУ),
   поэтому раздача — сменным вариантом (§1): по умолчанию команда пишет путь к ZIP; опционально
   `--publish <узел>` выкладывает ZIP на промежуточный узел, заданный в настройках, по случайному пути,
   с удалением после первого скачивания или по сроку. Адрес узла — из конфига, не из кода.

## EXE: режим «по приглашению»

1. Если рядом с EXE лежит `*.rainvite` (или его перетащили/вставили на первом экране) — режим приглашения,
   мастер администратора не показывается (доступен ссылкой «Настроить сервер вручную»).
2. Ключи хоста из приглашения записываются в known_hosts, проверка строгая; несовпадение — понятная
   ошибка, без «принять всё равно».
3. Генерируется собственный ключ компьютера (существующий код). Маршруты из приглашения пробуются по
   очереди существующим кодом маршрутов мастера; регистрация через `ra-enroll` с пропуском.
4. После «ок» пропуск и файл приглашения удаляются, дальше всё своим ключом и автоматически: связь, мост,
   Happier по выбору из приглашения, диск — показать только выбор папок (предзаполненный из приглашения).
5. Окно: одна строка этапа и честный итог; при ошибке — причина простыми словами и «Повторить».
   Просроченное/использованное приглашение — отдельное понятное сообщение.

## Проверки

- Сервер (изолированный sshd на loopback): пропуск срабатывает один раз; два одновременных — проходит ровно
  один; после срока не пускает; мусор/два ключа/не ed25519 — отказ; через пропуск нет shell, проброса
  портов, agent/X11; `revoke` закрывает; повторный `create` идемпотентен для `ra-enroll`.
- EXE: разбор приглашения и проверка схемы; несовпадение ключа хоста — отказ; перебор маршрутов
  (недоступен прямой → проходит следующий); сквозной тест на стенде: приглашение → регистрация → вход своим
  ключом. Полный `app/launcher/tests/run.sh` проходит.
- Сборка `build/build-exe.sh`, SHA-256 в отчёте.

## Отчёт

Коротко: что сделано, где (файлы), какие проверки прошли с цифрами, что не проверено на реальной системе
(Windows владельца, живой сервер, реальная раздача ссылки) и точная инструкция для приёмки владельцем.
