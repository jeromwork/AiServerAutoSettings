# Что делать дальше (после задачи CONFIG)

Записано 12.11.2026 по решению владельца. Порядок: сначала доделываем работу с конфигом (`docs/TASK-CONFIG.md`), потом — по списку.

## 1. Развёртывание чистого сервера по конфигу

Многое на текущем сервере ставилось руками в разное время. Нужно, чтобы чистый VPS после вставки конфига (вход root по паролю)
разворачивался программой полностью и работал так же стабильно, как текущий.

- [x] Опись живого сервера: что реально работает и что из этого ставит программа сама — `docs/SERVER-INVENTORY.md` (12.11).
      Главные пробелы: пакеты чистой ОС; серверная сеть (системный sing-box, вход 443, TUN, DNS, маршруты); установка агентов
      (Codex, Claude Code, ChatGPT) и метка `managed-user-v1` у пользователя; проверка готовности; автозапуск после перезагрузки;
      рабочий стол, project views, закрытие чатов, keepalive.
- [ ] По каждому пробелу: какие поля добавить в конфиг и какой шаг развёртывания написать (идемпотентно, с проверкой и откатом, §4).
- [ ] Отдельно описать, что зависит от внешних вещей и программа сама не сделает: домен, второй VPS / входной узел, CDN, хостинг —
      что владелец готовит заранее и какие поля конфига это заполняет.
- [ ] Проверка: чистый тестовый VPS → вставка конфига → сервер работает как текущий (связь, мост, диск, Happier, VPN, прокси).
- [ ] `remoteagents config export` с рабочего сервера даёт конфиг, по которому другой чистый сервер разворачивается так же.
- [ ] **Промежуточные VPS (входы, например в России).** Их может быть несколько. В конфиге — список `entries[]`/`relays[]`
      (адрес, логин, порт; пароль/ключ — секретом). ИИ при сборке конфига спрашивает «есть ли промежуточные VPS?». Программа сама
      ставит на них вход (rd-entry/relay — сейчас ставится вручную, entry-bootstrap исключён из EXE), проверяет и добавляет
      в каталог маршрутов; компьютеры получают их автообновлением. Принцип: зашёл один раз по паролю → поставил только вход
      (relay/SSH-переход), свой ключ, проверил, не задев чужие службы и порты → ушёл. Дальше VPS — просто маршрут.

## 2. Сбор конфига

Один формат конфига, три способа собрать. ИИ паролей не видит ни в одном.

- [ ] **ИИ в браузере** (ChatGPT/Claude/Gemini, без файлов): кнопка «Собрать конфиг с ИИ» копирует запрос
      (`app/launcher/config-ai-prompt.md`) со ссылкой на `docs/CONFIG.md` в публичном GitHub. ИИ задаёт вопросы, выдаёт только JSON,
      секреты — ссылки с подсказками и пустыми значениями; человек вставляет JSON в программу, пароли вводит в окне программы.
      ИИ предупреждает, если человек пишет пароль в чат. Довести текст запроса и проверить на 2–3 чатах вживую.
- [ ] **Агент на компьютере** (Gemini и т. п.): `docs/CONFIG.md` — как собирать конфиг, правило «файл секретов не читать»;
      пароли только через `RemoteAgents.exe secret set <имя> --why "…"` (окно со скрытым вводом). Проверить с живым агентом.
- [ ] **Сервер уже есть**: `remoteagents config export --name "…"`; описать в `docs/CONFIG.md`.
- [ ] Сценарий «сервера ещё нет»: ИИ спрашивает адрес VPS и подсказку к паролю root, конфиг помечает сервер как ненастроенный,
      программа разворачивает его (см. п. 1).
- [ ] Опционально: простая страница-форма в браузере (без ИИ), которая собирает конфиг локально.

## 3. Выдача доступа и поставка EXE

- [ ] **Команда «подключить ещё компьютер» на сервере**: `remoteagents config export --name "…" --zip` → ZIP: последний стабильный
      `RemoteAgents.exe` + файл конфига (по желанию с мастер-паролем). EXE и конфиг — разные файлы; в EXE конфиг не вшивается.
      Человек распаковывает, запускает EXE, программа находит конфиг рядом, показывает папки — и всё.
- [ ] **Одноразовая ссылка вместо команд PowerShell** (решение 12.11): человек получает ссылку `http://<сервер>:<порт>/<токен>`,
      открывает → страница с кнопкой «Скачать» → ZIP; после полного скачивания или по сроку ссылка гаснет, файл удаляется.
      Сейчас — `server/oneshot_link.py`; встроить в `remoteagents config export --link`. Порт и адрес — из настроек выдачи (§1),
      при ТСПУ — раздача через промежуточный VPS. По HTTP ключ идёт открыто — по умолчанию предлагать мастер-пароль.
- [ ] **Хранение EXE**: в истории git не копить (28 МБ на сборку). Последняя стабильная сборка — в GitHub Releases (latest)
      и в `~/downloads` на сервере; `release/*.exe` убрать из git.
- [ ] Всё нужное (скрипты PowerShell, sing-box) уже внутри EXE, отдельных командных файлов у человека нет — подтвердить на Windows.
- [x] Решено 12.11: **один EXE** — сам понимает по конфигу, подключаться или разворачивать сервер.
