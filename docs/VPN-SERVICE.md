# Служба системного VPN

Основной режим использует одну общую службу Windows `RemoteAgentsTun` для RemoteAgents.exe и RemoteVPN.exe. SCM автоматически запускает её как LocalSystem командой `"<ProgramFiles>\RemoteAgents\vpn\RemoteAgentsTun.exe" --vpn-service`. Рядом хранится проверенный `sing-box.exe` 1.14 со встроенным Wintun; отдельная DLL не нужна. Служба после загрузки Windows остаётся в состоянии `off`: автозапуск службы не включает VPN.

## Включение и выключение

`Vpn.Tun.ps1 -Enable` проверяет готовность службы. Первичная установка требует одного подтверждения UAC; далее обычный пользователь запускает остановленную службу и управляет ею без повышения. Пользовательский worker запускается через Win32_Process вне job лаунчера, строит конфиг существующим `New-VpnTunConfig` и отправляет команду `start` по именованному каналу. Служба валидирует и заново собирает конфиг, проверяет SHA-256 установленного sing-box, выполняет `sing-box check`, запускает TUN в kill-on-close job и выдаёт случайный идентификатор сеанса.

Сначала состояние службы — `starting`, с независимым сроком отката 300 секунд. Worker ждёт адаптер и выполняет существующую проверку маршрута через TUN, SSH 64 КиБ с закреплённым host key (кроме bootstrap), DNS и HTTPS. Только после успеха `confirm` снимает срок отката и переводит службу в `on`. Чужой VPN даёт предупреждение; его процессы и маршруты не изменяются. При смене пути или конфига новый запуск снова требует проверки и подтверждения.

`-Disable` записывает флаг остановки; worker отправляет `stop`. Выключение также происходит при общем Home/stop, отключённом vpn.enabled, смерти лаунчера или worker, выходе sing-box и отсутствии подтверждения. Служба следит за открытыми handle процессов, а не только PID. После остановки sing-box она ждёт исчезновения своего интерфейса до десяти секунд; оставшийся интерфейс означает `cleanup-error`, а не успешное выключение. Пользовательский статус `on` публикуется лишь после сетевой проверки и ответа службы с тем же сеансом.

## Модель угроз

Защищаемый актив — процесс и права SYSTEM. Противник — любой процесс обычного пользователя (в том числе владельца установки), другой пользователь компьютера либо сетевой клиент. Администраторы и SYSTEM могут управлять службой и её файлами.

1. Исполняемые файлы лежат в Program Files с защищённым ACL: запись только SYSTEM и Administrators, остальным чтение/выполнение. Конфиг с секретами и журналы находятся в `run`, доступном только SYSTEM и Administrators. Установщик устраняет junction/symlink каталогов назначения, применяет ACL и проверяет отсутствие разрешающей записи посторонним SID; служба повторяет проверку каталогов при старте. Копирование выполняется из прочитанного содержимого через SHA-256 и атомарную замену. sing-box принимается только по хэшу из `build/bundle-binaries.json`, вшитого в одобренный EXE, а не из пользовательского файла. Копия RemoteAgentsTun.exe отказывается работать как лаунчер.
2. Канал `RemoteAgentsTun` создаётся один раз и переиспользуется без освобождения имени. `FIRST_PIPE_INSTANCE` запрещает службе присоединиться к занятому имени, `REJECT_REMOTE_CLIENTS` отсекает сеть. DACL разрешает доступ только владельцу, SYSTEM и Administrators; владелец получает чтение/запись без FILE_CREATE_PIPE_INSTANCE, изменения ACL, владельца или удаления. Сервер аутентифицирует SID по токену процесса клиента; клиент до отправки конфига сверяет PID сервера канала с PID службы из SCM. Другой пользователь не может отправить команду или подставить канал остановленной службы так, чтобы получить конфиг.
3. Протокол версии 1 содержит только `status`, `start`, `confirm`, `stop`, без путей, исполняемых файлов, аргументов или скриптов. Размер запроса ограничен 1 МиБ, чтение строки — десятью секундами. Неизвестные ключи запрещены на каждом уровне; служба пересобирает конфиг по белому списку. Запрещены ssh/socks/direct/tor/wireguard и другие посторонние outbounds, пути ключей и сертификатов, experimental, rule_set, cache_file и log-файлы. Проверяются detour-граф, интерфейсы, адреса, порты, DNS, TLS и WS. Таким образом, процесс владельца может задавать только разрешённый VPN-маршрут, без произвольного исполнения или записи от SYSTEM.
4. Наблюдение удерживает handle каждого процесса до конца сеанса, защищая от повторного использования PID. `watchPid` допускается только для существующего процесса того же пользователя, который отправил запрос. Смерть клиента или наблюдаемого лаунчера выключает TUN.
5. Пятиминутный автооткат находится внутри службы и не зависит от живых пользовательских процессов, задач планировщика или читаемости Home/config.json. Отсутствие `confirm` выключает sing-box; закрытие job также завершает его дерево при выходе службы.
6. Остаточные риски: UAC при установке — согласие человека. Вредонос того же пользователя, работающий до установки, может подменить исходный EXE между согласием и чтением; UAC не является границей безопасности для того же административного пользователя. Владелец канала может направить весь трафик машины через свой сервер — это функция системного VPN, поэтому доступ получает только владелец, указанный при UAC. Он также может устроить отказ в обслуживании, остановив VPN. Компрометация самого sing-box и администратор компьютера находятся за пределами этой схемы проверки конфигурации.

## Обновление и удаление

Обычное включение не переустанавливает службу. Повторная установка с одним UAC нужна при смене Protocol или SHA-256 bundled sing-box. Остановленную совместимую службу владелец запускает без UAC благодаря праву SERVICE_START в SDDL. При обновлении установщик останавливает службу, ждёт выхода процесса, заменяет проверенные файлы, обновляет owner.json, автозапуск, recovery и DACL, затем ждёт Running. Отсутствие bundled sing-box допускается только при уже готовой совместимой службе.

Удаление RemoteAgents или RemoteVPN вызывает `--vpn-service-uninstall` с одним UAC: остановка, `sc delete`, удаление каталога vpn и пустого родительского RemoteAgents. Занятые файлы после повторов планируются к удалению при перезагрузке. Отмена UAC оставляет службу установленной. Старый broker с задачами остаётся только для `REMOTEAGENTS_VPN_LEGACY_UAC=1` и отката старых сеансов.

## Проверка на Windows

Linux-тесты проверяют схему, ACL-строки, установочный план, автомат состояний и пользовательский поток на заглушках; это не проверка живой сети. На Windows нужно проверить:

- Первую установку с UAC, фактические ACL каталогов/файлов, LocalSystem, автозапуск и recovery службы; повторное включение и запуск остановленной службы без UAC из обоих продуктов.
- PowerShell 5.1, настоящий канал и его права; отказ другому пользователю и сетевому клиенту, занятому имени канала и подменённому PID сервера.
- Рабочие TUN/DNS/HTTPS/SSH, предупреждение о чужом VPN, смену пути и протоколов; честный статус при выходе sing-box и исчезновении/остатке адаптера.
- Независимый откат без confirm, смерть worker/лаунчера, выключение и перезапуск службы; отсутствие оставшихся интерфейсов, маршрутов и процессов.
- Обновление с новым закреплённым бинарником, отказ неподходящему SHA-256, удаление и отмену UAC, удаление после перезагрузки при занятых файлах.
