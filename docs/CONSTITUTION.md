# Конституция проекта

Правила обязательны для людей и агентов. Изменяет их только владелец.

## 1. Приложение универсальное

Продукт работает у любого пользователя на любом подходящем сервере, а не только в нашей конфигурации.

- Домен, сервер, хостинг, прокси, DNS-провайдер, промежуточный хост и VPN-маршрут задаёт пользователь. В коде их значений нет.
- Если для функции нужен домен, приложение предлагает настроить свой и объясняет, что сделать. Если домена нет, оно говорит, что без него доступно.
- Наши значения (`corenetai.ru`, конкретный VPS, конкретный прокси) допустимы только в личном `config.json`, который не хранится в Git.
- Сторонний сервис подключается как сменный вариант, а не как условие работы продукта.
- Проверка правила: новый пользователь со своим сервером и доменом проходит мастер без правки кода.

## 2. Минимум своего кода

Там, где есть живое решение (Syncthing, sing-box, OpenSSH), пишем настройку и управление, а не свою реализацию. Если свой код всё же нужен, рядом указывается причина.

## 3. Настройки в конфиге, секреты отдельно

- Настройки хранятся в `config.json` со схемой и версией. В Git только схема и пример.
- Секреты в Git не попадают, в журналы и вывод не выводятся.
- Отметка «этап пройден» не заменяет проверку: перед пропуском этапа выполняется реальный тест.

## 4. Изменения сети обратимы

Любое изменение сети на сервере или компьютере проверяется до применения и имеет автоматический откат. Связь с компьютером не должна зависеть от того, что мы сейчас меняем.

## 5. Честный статус

Приложение и агенты показывают только проверенное состояние. Отсутствие подключения, паузу и ошибку не выдают за успешную работу. Проверка на заглушках не считается проверкой на реальной системе.

## 5а. Явные журналы

Журналы включены всегда и не зависят от компонента, который могут диагностировать: локальный файл пишется без сети, отправка на сервер не использует Syncthing и мост. Секреты в журнал не попадают.

## 6. Подключение остаётся своим

Подключение компьютера к серверу не выдаёт себя за чужой сервис. Основной путь: HTTPS к серверу пользователя под доменом пользователя.

## 6а. Как работают агенты

- Поиск в интернете выполняет субагент, а не Claude. Пока это Codex на `gpt-6.1-sol`; Gemini (`agent:agy`) отложен до отдельной проверки. Вывод проверяется перед использованием.
- Код пишет Codex на `gpt-6.1-sol` с уровнем `high`. Модели Luna не используются.
- Выбор готового компонента делается сравнением по условиям продукта: лёгкий, просто встраивается в `.exe`. То, что компонент уже стоит в проекте, не является аргументом.

## 7. Git

Весь код и документация находятся в Git. Изменение истории, push и видимость репозитория решает владелец.
