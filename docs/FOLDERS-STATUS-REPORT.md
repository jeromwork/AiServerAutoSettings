# Состояния папок, история .stignore и причины ошибок

Дата: 13.11.2026. Ветка: `app/folders-status`.

## Что изменено

### Состояние папок

- `app/launcher/DiskSyncStatus.cs`: чтение локального GUI и API key из `RemoteDisk/state/config.xml`, ID сервера из `server.txt`; один общий снимок для всех выбранных проектов. Общие `/rest/config/folders`, `/rest/system/connections`, `/rest/cluster/pending/folders` запрашиваются по одному разу за цикл; `/rest/db/status` и `/rest/folder/errors` — по одному разу на настроенный выбранный проект, независимо от числа панелей и раскрытых вложенных папок. Идентификация — по пути в локальной конфигурации и конкретному серверу, а не по совпадению имени.
- Чистые `DiskSyncSnapshot.Parse`, `DiskSyncStatus.Text` и `Complete`: `idle` с нулевыми need-счётчиками, без ошибок/паузы, при подключённом сервере; процент `floor(inSyncBytes/globalBytes*100)`, оставшиеся файлы и байты; сканирование; первая ошибка с путём; нет связи; ожидание подключения/серверного предложения; недоступность REST. Для пустой папки нет деления на ноль, отсутствующие need-счётчики не считаются нулём. Давность связи показывается только после реально наблюдавшегося подключения этого сервера.
- `DiskFoldersModel.cs`: presence используется для невыбранных папок и серверного факта. Отметка «применено» больше не подтверждает передачу. Та же функция завершённости считает верхнюю строку `Синхронизировано: N из M папок`; неполный общий список явно обозначен. Полное обновление инвентаризации удаляет устаревшие факты, сохранённый выбор остаётся.
- `DiskFoldersView.cs`: фоновый опрос через 2500 мс, без перекрывающихся циклов и без запуска PowerShell/SSH. Освобождение контрола отменяет запросы, скрытое окно не запускает новые циклы; ответы для прежней модели или выбора отбрасываются. Таймер перерисовывает строки без перестройки дерева и файловых проверок на UI-потоке.
- `DiskFolderTree.cs`: состояние передачи — слева, справа только `Есть на сервере`. Сохранённый выбор виден слева даже до появления каталога. Общая ошибка REST выводится одной строкой; строки выбранных папок в этом случае говорят, что состояние не получено.
- `LocalFolders.cs`, `LocalFolderBrowser.cs`: вкладка «Весь компьютер» использует то же состояние, выбор папки не называется доказанной синхронизацией.
- `ConfigWindow.cs`, `ConfigWindow.Main.cs`: учитывается настроенный `disk.home`; строка «Диск» вверху получает тот же снимок, включая замену старого статуса с префиксом ✅/❌/⏳.

Использованы штатные HTTP/XML API .NET Framework и REST Syncthing. Отдельный клиентский протокол или движок синхронизации не добавлен.

### .stignore

- `disk/stignore.txt`: добавлены три запрошенные строки Laravel.
- `disk/stignore-previous.sha256`: сохранён старый `9c1b…`, добавлены `53ec…` и `9a486…`. Последний также является хэшем получившегося текущего шаблона: `9a486952e5510eaf30e6d95dfe3400fb48a71e1d7d68a0cbccfb539562f6b80c`.
- `Disk.Common.ps1`: общая операция обновления серверного шаблона и union истории под `flock`; сохраняет также хэш заменяемого серверного шаблона. История публикуется атомарно раньше шаблона. На Windows история разных бандлов объединяется в `RemoteDisk/stignore-previous.sha256` под mutex, с атомарной заменой.
- `Install-RemoteDisk.ps1`, `Select-Disk.ps1`, `build/Wizard.Common.ps1`: используют общую операцию вместо перезаписи истории. Проверка помощников мастера сравнивает включение множества хэшей, поэтому накопленная история не вызывает постоянную повторную загрузку.
- `server-disk.sh`: нормализация согласована с Windows (UTF-8 без BOM, CR удаляются, один конечный LF); отказ содержит имя папки. Чужой пользовательский шаблон по-прежнему отвергается.
- `disk/README.md`: описана накопительная история, ручная команда обновления тоже объединяет список.

### Причина ошибки

- `Disk.Common.ps1`: stderr SSH читается как UTF-8; первая содержательная строка серверного отказа сохраняется. Ранний выход SSH не подменяется `Broken pipe` при записи stdin. Произвольный stderr остальных native-команд по-прежнему не попадает в сообщение.
- `Install-RemoteDisk.ps1`, `Select-Disk.ps1`: причина выводится в stderr отдельной строкой без оформления и переноса PowerShell. Безусловный совет проверить SSH убран из ошибки установки.
- `build/Setup.Common.ps1`: удалена повторная обрезка до последних 2048 символов, из-за которой начало причины превращалось в обрывок слова; выбирается первая содержательная строка stderr, stdout служит резервом. Журнал сохраняет ограниченный очищенный вывод обоих потоков. Оформление стека PS 5.1/7 не считается причиной.
- `build/Wizard.ps1`: общий совет про SSH добавляется только при неизвестной причине. Маскирование секретов сохраняется; длинное допустимое имя проекта в нашем отказе `.stignore` не маскируется как токен.

`ConfigApply`/`WizardRunner` и окно уже передают поле `reason`; исправлена потеря причины до формирования этого JSON.

После изменений:

- Обычный `SKIP_LAUNCHER_EXE=1 app/launcher/tests/run.sh` выявил описанную ниже зависимость существующего LAN-теста от прав настоящего `/var/lib/remoteagents`; такой прогон не объявляется зелёным.

Отдельно прошли `disk/test-install.ps1` и `disk/test-tree.py`; модель папок содержит 276 проверок, сценарий stderr — 7 проверок, история шаблонов — 4 интеграционных теста.

Дополнительно весь WinForms-код скомпилирован Roslyn в временную **библиотеку** с reference assemblies .NET Framework 4.8. Приложение EXE не собиралось.

## Ограничения и что не делалось

- В повторном обычном прогоне существующий `test_lan_vpn.SafetyTests.test_timer_failure_prevents_network_mutation` столкнулся с `PermissionError` на настоящем `/var/lib/remoteagents/lan/pending`: тест подменяет `STATE`, но не `PENDING`. На момент повтора `/var/lib/remoteagents` принадлежит root и имеет режим 700; исходный прогон этого теста прошёл. Исходники LAN/VPN и рабочие каталоги не менялись. Для проверки самого теста вне репозитория создана временная фикстура `unittest.mock.patch` для `PENDING` только этого теста; с ней тест проходит. Условия полного повторного прогона указаны выше отдельно.
- Реальные WinForms на «Ноуте» и Windows PowerShell 5.1 не запускались: работа и тестовый исполнитель находятся на Linux. PS-тесты выполнены на PowerShell 7, в том числе с моделированием массивов/вывода PS 5.1 и cp866. Это не выдаётся за проверку на Windows.
- Размер серверной папки инвентаризация не сообщает: справа показывается только подтверждённое наличие, без придуманного размера.
- Готовые старые EXE этой правкой не изменяются. Union выполняют обновлённые пути установки; старый выпущенный установщик, который сам перезаписывает историю/помощники, нужно обновить отдельно. Загрузка/установка на рабочие компьютеры и сервер не выполнялась.
- EXE не собирался и не выкладывался. Транспорт, VPN, мост и Happier не изменены; их штатные проверки запускались только как часть заданного общего набора.
