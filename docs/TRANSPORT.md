# Транспорт RemoteAgents

`transport/Transport.Daemon.ps1` — компонент лаунчера для Windows PowerShell 5.1 и sing-box **1.14.4**. Сам демон не устанавливает задачи планировщика и не меняет системные маршруты. Системный VPN вынесен в отдельный `Vpn.Tun.ps1` и по умолчанию выключен.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Transport.Daemon.ps1 -Home "$env:LOCALAPPDATA\RemoteAgents" -ParentPid 1234
.\Get-TransportStatus.ps1 -Home "$env:LOCALAPPDATA\RemoteAgents"
```

`-ParentPid` — PID лаунчера; без него компонент работает самостоятельно. Для остановки создайте `<Home>\stop` (общий флаг лаунчера) или `<Home>\state\transport.stop`. Флаг сохраняется: удалите перед следующим запуском. При остановке/закрытии родителя завершаются sing-box и SSH; на Windows дерево SSH закрывается через `taskkill /T`. Один Home допускает один экземпляр. Ошибка запуска возвращает код 1.


## Старая установка, занятые порты и чтение статуса

Старую установку владелец удаляет вручную через `tools/legacy-cleanup/Remove-OldInstall.cmd`
перед повторной установкой. Приложение не отключает старые задачи, процессы и автозапуск.
Ручной откат — `Restore-OldInstall.cmd` из инструмента очистки.

Перед каждым запуском sing-box, после остановки прежнего процесса и SSH-туннелей,
транспорт выбирает свободные локальные порты. Сначала проверяет настроенные значения,
затем одиночные порты с шагом 10, а блоки проб и SOCKS — целиком с шагом,
округлённым вверх до 100. После 200 попыток начало свободного блока выбирает ОС.
При следующем запуске свободное настроенное значение снова имеет приоритет.
Проверяются и слушатели в снимке Windows, и реальное исключительное занятие адреса.
Между проверкой и запуском возможна гонка: при ошибке bind демон повторяет выбор.
Если порт удалось заменить, перезапуск идёт с обычной короткой задержкой.
Если выбор остался прежним, повтор одной ошибки bind увеличивает паузу: 5, 10, 20,
30 секунд (с учётом `restartDelaySec`, максимум 30 с). Во время этой паузы статус
обновляется раз в пять секунд; `retryAt` показывает время следующей попытки.

### Запуск при Happ и без физического интерфейса

Событие `process-failed` при `engine-start-failed` содержит `error=<текст>`: сообщение исключения одной
строкой, не длиннее 300 символов; UUID, токены, ключи и пароли заменены (`<uuid>`, `<secret>`, `<redacted>`).
Тот же текст попадает в `error` статуса.

Паузы между неудачными запусками движка (не bind-конфликт): 3, 5, 10, 20, 30 с; после `ready` серия
сбрасывается. Перед каждой повторной попыткой сеть определяется заново (`Get-TransportNetwork`), а не ждёт
5-секундной проверки смены сети.

`Get-TransportNetwork`: сосед шлюза не обязателен (нет записи ARP, Stale/Probe/Delay), профиль сети тоже.
Без MAC `id` считается по `ifIndex + NextHop + имя профиля (или адаптера)`. Адаптер выбирается среди физических
(`-Physical`, `HardwareInterface`, не Tailscale/Happ/Wintun/TAP) по default-маршруту с NextHop на нём; чужой
default (например `happ-xray`, метрика 0) выбор не сбивает. Смена default route (Wi-Fi -> Ethernet)
меняет `interface/ip/id`, и движок пересоздаётся с новой привязкой.

Резервный режим без привязки: если физический интерфейс не найден 3 раза подряд **и** `status\vpn.json`
содержит `state=off`, движок стартует без `bind_interface`/`auto_detect_interface` (и без `-b` у OpenSSH);
в журнале `bind-mode bind=none reason=no-physical-interface`. Трафик к relay идёт по маршрутам ОС (через Happ).
Раз в 60 с (и при смене сети) повторяется привязка; при успехе движок пересоздаётся и пишется
`bind-mode bind=physical restored`. Если `vpn.json` отсутствует или `state` не `off`, режим запрещён
(иначе петля через свой TUN), запуск ждёт интерфейса как раньше.

`<Home>\state\transport-ports.json` хранит `schema:1`, `configured`, `effective`,
`moved` и `updatedAt`. Поле `defaults` хранит значения по умолчанию из общего кода для
сверки в лаунчере, без второй копии чисел в C#.
Файл закрыт правами текущего пользователя и заменяется атомарно. Выбор не пишется
в `config.json` и не вызывает reload. Все потребители читают эффективные значения
через общий код; если настроенные значения изменились, старое состояние игнорируется.
В `status/transport.json.ports` публикуются значения текущего запуска; открытый порт
сам по себе не означает связь: для `ok=true` по-прежнему нужна успешная проба пути.
Монитор диска обновляет локальный адрес устройства сервера Syncthing при смене файла
портов и раз в 30 секунд. При недоступном REST он пишет в журнал и повторяет попытку.

Событие `port-moved` в `logs/transport.log` объясняет выбор: «Порт 2222 занят другой
программой (C:\...\app.exe, PID 42) — использую 2232». Путь и PID указываются, если
Windows их предоставила. Диагностика ошибки bind сообщает «Порт 127.0.0.1:N занят
другой программой <путь> (PID n)». Для старого sing-box из
`%LOCALAPPDATA%\RemoteDisk\channel\` или процесса задачи `RemoteDiskChannel`
добавляется инструкция ручной очистки; чужие процессы автоматически не завершаются.

В режиме `channelFirst` вход SSH сохраняет **серверный** SSH-порт на отдельном адресе
loopback: сначала настроенный адрес, затем `127.0.0.2`, `127.0.0.3` и далее до `.254`.
`127.0.0.1` для него не выбирается. При смене адреса транспорт атомарно заменяет только
точный старый `HostName` в `configPath` профиля и `HostName=<старый>` в сохранённых
аргументах; событие `channel-address-moved` записывается в журнал. Если серверный порт
занят на всех адресах (`0.0.0.0` или `::`), смена loopback-адреса невозможна: статус
сообщает ошибку, связь не объявляется рабочей.

`Read-TransportJson` и читатель JSON лаунчера открывают файл с `FileShare.ReadWrite | Delete`,
повторяют нарушения общего доступа/блокировки и пустые/пробельные снимки в одном лимите до секунды.
После лимита пустой снимок даёт ошибку чтения. Писатель сначала закрывает
полностью записанный временный файл, затем делает `File.Replace`/`Move` в том же каталоге:
читатель видит целый старый или новый снимок. Повреждённый JSON и прочие ошибки не скрываются.

Проверки без настоящего Windows: `transport/test-transport-json.ps1`,
`transport/test-transport-ports.ps1` (адаптеры),
`transport/test-transport-daemon.py` (bind, пауза, восстановление на имитаторе).
Они входят в `app/launcher/tests/run.sh`. Реальную блокировку Windows дополнительно проверяет
ветка JSON-теста под Windows PowerShell 5.1; прогон на Linux её не подтверждает.

## Постоянный вход Happier

`profile.happier.localWeb` из вставленного конфига (для прежней/ручной установки —
`config.happier.localWeb`) задаёт `{enabled: true, port: 47831, serverPort: 47831}`.
Приоритет у `profile`, включая явное `enabled: false`; без поля вход выключен.
Это настройка компьютера вне секции `transport`; её схема — `$defs.localWeb` в
[`transport/config.schema.json`](../transport/config.schema.json), на неё ссылается схема рабочего конфига.
Поля `enabled`, `port`, `serverPort` обязательны, порты — целые 1024–65535; неизвестные поля отклоняются.

`Resolve-TransportPorts` резервирует фиксированный `127.0.0.1:<port>` **перед** SSH,
Syncthing, API, блоками проб и SOCKS, даже если он занят. Остальные входы при пересечении
перемещаются обычным способом. Сам порт Happier не перевыбирается и не входит в список `moved`.
Если его нельзя занять, вход `happier-web` не включается в sing-box, остальные входы работают;
`status/transport.json.localWeb.conflict`, `summary`, `Get-TransportStatus.ps1` и событие
`happier-port-conflict` журнала называют адрес/порт и, если доступны, PID/путь владельца.
После освобождения порта при следующем запуске/перезапуске вход возвращается на тот же адрес.
Гонка bind обрабатывается штатным перезапуском и повторной проверкой портов.

Вход — TCP direct `127.0.0.1:<port>` с назначением `127.0.0.1:<serverPort>` и правилом
на selector `active`, как SSH/Syncthing. Он действует для всех кандидатов, в том числе
OpenSSH напрямую, через jump/proxy: у них общий SOCKS `ssh -D`, дополнительных `-L` нет.
Изменение `localWeb` входит в ревизию канала и запускает штатную проверку/reload конфига.
`localWeb.available` в статусе означает результат проверки bind, а не здоровье веб-службы;
перед открытием браузера лаунчер отдельно проверяет HTTP health.

## Настройки и пути

Настройки — секция `transport` в `<Home>\config.json`. [Пример](../transport/config.example.json) содержит вымышленные значения; [схема](../transport/config.schema.json) описывает именно значение секции, её нужно включить в общую схему лаунчера. Версию всего `config.json` задаёт лаунчер. Home по умолчанию — `%LOCALAPPDATA%\RemoteAgents`.

| Параметр | По умолчанию / назначение |
|---|---|
| `profilePath` | SSH-профиль `ssh-transport.json`, созданный мастером; обязателен |
| `channelPath` | config канала, полученный мастером с сервера (`state/wizard-channel-*.json`): оттуда VLESS и **порт назначения** входа `sync`; обязателен |
| `singBoxPath` | `sing-box.exe` рядом со скриптом |
| `sshPort`, `syncPort` | Предпочтительно 2222, 22001; при занятости выбираются свободные. Только loopback; назначения — SSH-порт сервера и порт Syncthing из канала |
| `channelSocksPort`, `channelSshAddress` | Предпочтительно 2223 и `127.0.0.2`; входы режима `channelFirst`, при занятости заменяются |
| `probePortBase`, `socksPortBase`, `apiPort` | Предпочтительно 26000, 28000, 29090; блоки и API автоматически выбираются без пересечений |
| `bindPhysical` | `true`: auto_detect_interface и привязка внешних сокетов sing-box к физическому NIC; `ssh -D` напрямую получает `-b` IPv4 этого NIC. `false` разрешает системную маршрутизацию |
| `openSsh` | `true`: добавить OpenSSH напрямую и через SSH-переходы, используя локальные SOCKS-входы `ssh -D` |
| `metered` | `auto`, `true`, `false` (строки или boolean для последних двух); явное значение переопределяет Windows |
| `switch.stallSeconds`, `switch.stallConns` | Целые 1..3600 и 1..1024, по умолчанию 8/2: 8 секунд без download при растущем upload минимум у двух соединений одного пути; только подозрение, требующее подтверждения |
| `stallSeconds`, `probeTimeoutSec` | 5 секунд без новых байтов после первого; общий срок пробы 45 секунд |
| `restartDelaySec` | 3 секунды перед повторным запуском упавшего процесса |
| `entries[]` | `{name, ssh, enabled?, kinds?, configPath?}`: имя узла, SSH-алиас или host, по умолчанию enabled=true и все kinds |
| `relays[]` | `{name, host, port, enabled?}`: TCP-ретранслятор до VLESS сервера без расшифровки |
| `hops[]` | `{name, ssh, enabled?, configPath?, hostKey?}`: SSH-переход. `hostKey` — массив полных публичных OpenSSH host keys |
| `cdn[]` | `{name, domain, path?, entry, enabled?}`: VLESS-WS через домен любого CDN; uuid и путь по умолчанию из кэша entry |
| `disabledTags[]` | Отключённые отдельные tag, независимо от enabled узла |

Профиль должен содержать `sshExecutable`, `serverAddress`, `login`, `keyPath`, `knownHostsPath`; порт прямого SSH берётся из `arguments` (`-p`, иначе 22). Пользователь — рабочий, не root. Для native SSH sing-box ключ хоста извлекается через соседний `ssh-keygen.exe -F` из known_hosts профиля, включая hashed-записи. Для SSH-узла (hop) используются known_hosts из `ssh -G` либо явный `hostKey`. Новые ключи автоматически не принимаются. Зашифрованные приватные ключи, требующие интерактивного ввода, нужно предварительно подготовить для фонового запуска.

Доступны VLESS напрямую, через relay/SSH-переход, native SSH sing-box, OpenSSH напрямую/через переход, Hysteria2, Hysteria2+salamander, TUIC, Trojan, Reality, ShadowTLS+Shadowsocks, VLESS-WS напрямую и через CDN. Формирование узлов повторяет рабочий `Test-Transports.ps1`; CDN-кандидат добавляется при наличии `domain`, без предварительного DNS-запроса. Для собственного сертификата узла сохранён флаг `insecure` из формата установщика; WS напрямую повторяет режим тестера (`insecure=true`). На переходах OpenSSH внешний сокет создаёт SSH из ProxyCommand: его маршрут задаётся SSH-конфигурацией/системой; `-b` применяется к прямому OpenSSH.

## Проверки и переключение

Один конфиг `<Home>\state\transport-sing-box.json`: рабочие входы ведут в selector `active`, отдельные `effective.probePortBase+i` ведут каждый в своего кандидата, всегда на SSH сервера. Управление — локальный Clash API с Bearer-секретом из `state\transport-secret.json`; `PUT /proxies/active` переключает selector с `interrupt_exist_connections=false`. Обычное переключение не перезапускает sing-box и сохраняет существующие пользовательские соединения. Упавший sing-box перезапускается. При смене физического NIC/IP с `bindPhysical=true` процесс пересоздаётся для обновления привязки сокетов; старые соединения могут оборваться. Без доступного физического NIC в этом режиме запуск ожидает восстановления сети.

`Transport.Events.ps1` пассивно читает WebSocket Clash API `/logs?level=warn` и
`/connections?interval=1000`. У sing-box установлен `log.level=warn`. Читатель отдаёт
нормализованные `dial-fail`, `conn-closed-error`, `stall-suspect`; демон добавляет
`engine-exit` при завершении sing-box или OpenSSH. Очередь разбирается в такте 300 мс.
Потеря подписки сама по себе не означает отказ пути. Нетегированное закрытие соединения
относится к активному пути только если в текущем процессе движка использовался один
активный путь и событие пришло во время его работы. После переключения старые соединения
могут жить, поэтому неоднозначные закрытия не штрафуют ни один путь.

`Transport.Decide.ps1` — чистый решатель: получает события, состояние, кандидатов и время,
возвращает решение; сеть и процессы запускает только демон. Текущий путь остаётся выбранным
до подтверждённой неудачи. Кандидаты выбираются по здоровью, задержке, провалам и разбросу;
автоматического рейтинга скорости и планового поиска «более быстрого» пути больше нет.
Память по физической сети и метрики первичного выбора сохранены. Старые ключи расписания и объёма проб принимаются схемой с deprecated и игнорируются; объём всех SSH-проб фиксирован: 65536 байт.

| Повод | Проверка / полезные данные |
|---|---|
| Старт движка, смена сети, явный pin/auto | Один параллельный раунд живости: до 64 КиБ на доступного кандидата; в pinned только закреплённый |
| `dial-fail`, ошибка закрытия без локального признака | Ворота: SSH-баннер через probe-вход, до 6 с, не более двух проверок одновременно. Успех даёт пути окно 30 с без повторных ворот; отказ передаётся решателю, который запрашивает прямой TCP connect без данных на 1.1.1.1:443 и 8.8.8.8:443 (до 3 с, достаточно одного успеха) |
| `engine-exit`, `path-check/process-exited` | Событие сразу передаётся решателю: завершение процесса подтверждает отказ; при localNet=down штрафов нет |
| `stall-suspect` | Одна SSH-проба ровно 64 КиБ через `probe-<tag>`; дедлайн 12 с |
| Подтверждённая неудача активного пути | Один раунд живости по всем включённым путям (кроме уже проверяемых), не чаще раза в 60 с и никогда при localNet=down; только при switch на неподтверждённый путь или searching с причиной path-* |
| Окончание штрафа при отсутствии живого пути | Решатель выбирает доступный путь или запрашивает одну проверку для восстановления |
| Работа без событий | Сетевых проб нет; остаются пассивные подписки и локальное обслуживание процессов/конфига |

SSH-пробы используют `ssh.exe` профиля, закреплённые host keys, `HostKeyAlias=serverAddress`,
`ProxyCommand=none`, `head -c 65536 /dev/urandom`. Содержимое не сохраняется: .NET Stream
считает только байты и время. `kbps` — КиБ/с по времени от начала пробы; это метрика
разрешённой проверки, без отдельного фонового замера скорости. Первичный выбор не ждёт
таймаута молчащих соседей. После окончания раунда повторов по расписанию нет.

`stall-suspect` требует непрерывного роста upload без download у `switch.stallConns`
соединений на одном пути в течение `switch.stallSeconds`. Успешное подтверждение снимает
подозрение на 60 с. stalled/timeout подтверждения дополнительно проверяются прямым TCP.
Каждый запрос имеет билет с дедлайном в демоне: отсутствие ответа, потеря handle или
исключение дают `net-down/code=timeout` либо `path-check/code=timeout`. При смене поколения
при reload, смене сети, пина и остановке результаты проверок выбрасываются. Создаётся новое состояние решателя с сохранением только истории переключений и lastSwitchAt. При падении движка path-проверки отменяются событием cancelled без штрафа, прямая проверка продолжается.
Читатель пересоздаётся при reload, смене сети и перезапуске движка; активные теги и пороги
передаются заново. Прямая проверка получает физические IPv4 и ifIndex, чтобы обходить TUN.

Локальный признак ошибки или `net-down` переводит в `searching/local-network-down`,
без переключения и новых штрафов. Штрафы за последние 45 с или незавершённый более длинный
раунд откатываются. Новые события трафика проходят ворота; успешная разрешённая проверка пути
или смена физической сети возвращает связь. Фонового опроса интернета нет.

Подтверждённый отказ даёт паузу пути 5, 15, 45, 120, 300 с (далее 300 с), успех её сбрасывает.
Несколько ошибок до подтверждения дают один штраф; события в окне 500 мс объединяются.
Автоматические переключения происходят не чаще одного раза за 10 с, включая первичный выбор
и восстановление после перезапуска. Если все пути на паузе, демон остаётся в `searching`
до ближайшего разрешённого выбора. Транспорт не отдаёт команду выключить VPN.

`status\transport.json` заменяется атомарно раз в секунду и сохраняет прежние поля.
Добавлены `phase=searching`, `reason:{code,text,since}` (since — ISO UTC),
`localNet:ok|down|unknown`, `switches:[{at,from,to,why}]` (последние 10 фактических
переключений, at — ISO UTC), `candidates[].penaltyStep` (0..5) и `penaltyUntil` (ISO UTC/null).
Русский `reason.text` берётся из общей таблицы решателя; при code=ok текст пуст. Ворота сами не меняют phase; ожидание решателем проверки активного подтверждённого пути даёт degraded. Ожидание поиска не является
выключением VPN. Отключённые кандидаты остаются `enabled=false,state=disabled`, не
участвуют в проверках или selector. `Get-TransportStatus.ps1` считает запись старше 15 с устаревшей.

Журнал `logs\transport.log` локальный, ротируется при 2 МиБ (архивы `.1…5`), формат — в [LOGS.md](LOGS.md); `vpn.log` больше не пишется (события VPN идут в `transport.log`).
Диагностика процессов сохраняет очищенную категорию и stderr; детали событий не копируются
в статус. Секрет, конфиг движка и другие приватные файлы закрыты ACL текущего пользователя.
Старые настройки интервалов и рейтинга удалены из схемы и runtime-опций; в старом JSON
они игнорируются. `metered` остаётся информацией о сети и больше не запускает пробы.

## Трафик

Плановых загрузок 64/256 КиБ больше нет. В простое работают только две локальные
WebSocket-подписки; дополнительный внешний трафик возникает при старте, явных действиях,
смене сети и событиях отказа согласно таблице. Неуспешная проба может скачать часть объёма.

## Добавить узел

1. На своём узле подготовьте upstream сервера и выполните `transport/entry/install-entry.sh` по инструкции установщика. Узел должен иметь рабочий `/opt/rd-entry/client.json` и SSH-алиас на Windows; host key предварительно проверяется пользователем.
2. Добавьте `{ "name": "edge", "ssh": "entry-example", "enabled": true }` в `transport.entries` либо выполните `Edit-Transport.ps1 -AddEntry edge -Ssh entry-example`. Имена — буквы, цифры, `_`, `-`; адреса и пароли не помещаются в имя.
3. Запустите `.\Update-Entries.ps1 -Home ...`. Скрипт получает только `cat /opt/rd-entry/client.json`, нормализует CRLF, сохраняет `secrets\entries\edge.json` с ACL только текущему пользователю. Содержимое не печатается. Для полной валидации используйте тестер/демон; неудачная загрузка не заменяет старый кэш.
4. Проверьте статус: демон обнаруживает изменение локального конфига/кэша без перезапуска лаунчера. Для нового включённого entry без кэша фоновая подготовка сама получает `client.json` по проверенному SSH. Существующий кэш обновляется только явной `Update-Entries.ps1`; новые host keys автоматически не принимаются.

## Проверки разработки

```powershell
.\transport\test-transport-config.ps1 -SingBox C:\tools\sing-box.exe
```

Тест работает в Windows PowerShell 5.1 и pwsh, использует фиктивный client.json, CRLF, синтетические потоки и временный SSH-ключ. Без sing-box проверяется структура; с `-SingBox` дополнительно проверяются настоящий `sing-box check` и локальный Clash API (без открытия внешних путей). Для этой проверки нужен `ssh-keygen` из OpenSSH. `-OutputConfig` сохраняет тестовый JSON для внешней проверки (ссылки на временные файлы ключей после теста уже не действуют).

Дополнительно на Linux: `python3 transport/test-transport-daemon.py /path/to/pwsh`. Это локальный стенд с имитаторами SSH/sing-box и loopback API: проверяет отсутствие планового трафика счётчиками, локальный обрыв без штрафов, подтверждение stall 64 КиБ, ограничение переключений 10 с, потерянные ответы и исключения проверок, pin/reload, перезапуск движка, stop и ParentPid с завершением дочерних процессов. Для повторной проверки только жизненного цикла есть флаг `--lifecycle-only`; `--decision-only` проверяет подтверждение selector, восстановление закреплённого пути после паузы и начало cooldown без сетевого ввода-вывода. Наборы `test-transport-liveness.py`, `test-transport-decide.ps1`, `test-transport-events.py`, `test-transport-config.ps1` и `test-transport-json.ps1` проверяют остальные стороны контракта отдельно. Он не подтверждает работу протоколов, Windows ACL/WinRT/NetTCPIP и реальной сети. Приёмка на настоящей Windows PowerShell 5.1 и проверка всех путей рабочим тестером остаются обязательными перед внедрением.


## Ручной выбор и изменение списков

```powershell
.\transport\Set-TransportPath.ps1 -Home $root -Auto
.\transport\Set-TransportPath.ps1 -Home $root -Tag ws-direct-edge
.\transport\Edit-Transport.ps1 -Home $root -List
.\transport\Edit-Transport.ps1 -Home $root -AddEntry ru-in -Ssh my-ru-vps -Kinds ws-direct,trojan
.\transport\Edit-Transport.ps1 -Home $root -AddRelay relay-two -Host 203.0.113.40 -Port 8443
.\transport\Edit-Transport.ps1 -Home $root -AddHop jump-two -Ssh my-jump
.\transport\Edit-Transport.ps1 -Home $root -AddCdn my-cdn -Domain cdn.example.com -Entry ru-in -Path /my-ws
.\transport\Edit-Transport.ps1 -Home $root -Disable ru-in
.\transport\Edit-Transport.ps1 -Home $root -Disable vless-direct
.\transport\Edit-Transport.ps1 -Home $root -Enable vless-direct
.\transport\Edit-Transport.ps1 -Home $root -Remove my-cdn
```

`$root` здесь — каталог Home установки. Команды возвращают JSON и ненулевой код при ошибке. `-List` выводит секцию transport; интерфейс списка **состояний путей** — `status/transport.json`. Все изменения JSON атомарны, edit-команды используют общую межпроцессную блокировку и сохраняют соседние поля конфига. Имена узлов уникальны во всех четырёх списках; `Enable/Disable` сначала ищет имя, иначе считает аргумент tag. CDN, ссылающийся на entry, нужно удалить раньше entry. Для совместимости с задачей A читаются также `alias` вместо `ssh` и `server` вместо `host`.

Допустимые `entries.kinds`: `hy2`, `hy2obfs`, `tuic`, `trojan`, `reality`, `shadowtls`, `ws-direct`, `ws-cdn`. Отсутствие или пустой массив означает все доступные типы. WS возможен только если client.json содержит WS-секреты. `cdn[].entry` выбирает кэш с uuid/путём; домен, SNI и Host берутся из `domain`, path можно переопределить. Приложение не настраивает CDN у провайдера: пользователь должен направить домен на нужный entry, включить WebSocket и подготовить сертификат. Отключённый entry может оставаться источником секретов для отдельно включённого CDN.

Pin хранится отдельно в `state/transport-pin.json`: `{ "mode": "auto", "tag": null }` либо `{ "mode": "pinned", "tag": "ws-direct-edge" }`. При работающем движке демон читает файл раз в секунду и применяет выбор через Clash API за ≤5 секунд после записи. Асинхронные проверки пути и подготовка новой конфигурации не блокируют этот цикл. При недоступном API статус сообщает ошибку и команда переключения повторяется; применить selector остановленного/недоступного движка невозможно. Pin сохраняется при смене сети и перезапуске.

В pinned решатель проверяет только закреплённый путь и не меняет выбор. Мёртвый pin даёт `ok=false, phase=searching` и причину ожидания. Отключённый/удалённый tag остаётся `active/pinnedTag`, а selector направляется в локальный недоступный SOCKS `unavailable` (127.0.0.1:1); сетевого fallback нет. Из-за `interrupt_exist_connections=false` уже существующие соединения прежнего пути могут жить до естественного завершения. Вернуться к автоматическому выбору можно только через `-Auto`.

Изменения config.json.transport, профиля/канала и кэшей обнаруживаются по содержимому. Подготовка кандидатов и `sing-box check` идут в фоновом PowerShell job. Невалидная подготовка сохраняет прежний работающий процесс и публикует `configError`; повтор — через 30 секунд. После успешной проверки останавливаются транспортный sing-box и его OpenSSH -D, затем заново выбираются свободные порты и проверяется итоговый конфиг. Входы SSH/Syncthing слушают эффективные порты из `state/transport-ports.json`; они могут отличаться от настроенных. При этом TCP-сессии самого sing-box могут оборваться: sing-box 1.14 не умеет заменять весь набор listeners/outbounds через selector API. Лаунчер, диск и мост не перезапускаются. Применение только `vpn.enabled` транспорт не перезапускает.

Локальные `sshPort`, `syncPort`, `channelSocksPort`, `apiPort`, `probePortBase` и
`socksPortBase` не входят в серверный контракт. `disk/server-disk.sh channel()` ещё
выдаёт старые клиентские входы 2222/22001 для совместимости с RemoteDisk; новый
транспорт берёт из входа `sync` только `override_port` — порт Syncthing на сервере.
Порт сервера из SSH-профиля и этот `override_port` при выборе локальных портов
не меняются. Обратные туннели моста используют собственные параметры и от этих
локальных входов не зависят.

## Интерфейс для лаунчера

- Запуск транспорта: `Transport.Daemon.ps1 -Home <Home> -ParentPid <launcherPID>` как обычный пользователь. Статусы читать раз в секунду, запись старше 15 секунд считать устаревшей. `ok=false` и `error/configError` отображать явно.
- В меню путей показывать `title`, `kind`, `via`, `enabled`, `state`, `kbps` (**КиБ/с**) и `checkedAt` (UTC ISO 8601, null = не проверен). Текущий tag — `active`; галочка «Автовыбор» определяется `mode`, закреплённая строка — `pinnedTag`. Tag — стабильный идентификатор для команды, не подпись для человека. Не считать remembered подтверждённым подключением.
- Выбор пути: запуск `Set-TransportPath.ps1 -Auto` или `-Tag <tag>`, затем ждать статус. JSON команды подтверждает запись запроса, не успешность соединения. Отключённые строки не предлагать для выбора; уже закреплённую отключённую/удалённую строку показать с ошибкой.
- Добавить/удалить/включить/выключить узел либо tag: вызывать Edit-Transport с параметрами из примеров; не переписывать весь config из устаревшей копии. `-List` даёт настройки, status даёт проверенные состояния. Ошибка нового config появляется в `configError`, старый транспорт продолжает работать до успешного reload.
- «Включить системный VPN»: сначала Test-VpnConflict. При conflict рисовать окно с items и действиями «Отключу другой VPN самостоятельно» / «Оставить другой VPN, наш не включать». Приложение не завершает чужие процессы. После устранения вызвать `Vpn.Tun.ps1 -Enable -ParentPid <launcherPID>`; компонент повторит проверку и попросит UAC. Сам лаунчер остаётся без повышения прав. Не запускать worker напрямую и не включать VPN автоматически после перезапуска Windows.
- «Выключить системный VPN»: `Vpn.Tun.ps1 -Disable`. Ждать `off/rolled-back`; `stopping` означает запрос, а `error/rollback-error` — проблему. `enabled=true` без свежего `ok=true, state=on` не считать проверенным VPN. Пока идут UAC/starting, показать ожидание, а не зелёный статус. При отмене UAC/ошибке предложить повторное явное включение.
- Для статуса VPN не требуется постоянно держать ещё один непривилегированный daemon: worker живёт в своей одноразовой задаче и следует ParentPid/config/stop. Лаунчер читает vpn.json и вызывает команды по действиям пользователя. При выходе лаунчера worker видит завершение PID и выключает TUN. На старте создайте `off` через вызов Vpn.Tun без ключей, если файла ещё нет; старую запись `on` со старым updatedAt показывайте как устаревшую.

## Результаты разработки задачи C

Скрипты с Unicode сохранены в UTF-8 BOM; чистый ASCII также совместим с PowerShell 5.1. Скрипты используют синтаксис PowerShell 5.1. Расширенный `test-transport-config.ps1` проверяет CRLF, pin/auto, реальные edit-команды, metadata/disabledTags/kinds/CDN, конфликты на фиктивном инвентаре, исключения и запрет SSH в TUN, выбор маршрута пробы, построение watchdog на пять минут и идентификацию своего PID, UTC в PS 5.1/7 и очистку маршрутов только своего GUID. С `-SingBox` выполняется `check` обычного транспорта и каждого из десяти поддерживаемых TUN-кандидатов. Ни один TUN в тестах не запускается. Локальный Python-стенд дополнительно проверяет pin за ≤5 секунд после записи, удержание мёртвого pin, возврат в auto, hot reload с повторным выбором свободных портов и сохранение рабочего процесса при невалидном config.

Фактический прогон: Linux, pwsh **7.4.13**, sing-box **1.14.4** — **212 проверок без сети**, отдельный Python-стенд завершился `OK`; обе JSON-схемы и config.example.json прошли jsonschema Draft 2020-12. Это не приёмка Windows PowerShell 5.1. Живые TUN, UAC, ScheduledTasks, Wintun/DNS/маршруты Windows, административные ACL, реальный конфликт с другим VPN, серверный internet egress и UDP пока **не проверены**. До отдельной приёмки включение TUN на компьютере с рабочими MCP-сессиями запрещено решениями владельца.


## Интерфейс статуса

`status/transport.json.summary` всегда содержит проверенный путь и измеренную скорость либо
«нет связи: <причина>». `kbps=null` не превращается в ноль. При смене адреса входа канала демон обновляет точные ссылки на него в SSH-профиле.
Автозапуск и задачи он не меняет. entries/relays/hops/cdn по умолчанию пустые. Прямые SSH и пробы транспорта используют
-F NUL и явный HostKeyAlias.

Ревью F: управляющий цикл демона ждёт 300 мс; счётчик байтов и требование pin ≤5 с
сохранены; плановые пробы удалены. Журнал транспорта записывает только фиксированные коды событий: текст исключений может
содержать короткий пароль, который нельзя надёжно замаскировать регулярным выражением. Пробы и
OpenSSH используют внутренние кавычки в UserKnownHostsFile для путей с пробелами. Стенд демона
дополнительно проверяет завершение всех SSH-проб после stop и смерти родителя. CPU на Windows
после изменения интервала ещё не измерен.

`Test-Transports.ps1` читает пути из `config.json` Home приложения и не содержит личных маршрутов по умолчанию; его временный каталог и
конфиг закрыты ACL, журнал движка отключён, сырой stderr в отчёт не попадает, запуск/остановка общие
с демоном. `Update-Entries.ps1` скрывает текст исключения JSON. `test-diagnostics.py` проверяет это
на локальных имитаторах. Серверные `entry/*.sh` остаются только в исходниках: они меняют ufw/nginx/
systemd без независимого автоматического отката и не включаются в Windows-бандл до отдельной
серверной доработки и приёмки. Windows-приложение их не вызывает.

## Предварительная проба и диагностика

Мастер проверяет новую конфигурацию на временных портах (`Invoke-TransportPreflight` в
`build/Setup.Common.ps1`, Home `state/transport-probe`): пробы по 64 КиБ
с параллелизмом 4. Производственные параметры пользователя остаются прежними. Успех требует
проверенного активного пути и SSH true на временном входе; до этого рабочая связь не меняется.

stderr читается асинхронно в ограниченный буфер (первая строка до 2 КиБ и последние 8 КиБ), без
сырых файлов. Известные значения секретов, включая короткие пароли, удаляются до записи;
дополнительно маскируются UUID, токены и авторизация в URL. sing-box пишет предупреждения и ошибки (warn).
`status/transport.json` содержит `candidates[].diagnostic` с candidate/reason/exitCode/stderr и,
при наличии, engineStderr. Таймаут живого процесса имеет exitCode=null: код не придумывается.
При отказе preflight `logs/setup.log` получает `preflight.candidate` по каждому пути, включая
непроверенные; понятная причина возвращается в окно мастера.

`server_node_catalog.py` — каталог Windows executor/project bindings (hostId, projectId, socketPath),
без адресов, протоколов и клиентских секретов транспортных входов. `Update-Entries.ps1` умеет забрать
client.json только для уже заданного SSH-узла.

## Класс сети и качество (Q)

`NetClassPublisher` в лаунчере реагирует на `win.iface.changed`, `win.route.changed`,
`win.addr.changed`, `net.change` и готовность нового демона. Он публикует
`net.change {id, class, ifIndex, classifier:q}` без опроса по таймеру. Профиль WinRT
сопоставляется с физическим адаптером default-маршрута по GUID: WWAN → `mobile`,
Wi-Fi с Fixed/Variable, metered, roaming или лимитом → `mobile-hotspot`, прочий
Wi-Fi → `wifi`, Ethernet → `fixed`. При недоступном адаптере класс `unknown` и
коэффициент 1. Полученный извне `net.change.id` сохраняется при обогащении класса.
Исходный id лаунчера — SHA256 от GUID адаптера, шлюзов и имени профиля, без публикации SSID.
WinRT читается только при событиях; недоступность API оставляет классификацию по типу адаптера.

Политика в `config.json.transport.switch` (при вставленном профиле приоритет у
`config.json.profile.transport.switch`), в экспортируемом конфиге — `transport.switch`:

```json
{"transport":{"switch":{
  "blipMs":{"default":10000,"min":3000,"max":30000},
  "hardFailMs":{"default":3000,"min":1000,"max":10000},
  "stageMs":[1000,3000],
  "classK":{"fixed":0.5,"wifi":0.8,"mobile-hotspot":1.3,"mobile":1.5},
  "minStayMs":30000,"flapWindowMs":600000,"flapSwitches":3,
  "probeBudgetKiBPer10m":{"default":512,"mobile":192},"tspuMemoryHours":24
}}}
```

Без `switch` берутся эти значения. Частичный объект дополняется ими; `min <= default <= max`,
две возрастающие ступени не выше `blipMs.default`. Старые `stallSeconds` / `stallConns`
остаются совместимыми. Настройки выдачи `server/remoteagents_config.py` принимают
такую же секцию `transport`, экспорт и config-sync выдают нормализованную политику.
Публичный профиль допускает только `switch`, без путей к исполняемым файлам.

`Transport.Quality.ps1` — событийный модуль для демона: сам он не создаёт трафик,
таймеры или потоки. Все функции получают `Now` (Unix ms) от вызывающего кода.
`Update-TransportQuality` публикует `net.quality` через переданный callback после
нового факта; результаты старой сети и повторы `eventId` игнорируются.

Контракт подключения для T0/T1 (Q не изменяет `Transport.Daemon.ps1` и `Transport.Decide.ps1`):

1. Dot-source `Transport.Quality.ps1`; создать `New-TransportQualityState $config`.
   После `Read-TransportMemory` вызвать `Import-TransportQualityMemory $q $memory.networks $now`.
2. Передать `Update-TransportQuality $q 'net.change' $fields $now $publish`, где
   `$publish` принимает `(topic, fields)` и отправляет их существующим мостом шины.
   Использовать **тот же** id в поколении проб, памяти и последующих событиях.
3. Новые факты передавать как `light-probe {id,eventId,tag,probeId,ok,ms}`,
   `probe64 {id,eventId,tag,probeId,ok,ms}`, `episode {id,eventId}`,
   `switch {id,eventId}` и `stall-suspect {id,eventId}`. `ok` — boolean;
   `probeId` связывает успешный баннер с последующей пробой 64 КиБ ровно один раз,
   `eventId` уникален для результата (для эпизода — идентификатор эпизода).
   Прерванную пробу при смене поколения не передавать как отказ.
4. В начале эпизода взять снимок `net.quality` / `Get-TransportQualitySnapshot`,
   сохранить `blipMs`, `hardFailMs`, `stage1Ms`, `stage2Ms` до следующего эпизода.
   `minStayMs` и параметры антикачелей брать из `$q.config`. Текущий эпизод
   не пересчитывает пороги после каждой пробы.
5. Упорядоченные, доступные и неоштрафованные кандидаты передать в
   `Get-TransportQualityRound $q $candidates $active $now`. Он сохраняет порядок
   внутри групп, опускает ТСПУ вниз, задаёт `maxParallel=4`. При исчерпанном бюджете
   оставляет активного и двух лучших, отключает 64 КиБ и возвращает текст статуса.
   Перед каждой пробой вызвать `Request-TransportQualityProbe` с purpose `light`
   или `post-switch-verify`: false запрещает старт. Лимиты на эпизод — три лёгких
   активному, одна остальным, одна 64 КиБ одному пути. Резервируется 1 КиБ за
   лёгкую и 64 КиБ за полную пробу; уже идущую плановую живость / превышение
   резерва учитывать событием `traffic {id,eventId,bytes}` (не считать резерв дважды).
   `postSwitchVerify=false` и текст пропуска включить в статус демона.
6. `Save-TransportQualityMemory $root $memory $q $now` сохраняет
   `networks[id].quality.tspu[tag] = {count,until}` в существующий приватный файл
   памяти, не меняя кандидатов. Сохранение кандидатов через `Save-TransportMemory`
   сохраняет поле `quality`. Статус `net.quality.status` показывает причину понижения пути.

`net.quality` содержит `class`, `lightP50Ms`, `kib64Ms` (последняя успешная 64 КиБ),
`episodes10m`, `switches10m`, `stalls10m`, `tspuSuspect`, `tspuRatio` (доля отказов
среди **сопоставленных** пар баннер/64 КиБ), использование бюджета и пороги.
Две независимые пары «баннер прошёл, 64 КиБ нет» помечают путь по id сети на 24 ч.
Память ограничена 32 сетями в процессе, история каждого вида — 4096 измерениями;
история кандидатов и метки других сетей на диске сохраняются.

Пороги: `clamp(default * classK * stabilityK * flapK, min, max)`.
Начальное `stabilityK=1`; возможные ступени `0.6, 1, 1.5, 2`.
Переход не больше одной ступени в начале нового эпизода: тихие 30 минут наблюдения
с успешной 64 КиБ <1500 ms дают 0.6; ≥3 эпизодов за 10 минут — 1.5, вместе
с ТСПУ — 2. Ступени `stageMs` ограничены пропорциональными границами hardFail
(в wire-схеме отдельного min/max для stage нет). При трёх переключениях за окно
`flapK=2`, в пределах clamp; `allowImprovement=false`. Окна и срок памяти
обновляются по новым событиям, собственных tick-источников нет.
