## Что сделано

- Зарегистрированный компьютер проверяет настройки при запуске, восстановлении
  связи и раз в пять минут. Общий каталог остаётся прежним; адрес, pins,
  маршруты и закрытые данные VPN публикуются командой `remoteagents invite sync`
  и при `create`. Получение — своим ключом через уже доверенный SSH-канал,
  включая работающий местный транспорт. Неизвестный ключ не принимается.
- Новые пути проверяются до применения; каталог заменяет старый. Удалённый
  закреплённый путь возвращает автовыбор. Профиль сохраняет прежнее имя файла
  и закрытый ключ, поэтому Disk и supervision моста продолжают использовать
  свою настройку. VPN подхватывает новую ревизию штатным перезапуском.
- При полной потере связи в трее появляется красный пункт получения обновления:
  инструкция человеку и копирование имени/id без секретов.
- `invite refresh --device <имя|id> [--hours N] [--publish узел]` выпускает один
  EXE с нагрузкой `refresh`, без пропуска/повторной регистрации. Привязка
  проверяется по открытому ключу, выведенному из имеющегося **закрытого** ключа;
  подмена одного `.pub` не помогает. Есть срок, понятные отказы и идемпотентность.
- Вложенный VPN-бинарник сохраняется отдельно; новая версия программы ставится
  существующим ручным установщиком с чистым EXE, самопроверкой и откатом.
  Папки, Happier, мост и настройки сохраняются. При остановленном трее задача
  отката связи остаётся включённой до подтверждения новым экземпляром.
- `invite devices` показывает имя, время регистрации, id и отпечаток;
  `revoke-device` удаляет соответствующую строку authorized_keys. Проверено
  только на стенде. Уже открытые SSH-сессии удаление строки не завершает.
- «Настройки…» использует прежнее окно разделов и сохранённый профиль.
  Приглашение не запускает мастер администратора при потере связи.
- В [INVITE.md](INVITE.md) описаны обновления и правило смены VPS:
  **сначала добавить новый путь и опубликовать настройки, затем убрать старый**.
  Pins из refresh-файла считаются доверенными, потому что файл выдал администратор;
  SHA-256 overlay — целостность, не подпись издателя.

## Что требует приёмки на реальной системе

Windows GUI и заполнение разделов проверены по существующим путям кода/моделям,
не нажатием в реальном окне. Не проверены PowerShell 5.1, UAC, настоящий TUN/DNS,
Scheduled Tasks и watchdog, замена исполняющегося EXE средствами Windows,
восстановление живого моста/Syncthing после смены VPS, реальная внешняя HTTPS-раздача,
реальные ограничения провайдеров. VPN и ОС в новых тестах заменены заглушками;
OpenSSH-аутентификация, смена доверенного хоста и отказ чужому ключу — настоящие.

Для приёмки использовать отдельный сервер и чистую Windows по [INVITE.md](INVITE.md).
На живую систему эта ветка не устанавливалась. Push и merge не выполнялись.
Исходный untracked `docs/TASK-INVITE.md` оставлен вне коммитов.
