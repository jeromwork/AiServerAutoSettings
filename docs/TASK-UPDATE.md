# Задача: обновление программы «по воздуху»

Решение владельца 16.11.2026, уточнено им же 16.11.2026 вечером: **программа сама проверяет и сама ставит
обновления**. Обновления у нас каждый день; без автообновления программу нельзя отдавать людям. Человек ничего
не нажимает. Не ставится обновление только тогда, когда новая версия не принимает конфиг человека.

## Как это видит владелец

1. Программа сама проверяет новую версию: при запуске и потом раз в несколько часов (по умолчанию 6 ч, поле в конфиге).
2. Новая версия есть → программа **сама** скачивает, проверяет, ставит, перезапускается и подтверждает, что всё
   работает. Ставит в безопасный момент: не во время применения конфига, работы с Диском или долгого процесса
   моста (ждёт их окончания, как `MutationConflict`). Если что-то не так — сама возвращает прежнюю версию
   и пишет понятную причину; ту же сломанную версию повторно не ставит (`bad.txt`).
3. Человек видит итог одним уведомлением трея: «Программа обновлена до …» или «Обновление … не установлено: <причина>».
   В окне строка: «Установлена последняя версия <версия>, проверено <время>» / «Обновляется до …» / причина отказа.
   Кнопка «Проверить сейчас» остаётся.
4. Конфиг человека новая версия принимает как есть. Если формат конфига изменился, новая версия сама переводит
   старый конфиг в новый формат. «Ваш конфиг не поддерживается» — только редкое исключение: тогда обновление
   **не ставится**, программа остаётся рабочей и одной фразой говорит, что сделать
   («попросите администратора выдать новый конфиг»). Человек не должен оказаться с неработающей программой.
5. Отключить автоматическую установку можно только явно (`update.auto=false` в конфиге, решение владельца).

## Что уже есть (не писать заново, конституция §2)

- `app/launcher/UpdateEngine.cs` — транзакция обновления: `Prepare` (проверка размера и SHA-256, распаковка,
  `selftest.ps1`, бинарники), `Activate`, 120 с проверки здоровья, автоматический откат, `bad.txt`.
  `TrySelfUpdate` в `TrayContext.cs` заменяет сам EXE (`.launcher-manifest.json`).
- `app/launcher/SshUpdate.cs` — источник обновления на нашем сервере по SSH, с проверкой ключа хоста.
  Из `update.remoteDir` (по умолчанию `~/.local/share/remote-agents/dist`) он читает `manifest.json`
  (`version`, `file`, `sha256`, `size`, `minLauncher`, `launcher{version,sha256}`).
- Пункт трея «Проверить обновления на сервере» (`CheckUpdates` в `TrayContext.cs`) — ручная проверка.
- `build/publish.sh` / `bundle.py publish` выкладывают сборку в dist на сервере, `manifest.json` пишется атомарно.
- `build/release-github.sh` выкладывает ту же сборку в единственный GitHub-релиз `main-latest` (конституция 7а).
- Описание текущего поведения: `docs/LAUNCHER.md`, раздел «Установка и ручное обновление».

## Почему сейчас не работает

- В конфиге `update.enabled=false` по умолчанию (`Data.cs`), `config export` раздел `update` не выдаёт, поэтому пункт трея серый.
- В dist на сервере ни одна сборка не выкладывалась, и папки `~/.local/share/remote-agents/dist` нет.
- Фоновой проверки нет: это прежнее решение «только вручную» (LAUNCHER.md). Владелец его отменяет:
  проверять и ставить автоматически.
- Совместимость конфига при обновлении нигде не проверяется.

## Проверка

- Тесты: фоновая проверка (есть / нет / нет связи / испорченный manifest); автоустановка ждёт применения конфига /
  Диска / долгого процесса моста; установка (ok / самопроверка
  не прошла / здоровье не подтвердилось → откат); конфиг старой схемы → переведён; неподдерживаемый конфиг →
  обновление не ставится, программа работает; обновление самого EXE. Запускаются `app/launcher/tests/run.sh`
  и `server/tests/run.sh`, тяжёлое — по одному через `flock /tmp/heavy-tests.lock`.
- Живая приёмка на компьютере владельца (только с его «да»): поставить сборку N, выложить N+1, увидеть
  что программа сама обновилась (уведомление в трее), а мост, связь, Диск
  и Happier работают. Затем выложить заведомо битую N+2 (самопроверка падает) и убедиться, что осталась N+1
  с понятной причиной.

## Границы

- Работа в ветке от `main` в `~/work/wt-update`. Готовое сливается в `main` с прогоном тестов и `git push origin main` (AGENTS.md).
- Сеть, sing-box, nft, sshd на живом сервере не трогать. Запись в dist на сервере (`~/.local/share/remote-agents/dist`)
  входит в задачу, это обычные файлы рабочего пользователя.
- Код Диска (`disk/*`, `app/launcher/Disk*.cs`) сейчас меняет сессия «Папки Диска: железобетонный план»,
  с ней надо договориться до правок в общих файлах (`TrayContext.cs`, `ConfigWindow*.cs`).
- Сборку выкладывать только в `main-latest` (конституция 7а), новых релизов не заводить.
