# Windows → VPS: Codex и Claude

Переносной комплект установщика для Windows 10/11 и Ubuntu VPS. Это текущая рабочая версия для продолжения настройки, а не подтверждённый production-релиз. Незавершённые проверки описаны в [CONTINUE.md](CONTINUE.md).

Для работы с чатами на слабом интернете выберите в меню сервера **14 — Чаты Codex и Claude в браузере**. Агенты работают на VPS; на компьютере нужен браузер. Установка, первый вход и отдельные пользователи описаны в [REMOTE-CHAT.md](REMOTE-CHAT.md).

## Установка одним файлом

Распакуйте папку и дважды нажмите **SETUP.cmd**. Он по очереди:

1. проверяет SSH-профиль, а если его нет — открывает настройку входа (после проверки входа в меню введите 0 и 0);
2. разрешает ключ компьютера пользователю `remoteagents` на сервере и сохраняет профиль диска (диск не входит под root);
3. ставит диск: Syncthing Tray, канал и автоподключение серверных папок в `%USERPROFILE%\Disk`;
4. ставит мост управления компьютером (MCP).

В конце показывает итог по каждому шагу. Всё запускается само при входе в Windows; повторный запуск безопасен. Отдельные `01`, `04`, `05` остаются для ручной настройки.

Если OpenVPN пишет «All wintun adapters on this system are currently in use», запустите **OPENVPN-FIX.cmd**: он пересоздаёт адаптер Wintun OpenVPN и перезапускает TAP (нужно подтверждение администратора).

## Запасной маршрут SSH для RDP

Если прямой SSH зависает, запускатель может автоматически использовать существующее промежуточное SSH-подключение. Однократный запуск: `01-setup-ssh.cmd -SSHJumpHost ИМЯ_ПОДКЛЮЧЕНИЯ`; имя берётся из вашего SSH config. Для другого файла настроек добавьте `-SSHJumpConfig "C:\полный путь\config"`. Вход на промежуточный сервер должен работать без запроса пароля, с уже проверенным ключом сервера.

После успешного подключения запасной маршрут сохраняется в выбранном профиле. Обычный запуск BAT сначала проверяет прямое соединение и при необходимости переключает RDP и остальные компоненты на запасное. Если оба пути недоступны, сохраняются последние рабочие настройки. При переносе на другой ПК промежуточное SSH-подключение нужно настроить на нём отдельно.

## Диктовка через микрофон

При подключении через комплект RDP передаёт микрофон текущего Windows-ПК в Linux как `xrdp-source`; он выбирается источником записи по умолчанию. Для применения обновления закройте окно RDP и снова откройте рабочий стол через BAT обновлённого комплекта. Затем полностью закройте и откройте приложение с диктовкой. В Windows должен быть разрешён доступ классических приложений к микрофону; в браузере также разрешите микрофон для сайта. Если RDP подключается с другого ПК, используется микрофон этого ПК. Общий рабочий стол не даёт отдельного аудиосеанса каждому проекту.

Локальные проверки подтверждают настройки подключения и скриптов. Распознавание речи и переключение микрофона между двумя физическими ПК требуют проверки в реальном RDP-сеансе.

## Запуск на другом компьютере

1. В GitHub выберите ветку `codex/portable-installer-package`, нажмите **Code → Download ZIP**, распакуйте **всю** папку в обычную доступную для записи папку. Либо выполните `git clone --branch codex/portable-installer-package https://github.com/jeromwork/AiServerAutoSettings.git`.
2. Дважды нажмите **01-setup-ssh.cmd**. Не запускайте отдельные серверные скрипты вручную.
   В начале выберите вывод: Enter — краткий режим с индикаторами и подробностями в журнале; 2 — подробности также в окне. Папка журналов показывается сразу. Для запуска из командной строки доступен параметр `-DetailedOutput`.
3. Добавьте свой сервер: адрес, имя подключения и SSH-пользователя. Первое подключение поддерживает `root` и пароль: пароль вводится в отдельном окне OpenSSH и не записывается в комплект. Проверьте отпечаток сервера. Для дальнейших подключений установщик подготовит ключ и профиль локально на этом компьютере.
4. После проверки SSH и Ubuntu откроется меню работы с сервером. **Enter / 1 — рабочий стол RDP**, без обязательной установки Codex/Claude и без выбора режима. На первом запуске установщик подготовит служебного пользователя и рабочий стол; готовые компоненты использует повторно. Обычный запуск не требует администратора Windows и не отключает проверки сертификатов. RDP остаётся открытым при работе с меню BAT.
5. **3 — добавить папки или изменить выбор**, **13 — подключить сохранённые папки** (названия видны в меню). Установка агента для синхронизации не нужна: в режиме управления Windows мост команд запускается вместе с синхронизацией, а MCP регистрируется для уже установленных Codex/Claude. Уже работающие подключения сохраняются при добавлении папок. Для нового исходника выберите папки этого ПК; для общей серверной копии — присоединение по ID.
6. **11 — установить/настроить Codex, Claude или оба**, **2 — открыть выбранное приложение на рабочем столе**. Войдите в аккаунт только при запросе официального приложения/браузера. Если синхронизация уже работает, MCP подключается к ней без нового seed. Выбор режима управления Windows уже разрешает команды с правами текущего пользователя; дополнительного вопроса BAT нет. Выберите серверную папку, показанную в ярлыке «Начать настройку проекта», и создайте сессию задачи. AGENTS.md/CLAUDE.md сохраняют существующие правила. Для Claude используйте Code; для Codex после изменения подключения может потребоваться Settings → MCP → Restart. VPN — отдельный необязательный пункт и для RDP не нужен.

При повторном запуске короткий путь: **краткий вывод → номер сервера (Enter — первый) → Enter для RDP**. Повторной установки агентов на этом пути нет. Дополнительные действия (компоненты, режим, localhost и VPN) раскрываются пунктом **10**. Обслуживание SSH вынесено в выбор сервера **M1** (M и номер) или параметр -ConnectionSettings: прежняя настройка/смена защиты ключа сохранена.

Оставляйте установщик открытым во время работы: он держит SSH-туннели, синхронизацию и мост команд. Отключайтесь через его меню. Исходная папка проекта сохраняется; сервер работает с отдельной копией, изменения возвращаются в отдельную рабочую копию Windows. Перед выдачей доступа к командам установщик проверяет состояние копий. В режиме управления компьютером команды имеют права текущего пользователя Windows; правила подтверждений самого агента сохраняются.

## Что нужно

- Windows PowerShell **5.1**, .NET Framework/Windows Forms, клиент OpenSSH **8.6+** (`ssh.exe`, `ssh-keygen.exe`), штатный клиент удалённого рабочего стола и интернет.
- **Ubuntu 24.04 LTS x86_64 (amd64)** с root или sudo без пароля. Полный сценарий с приложениями и RDP ограничен этой системой; Red Hat, Debian, ARM и другие Ubuntu не заявлены поддерживаемыми. Установщик проверяет ОС до установки приложений.
- Python, Codex и Claude **на Windows для обычного запуска не нужны**. Серверные Python-скрипты исполняются на Ubuntu. Python на Windows требуется только разработчику для дополнительных тестов.
- Обычный запуск не требует «Запуск от администратора». UAC может понадобиться при добавлении компонента OpenSSH в Windows или при отдельной установке VPN.

При отсутствии Git установщик загружает официальный portable MinGit и проверяет закреплённую SHA256. Syncthing скачивается с официального GitHub с закреплённой SHA256. Большие установщики, архивы и кэши в репозиторий не входят. HAPP устанавливается отдельно с официального сайта; VPN включается пользователем.

Git не требует GitHub: подключение выбранной локальной папки работает с репозиториями GitHub, GitLab, других серверов и без удалённого репозитория. При переносе не выполняются clone/fetch/push и не нужен вход в Git-хостинг. Исходная `.git`, история, remote и учётные данные не переносятся; сервер получает разрешённые файлы и отдельные служебные Git-метаданные. Для дальнейших fetch/push доступ к нужному сервису на сервере настраивается отдельно по запросу владельца; автоматического входа в Git-хостинг в установщике пока нет. Ошибка локального Git не является запросом такой авторизации. При первичном seed каждая Git-проверка ограничена 60 секундами; быстрый поиск сохраняет короткие лимиты. Ошибка указывает операцию, лимит или код выхода, без вывода remote и учётных данных.

Во время подключения консоль показывает этап: проверку Git, состав/контрольные суммы файлов, создание архива, отправку, распаковку на сервере, получение Windows-копии и окончательную проверку. В обычной консоли числа и проценты обновляются в одной строке примерно раз в секунду; при смене этапа завершается предыдущая строка. Если вывод перенаправлен в файл, используются отдельные строки примерно раз в 5 секунд. Для упаковки/отправки/распаковки видны проценты и объём, для отправки — скорость и приблизительное оставшееся время. Пока объём неизвестен, показываются обработанные файлы/байты и время этапа. Проценты относятся к своему этапу: 100% отправки ещё не означает готовую Windows-копию. Получение Windows оценивается по завершённым файлам Syncthing, поэтому на одном большом файле процент может долго стоять; сетевой счётчик отдельно учитывается при проверке активности. Смысл счётчиков: [Syncthing folder status](https://docs.syncthing.net/rest/db-status-get.html).

Готовый seed сохраняется вместе с индексом SHA-256: хешами файлов в manifest и отдельным seed-index.json для архива. Повтор не упаковывает исходную папку заново. Для неизменившегося архива используются сохранённый SHA-256, размер/время записи и хеш manifest; при изменении или повреждении индекса он пересчитывается. Сервер всё равно проверяет полный SHA-256 полученного архива. Настроенный серверный проект подключается без повторного seed/upload. Финальная сверка файлов Windows-копии остаётся полной: индекс архива не заменяет проверку актуальной копии. Обход файлов ускорен прямыми файловыми API без повторных команд Get-Item/Test-Path; проверки исключений, ссылок и содержимого сохранены. Изменения отслеживает fsWatcher; плановая полная проверка Syncthing выполняется раз в час вместо ежеминутной, а явный свежий снимок перед действием агента сохраняется.

Текст SSH-скриптов нормализуется в LF перед отправкой, бинарные данные передаются без преобразования. Обычные имена маршрутов `[id].tsx` поддерживаются буквально и экранируются отдельно от шаблонов Syncthing; правила для Linux/Windows различаются согласно [официальной документации](https://docs.syncthing.net/users/ignoring.html). Разрыв SSH с кодом 255 при отправке служебного файла получает одну повторную попытку; исполняемые команды автоматически не повторяются.

Для файлового ввода-вывода Windows PowerShell 5.1 используется явный формат длинных путей: служебные архивы/снимки и вложенные файлы копии могут превышать 260 символов. Это не требует изменения реестра, системных политик или переноса профилей. Сохранённые пути и идентификаторы остаются в обычном виде, префикс применяется только при обращении к файлам; проверка границ передачи и запрет ссылок сохраняются.

Первичное подключение допускает до 12 часов в целом, а не фиксированные 30/60/120 секунд на большой перенос. Долгие SSH-операции получают такой же верхний предел и контроль отсутствия активности 5 минут; серверные долгие операции передают heartbeat. Обычные короткие проверки и проверки перед командами агента сохраняют свои лимиты. При обрыве повторите **13 — «Подключить сохранённые папки»**: готовый локальный архив используется повторно, его частичная отправка продолжается в файл `.part`, после полной SHA256-проверки архив публикуется на сервере. Полный повреждённый архив сохраняется отдельно и следующая попытка отправляет его заново. Готовая серверная распаковка отмечается отдельной проверяемой квитанцией, чтобы продолжить настройку без повторного seed; распаковка публикует папку атомарно и не заменяет уже существующую. Ошибка показывает этап и журнал. Исходная папка компьютера остаётся источником, не принимающей копией.

## Дополнительные возможности

Установщик заканчивает подготовку на передаче проекта агенту. OpenVPN, корпоративные сети, production, конкретные SDK и приложения настраиваются уже агентом по запросу владельца, не вшиты в пакет. Если целевой сервер доступен через сеть/VPN компьютера, агент выполняет разрешённый SSH/клиент на Windows через MCP-мост. Приватные SSH-ключи остаются в Windows, пароли вводятся пользователем в штатном окне. В режиме управления компьютером команды Windows включены автоматически с правами пользователя; подтверждения действий задаются в Codex/Claude. UAC и политики Windows не обходятся.

Режимы работы: **1. Автономный сервер**, **2. Сервер управляет этим компьютером**. Внутренние сохранённые значения прежних версий совместимы: новая нумерация меню не меняет смысл ранее выбранного режима.

Целевая модель — несколько подключённых компьютеров одновременно, с явным выбором узла для каждой задачи. Например: веб-приложение на VPS, эмулятор на домашнем ПК, просмотр на ноутбуке; VPN-доступ к другой сети назначается отдельно. Выбор нового узла не должен требовать физически закрывать BAT на предыдущем. Каждая команда обязана проверять точную привязку устройства и проекта; исключительные изменения общей среды требуют явного `exclusive: true`. Домашний ПК должен быть включён, доступен и иметь работающий Windows-мост. Само присутствие пользователя за ноутбуком не переключает цель команд.

Выбор проектов теперь происходит **в консоли BAT, без отдельного окна**. При пустом списке быстрый поиск запускается автоматически. **Q** повторяет поиск любых Git-репозиториев/worktree в типичных папках профиля, документов, рабочего стола и фиксированных дисков (GitHub, repos, source, projects, work, dev, code и похожие). Поиск находит и вложенные самостоятельные репозитории внутри родительского Git-проекта. Список показывает имя, тип, дату исходников и точный путь, обычные Git выше worktree, внутри групп свежие сверху, по 10 проектов на странице. В обычной Windows-консоли можно щёлкать мышью по строкам с [ ] и по обновляемым пунктам S/V внизу; исходный режим ввода восстанавливается после выбора. Если консоль не поддерживает мышь, остаётся клавиатура. Номера через запятую, точку или пробел меняют отметки (1,3 / 1.3 / 1 3), **N/P** переключают страницы, **V** показывает только отмеченные папки (повторное V — все), **F** ищет репозитории в указанной папке и её подпапках (до 30 секунд, глубина 8), **A** добавляет точные пути вручную, **Enter / S — «Подключить выбранные (N): имена…»** обновляется после каждого изменения отметок и сохраняет/начинает подключение; **0** отменяет; Enter подключает отмеченные папки; если ничего не отмечено — запускает поиск. Для повторного поиска при уже выбранных папках используется Q. Новые результаты не выбираются автоматически, прежние отметки сохраняются. Быстрый поиск ограничен примерно 15 секундами, глубиной 5, 4000 каталогами и 100 проектами. Сначала собираются пути, затем проверяются Git и даты, поэтому тяжёлый ранний репозиторий не скрывает вложенные. Неполные оценки отмечаются знаком ~; если дата не проверена, показано «не определена». Дата каталога и его Git-метаданных не выдаётся за дату исходников. Родительский и вложенный проект одновременно для переноса выбирать нельзя. Используется только уже подготовленный Git, без скрытых загрузок. Оконный вариант сохранён как явный технический параметр -Window, BAT его не вызывает.

В меню проектов разделены создание из локальной папки, присоединение к существующему серверному проекту и повторное подключение. Пункт повторного подключения относится только к ранее выбранным проектам этого ПК; если список пуст, выберите 1 для локальной папки или 2 для существующего проекта VPS. На первом ПК создайте тестовый проект и сохраните показанный projectId. На втором выберите «Присоединить» и именно этот ID из серверного каталога: получите отдельную receive-only копию без передачи локального seed и без перезаписи исходников VPS. Одинаковые имена папок ничего не объединяют. Ранее настроенный проект появляется в каталоге после повторного подключения первым ПК обновлённым комплектом.

На каждом компьютере синхронизируются только явно подключённые к нему проекты. Проект, выбранный другим компьютером, автоматически сюда не добавляется; к общему проекту присоединяются отдельно по ID. Несколько компьютеров могут оставаться подключёнными и обслуживать разные явно назначенные задачи. Изменения одного серверного проекта получают все подключённые к нему копии; одновременные изменения тех же исходников разными агентами требуют координации.

**Отдельная синхронизация не означает изоляцию людей.** Текущий комплект использует общую учётную запись remoteagents, рабочий стол, настройки приложений и каталоги на VPS. Поэтому разные проекты отца и сына не копируются друг другу автоматически, но отдельный доступ к файлам/учётным записям этим не обеспечен. Многопользовательские права и отдельные серверные окружения пока не реализованы. Общий root-доступ к VPS также не разделяет владельцев. Не используйте выбор проектов как защиту чужих данных.

MCP-инструмент windows_devices показывает стабильный hostId, имя компьютера, projectId, живую доступность и обнаруженные исполняемые файлы. Это доступность моста, а не подтверждение работы SDK/VPN/эмулятора или свежести копии. Во все действия передаются точные projectId + hostId; для команд и процессов — также taskId текущей задачи. Новая проверка синхронизации остаётся обязательной перед запуском. Неизвестный, спящий или отключённый узел не заменяется другим. Команды и фоновые процессы разных задач выполняются параллельно, в том числе через один MCP-сеанс. Для установки, перехода, изменения сети/служб и перезагрузки задавайте `exclusive: true`: чужая активная операция сразу даёт busy с `taskId`, видом операции и временем начала UTC. Статус и файловые инструменты остаются доступны. Блокировка координирует shell-операции исполнителей одного пользователя Windows, не является песочницей shell и не замораживает произвольные записи агента на VPS. Лимиты: 8 живых процессов на задачу, 64 суммарно; завершённые освобождают слот автоматически. Подробности, совместимость и обновление — в [описании моста](REMOTE-CHAT.md#мост-управления-windows).

Каждый участвующий ПК должен один раз запустить обновлённый комплект и переподключить проект. Затем перезапустите MCP и создайте новую сессию проекта в агенте: схемы теперь требуют явную цель; старые вызовы без привязки отклоняются. При последующей смене цели закрывать BAT другого ПК не нужно. Работа двух подписок проверена локально реальным Syncthing с двумя Linux-приёмниками; проверка двух физических Windows-ПК через VPS и реальную сессию модели ещё требуется. OpenVPN и ограничения числа его сессий настраивает администратор соответствующей VPN-системы; частные профили не входят в комплект.

Пункт 9 открывает localhost VPS через SSH только на 127.0.0.1 этого компьютера: например, локальный 3801 → VPS 127.0.0.1:3801. При занятом локальном порте выбирается свободный и показывается точная ссылка. Туннель остаётся открытым вместе с меню BAT и закрывается при выходе. Сам сервис запускает агент по задаче владельца; наличие туннеля не означает, что сервис уже отвечает. Публичный доступ автоматически не создаётся.

VPN для HAPP использует Xray с VLESS/REALITY на TCP 8443. Сервер сам загружает официальный выпуск Xray и проверяет SHA256 из метаданных выпуска GitHub. SSH на 22 и 443 сохраняется. Подключение передаётся в буфер обмена только при запуске владельцем настройки VPN; приватные ключи сервера не покидают VPS. В HAPP нажмите «+ → Из буфера обмена» и включите режим VPN. Конфигурация хранится на сервере, доступ к ней ограничен. HAPP устанавливается с официального сайта https://happ.info.

Пользователь ранее подтвердил развёртывание контейнера и появление профиля в Windows-клиенте. Полная VPN-связность и совместимость с другим действующим VPN не подтверждены; в текущей проверке VPN не подключался и не изменялся.

После SSH-подключения установщик показывает наличие приложений Codex/Claude, их терминальных компонентов и рабочего стола. Сводка обновляется после установки приложений и через пункт **«Проверить установленные компоненты»**. Это проверка наличия пакетов и исполняемых файлов, а не входа в аккаунты или полной работоспособности.

Серверные установщики передаются по SSH как текстовые скрипты. Пакеты Codex, Claude и системные зависимости скачивает сам VPS. Windows-клиент HAPP устанавливается отдельно пользователем. Подключение проектов отдельно запускает передачу файлов выбранных проектов; её объём зависит от их содержимого.

Серверный браузер, рабочий стол, звук через RDP, безопасный выбор папок, Git worktrees, синхронизация обычных папок и передача контекста агенту включены в комплект. Готовность этих компонентов кода и локальные проверки не означают успешной проверки на новом VPS. Личные профили, ключи, токены, адрес прежнего сервера и аккаунтные файлы переносить не нужно: добавьте сервер заново.

Технический контракт синхронизации: [SYNC-CONTRACT.md](SYNC-CONTRACT.md). Состав поставки: [PACKAGE-MANIFEST.txt](PACKAGE-MANIFEST.txt). Проверки и следующий шаг: [CONTINUE.md](CONTINUE.md).

Подключённые проекты доступны для выбора по понятным именам в ~/work/projects/<имя выбранной папки>. Это ссылки на прежние серверные каталоги с ID: синхронизация и привязки не перемещаются. При совпадении имён добавляется короткий ID; существующая чужая папка не заменяется. Название берётся из выбранной исходной папки, её родительская структура Windows не переносится. Технический work/projects — стандартная серверная рабочая область, а не отражение локального диска.

## Общий аккаунт и несколько компьютеров

Приложения и рабочий стол общие, проекты и чаты задач — отдельные. RDP показывает Linux; команды в Windows выполняются через MCP, а их результат виден в чате. При открытии RDP в режиме управления сохранённые проекты этого ПК подключаются автоматически. BAT нужно оставить открытым на каждом подключённом ПК.

Установщик сам записывает инструкции для Codex и Claude, сохраняя прежние правила. Технический первый запрос вставлять не нужно. Для единственного доступного Windows-узла проекта агент выбирает его автоматически; при нескольких уточняет компьютер. В начале работы и при смене цели инструкции требуют показать «Проект: имя → Windows: компьютер». Цель относится к текущей задаче, а подключение другого RDP или ПК её не меняет. Существующий чат может потребовать обновления MCP; новый чат должен получить установленные инструкции.

Для одной серверной копии на двух своих ПК используйте присоединение второго ПК к существующему проекту. Для проекта сына создайте отдельную привязку. Это выбранная схема общего аккаунта, без отдельных пользователей и изоляции файлов.

## Отдельное управление Windows

Запустите `05-control.cmd` один раз: выберите сохранённый SSH-профиль, и MCP-мост управления компьютером установится в `%LOCALAPPDATA%\RemoteAgents\control\app`, будет работать без окна, запускаться при входе в Windows и переподключаться бесконечно. Синхронизация и агенты не устанавливаются. Можно указать `-Profile <путь>` и `-AgentUser <пользователь сервера>` (при входе root). Журнал: `%LOCALAPPDATA%\RemoteAgents\control\logs\control.log`. Команды агентов выполняются с вашими правами Windows. Отключить: `05-control.cmd -Uninstall`.
