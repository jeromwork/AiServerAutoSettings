# Проверка прямого SSH — 3 ноября 2026

## Подтверждённые факты

- На портах 22 и 443 сервер отвечает баннером OpenSSH 9.6p1.
- Оба порта проходят согласование ключей. Прямая сессия затем останавливается около
  `SSH2_MSG_SERVICE_ACCEPT`: клиент сообщает отправку `SSH_MSG_USERAUTH_REQUEST` (тип 50),
  но ответа об успешном входе или допустимых способах входа не получает.
- Результат воспроизводится со встроенным OpenSSH Windows 9.5p1 и OpenSSH Git 8.8p1.
- Проверки выполнялись без пользовательского SSH config и SSH-agent. Проверка известного
  ключа хоста для настоящего входа сохранялась. Для порта 22 использован тот же проверенный
  ключ хоста, что и для порта 443. Файлы ключей не читались и не изменялись.
- Переменных окружения с префиксами SSH/GIT_SSH в процессе проверки не найдено.
- Отключение IPQoS и варианты AES-CTR/AES-GCM прямое соединение не восстановили.
- Через существующий промежуточный сервер тот же ключ успешно проходит авторизацию
  на Contabo. Настройки и ключи промежуточного сервера не изменялись.
- На Contabo SSH активен; PermitRootLogin=yes, PasswordAuthentication=yes, UseDNS=no,
  AuthenticationMethods=any. Нагрузка низкая. Служба Happier активна, Linger=yes.

## Наблюдение за пакетами

Короткий захват заголовков TCP на сервере показал первоначальный двусторонний обмен.
После согласования шифрования сервер повторно отправляет один и тот же пакет длиной
44 байта и не получает подтверждения. Последующий запрос входа, об отправке которого
сообщает прямой клиент, в этом захвате на сервере не наблюдается.

Это локализует сбой обмена, но не доказывает конкретного виновника. Без захвата на стороне
Windows нельзя окончательно разделить локальный фильтр/драйвер, VPN-маршрут, роутер
и промежуточную сеть. Блокировка конкретно Роскомнадзором, провайдером или Windows
не установлена. Обычная недоступность порта и несовпадение пароля не объясняют наблюдения.

## Подготовленный рабочий путь

Окно привязки Happier открыто через проверенный промежуточный маршрут. Для него создан
отдельный временный SSH config; основной профиль подключения и настройки Windows/VPN
не менялись. Через этот путь получен ответ Happier `not_authenticated`.
Владельцу остаётся подтвердить привязку аккаунта в открытом окне.

После привязки браузерные чаты используют Happier Cloud, а не прямой SSH с компьютера.
Обычный BAT-путь прямой проверки SSH пока воспроизводит описанный сбой; он не объявлен
исправленным. Все проверки SSH ограничивались короткими внешними таймаутами.

## Обновление 4 ноября: автоматический запасной маршрут

В запускатель добавлено переключение на сохранённое промежуточное SSH-подключение,
если прямые порты не доходят до авторизации. Маршрут передаётся дочерним компонентам
через общий генерируемый SSH config; проверка ключей целевого и промежуточного серверов
сохраняется. Прямой сетевой сбой не устранён: подключение обходит его через резерв.

На этом компьютере профиль настроен на ранее проверенный промежуточный сервер.
Живой запуск прошёл прямую неудачную проверку, автоматически выбрал резерв и подтвердил
вход сохранённым ключом. Второй запуск без параметров повторил успешный вход.
Отдельно подтверждены RDP negotiation с Windows через резервный туннель и TLSv1.3
серверной проверкой рабочего стола. Тесты проверяют повторный запуск, восстановление
прямого пути, сохранение настроек при отказе обоих путей и отклонение постороннего ProxyCommand.

Проверка переносного пакета пока останавливается на старом диагностическом SSH-логе
в корне репозитория; этот файл не удалялся. Это не мешает запуску подключения.
