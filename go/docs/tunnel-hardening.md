# Устойчивость туннеля v3 (ветка v3/tunnel)

## Как работает
- **Выход sing-box только через физический адаптер.** `platform.PickPhysical` берёт адаптер: поднят, есть шлюз и IPv4,
  не виртуальный (Tailscale, happ-tun, RA2-LAN/ra3-*, Hyper-V vEthernet, WSL, VPN других программ, loopback, docker и т.п.),
  с меньшей метрикой. Имя пишется в `route.default_interface` (вместо `auto_detect_interface`). Адаптер не найден — остаётся
  `auto_detect_interface`. Чужой TUN как маршрут по умолчанию на выход не влияет; маршруты 100.64.0.0/10 и MagicDNS не используются
  (адреса путей — IP из конфига).
- **События сети без опроса.** Windows: NotifyIpInterfaceChange + NotifyRouteChange2 + NotifyUnicastIpAddressChange; Linux: netlink;
  macOS: заглушка. Пачка событий сливается (debounce 0.7 с). Перестройка идёт только если изменился отпечаток физической сети
  (имя адаптера + его адреса) или канал не `up`; шум Tailscale/Happ канал не дёргает.
- **Перестройка.** `singbox.NetChanged`: интерфейс выхода изменился — конфиг перерисовывается и sing-box перезапускается
  (check → замена); не изменился — `DELETE /connections` (сброс зависших). Затем `channel.NetChanged`: текущая попытка/сессия
  обрывается, круг путей идёт с первого по рангу без паузы, на странице причина «сеть сменилась, перестраиваю»
  (состояние `connecting`; номер сессии `session` растёт при каждом `up`). Закреплённый путь (ForcePath) не сбрасывается.
- **Живучесть.** Падение sing-box → автоперезапуск с задержкой 0.5 с … 30 с (удвоение; сбрасывается после 30 с работы).
  Канал после круга неудач ждёт 0.5 с … 30 с (удвоение, сброс при успехе). Пока sing-box перезапускается, канал ждёт его
  событие `Ready` (не уходит в ssh-direct). Рукопожатие — таймаут 40 с; keepalive SSH — по тишине линии (3 пропуска).
- **Возврат на предпочтительный путь.** Сессия поднялась на пути не первого ранга → одноразовый таймер (60 с, при неудачных
  возвратах 2x до 15 мин); по нему выбирается первый путь и сессия перестраивается; если он не отвечает — идёт по рангу дальше.
  На первом пути и на закреплённом таймер не ставится.

## Проверка вручную на ПК (для основного агента)
Журнал: `%LOCALAPPDATA%\RemoteAgents3\logs\lab-*.jsonl`; страница ядра `/state`, SSE `/api/events`. Новые события журнала:
`net-changed` (physical, changed), `singbox.default-iface`, `singbox.exited`, `singbox.restart`.
1. Старт: в журнале `singbox`-конфиг с `default_interface` = Wi-Fi/Ethernet (не happ-tun/Tailscale); канал `up`.
2. Happ вкл/выкл: через ~1 с `net-changed`; если физический адаптер тот же — `changed=false`, канал не рвётся (канал `up`).
3. Wi-Fi → другой Wi-Fi/кабель: `net-changed changed=true`, `singbox.default-iface from→to`, на странице «сеть сменилась,
   перестраиваю», затем `up` с новым номером сессии; ожидаемо за единицы секунд.
4. Tailscale: выключить/включить адаптер — канал не дёргается; канал держится при Tailscale как default route.
5. Убить `sing-box.exe` в диспетчере: `singbox.exited`, `singbox.restart in_ms=500`, канал вернулся; убить 3 раза подряд — задержки 0.5/1/2 с.
6. Выключить предпочтительный путь (или отрезать его порт): канал на запасном; вернуть — через ~1 мин переход на первый путь.
Не проверено автоматически: реальная работа с `default_interface` вместе с TUN VPN/LAN режимов и поведение GetAdaptersAddresses
на машине с Happ/Tailscale (проверено только классификатором на примерах имён).
