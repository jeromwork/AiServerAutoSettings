## 1. Клиентский журнал (`lab/ralab/journal.py`)

### 1.1. Файловое хранилище и ротация
- **Каталог хранения:** `<home>/logs` (`app.py:73`, `journal.py:81,85-86`).
- **Именование файлов:** `lab-<N>.jsonl`, где `<N>` — целое число (`journal.py:87,93`).
- **Нумерация:** продолжается с максимального существующего `<N>`; при отсутствии файлов — с `1` (`journal.py:87-89`).
- **Пределы файлов:**
  - `FILE_MAX = 5 * 1024 * 1024` байт (5 МиБ) на один файл (`journal.py:9,102,145`).
  - `FILES_MAX = 4` файла (`journal.py:9,114`).
- **Алгоритм ротации:**
  - `init(directory)` открывает файл `lab-<N>.jsonl` на дозапись (`journal.py:89,105`). Если его размер $\ge$ `FILE_MAX`, вызывается `_roll()` (`journal.py:102-104`).
  - `_roll()` увеличивает `_num` на 1 (`journal.py:113`) и удаляет устаревшие файлы с номерами от `1` до `_num - FILES_MAX` включительно (`journal.py:114-119`).
  - При первом вытеснении старого файла ставится `_rolled = True` и пишется служебное событие rollover (`journal.py:120-122`):
    `{"ts": "<ISO8601>", "src": "journal", "ev": "journal.rollover", "data": {"max_files": 4, "file_mb": 5}}`.
  - При ошибке `OSError` при открытии: `_fh = None`, `_broken = True`, ошибка выводится в `sys.stderr` (`journal.py:106-108`).
- **Режим записи:** бинарная дозапись (`'ab'`), с вызовом `flush()` после каждой записи (`journal.py:105,140-141`).

### 1.2. Формат записи JSONL и лимиты полей
- **Формат строки:** одна строка JSON в кодировке UTF-8 (`ensure_ascii=False`) + `\n` (`journal.py:132,138`).
- **Поля записи (`log(src, ev, data=None, why=None)`):**
  - `ts`: строка ISO 8601 с локальным часовым поясом и миллисекундами (`timespec='milliseconds'`) (`journal.py:126-127,159`);
  - `src`: строковый идентификатор источника/подсистемы (`journal.py:159`);
  - `ev`: строковый идентификатор события (`journal.py:159`);
  - `data`: произвольный объект данных, прошедший маскировку и усечение (`journal.py:160-161`);
  - `why`: опциональная строка причины, прошедшая маскировку и усечение (`journal.py:162-163`).
- **Ограничения размера полей и записи:**
  - `FIELD_MAX = 2000` символов: строки длиннее 2000 символов обрезаются с суффиксом `"...(+%d)" % (len - 2000)` (`journal.py:9,72-73`). Списки усекаются до первых 200 элементов (`journal.py:77`).
  - `REC_MAX = 16000` символов: если длина сериализованной JSON-строки превышает 16000 символов, при записи в файл она замещается служебной краткой записью об усечении (`journal.py:9,133-134,138`):
    `{"ts": "<ts>", "src": "<src>", "ev": "<ev>", "data": {"truncated_chars": <len>}}`.
    При этом кольцевой буфер `_ring` всегда сохраняет исходную запись `rec`, а краткая усечённая запись идёт только в файл (`journal.py:133-135,138-140`).

### 1.3. Регистрация и маскировка секретов
- **Секретные ключи:** `SECRET_KEYS = ('uuid', 'password', 'private_key', 'short_id', 'public_key', 'private_key_passphrase', 'path')` (`journal.py:8`).
- **Лимит секретов:** `SECRETS_MAX = 2000` значений (`journal.py:9,33`).
- **Регистрация:**
  - `register(*values)`: принимает строки, добавляет само значение и строки из `splitlines()`, если длина после `strip()` $\ge 2$ (`journal.py:25-34`). Секреты сортируются по убыванию длины (`journal.py:35`).
  - `collect(o)`: рекурсивный обход структур данных (dict, list, tuple); при совпадении ключа с `SECRET_KEYS` регистрирует все вложенные строки (`journal.py:38-49`).
- **Правила маскировки `mask(x)`:**
  - Подстроки зарегистрированных секретов длиной $\ge 4$ символа заменяются на `'***'` через `x.replace(s, '***')` (`journal.py:61-62`).
  - Короткие секреты длиной 2–3 символа заменяются только как отдельные токены через regex `(?<![\w-])%s(?![\w-])` (`journal.py:62`).
  - Рекурсивно обрабатывает словари (`{str(k): mask(v)}`) и списки (`journal.py:64-67`).
- `redact(o)`: рекурсивная замена значений ключей `SECRET_KEYS` на `'***'` в словарях и списках для показа конфигов без раскрытия (`journal.py:51-55`).

### 1.4. Дедупликация повторов и кольцевой буфер
- **Сворачивание одинаковых событий подряд:**
  - Ключ дедупликации: `(src, ev, json_sorted(data), why)` (`journal.py:164`).
  - Идущие подряд записи с одинаковым ключом не пишутся сразу, а инкрементируют счётчик `_repeat` (`journal.py:166-168`).
  - При смене ключа, вызове `flush()` или `tail()` сбрасывается запись о повторах (`journal.py:149-154,169-170,176,182`):
    `{"ts": "<ts>", "src": "<src>", "ev": "<ev>", "data": {"repeated": <count>}}`.
- **Кольцевой буфер в ОЗУ:** `_ring = collections.deque(maxlen=RING_MAX)`, где `RING_MAX = 2000` (`journal.py:9,13,135`). Буфер содержит исходные записи `rec` целиком; если длина записи превышает `REC_MAX`, в буфер идёт полная запись, а при переполнении в файл пишется краткая служебная (`journal.py:133-135,138-140`).
- **Чтение буфера (`tail(n=200)`):** сбрасывает повторы, возвращает последние $\max(1, \min(n, 2000))$ записей (`journal.py:174-177`).
- **Потокобезопасность:** манипуляции с файлом, регистрацией секретов, буфером и повторами защищены `threading.RLock()` (`journal.py:11,28,84,165,175,181`). При этом `RLock` не покрывает чтение списка маскировки (`_sorted`) внутри `mask(...)` в `log()`, так как маскировка `data` и `why` выполняется до захвата блокировки (`journal.py:61,161,163,165`).

## 2. Сборщик журналов на сервере (`lab/server/ra_lab.py`)

### 2.1. Конфигурация и запуск
- **CLI команда:** `ra-lab [--pc <PC>] collect [--every 20]` (`ra_lab.py:560,585`).
- **Период опроса:** по умолчанию 20 секунд (`--every 20`) (`ra_lab.py:555,585`).
- **Каталоги и файлы на сервере:**
  - Каталог сбора журналов ПК: `~/work/logs-in/lab/<pc>/` (`ra_lab.py:497-500`).
  - Файл вех (milestones): `~/work/logs-in/lab/<pc>/milestones.jsonl` (`ra_lab.py:503-509`).
  - Файл сохранённых смещений: `~/work/logs-in/lab/<pc>/.offsets.json` (`ra_lab.py:517-518`).
- **Отслеживание версии (`cmd_collect`):**
  - При несовпадении `st.get('version')` с предыдущим значением фиксируется веха (`ra_lab.py:547-549`):
    `{"ts": "<ISO8601_seconds>", "ev": "version", "version": ..., "rollback": ...}`.
- **Ошибки цикла опроса:**
  - `SystemExit` (канал недоступен / ПК выключен) перехватывается, цикл ждёт следующий интервал (`ra_lab.py:551-552`).
  - Прочие исключения логируются в `sys.stderr` вида `collect: %s` (`ra_lab.py:553-554`).

### 2.2. Протокол инкрементального сбора (`collect_once`)
1. **Запрос корня данных ПК:**
   - Вызов `GET /status` (`ra_lab.py:513`, `agent.py:173-174`).
   - Извлекается `home`; если `home` отсутствует — возврат `0` байт (`ra_lab.py:513-515`).
   - Путь к журналам на ПК: `logs = home + '\\logs'` (`ra_lab.py:516`).
2. **Получение списка файлов:**
   - Вызов `GET /files?path=<quote(logs)>` (`ra_lab.py:520`, `agent.py:281`).
   - Фильтрация записей: игнорируются каталоги (`e['dir']`), файлы без префикса `lab-`, файлы с `size is None` (`ra_lab.py:521-523`).
3. **Обнаружение перезапуска / усечения файла:**
   - Если размер файла на клиенте меньше зафиксированного смещения (`e['size'] < offs.get(n, 0)`):
     - Локальный файл переименовывается в `<local>.old-<int(time.time())>` (`ra_lab.py:525-527`).
     - Смещение файла сбрасывается в 0: `offs[n] = 0` (`ra_lab.py:528`).
4. **Порционная выкачка байтов:**
   - Пока `offs[n] < e['size']` (`ra_lab.py:529`):
     - Вызов `GET /read?path=<quote(logs + '\\' + n)>&offset=<offs[n]>` (`ra_lab.py:530`, `agent.py:252-254`).
     - Параметр `length` в запросе не передаётся, действует ограничение агента `CHUNK = 4 * 1024 * 1024` байт (4 МиБ) (`agent.py:16,254`).
     - Декодирование содержимого `b64` (`ra_lab.py:531`, `agent.py:262`). При получении пустого буфера — выход из цикла (`ra_lab.py:532-533`).
     - Дозапись в локальный файл `open(local, 'ab')` (`ra_lab.py:534-535`).
     - Продвижение смещения: `offs[n] = offs.get(n, 0) + len(b)` (`ra_lab.py:536`).
     - Подсчёт переданных данных: `got += len(b)` (`ra_lab.py:537`).
   - Сохранение актуальных смещений в `.offsets.json` выполняется один раз на файл после завершения цикла чанков (`ra_lab.py:538`).
5. **Возврат:** общее число полученных за вызов байтов (`got`) (`ra_lab.py:539`).

## 3. Смежные HTTP-эндпоинты агента (`lab/ralab/agent.py`)

- **`GET /log?n=<count>`** (`agent.py:194-195`):
  - Параметр `n`: число строк из хвоста буфера (по умолчанию `200`).
  - Ответ `200`: `{"records": [...]}`.
- **`GET /files?path=<path>`** (`agent.py:281-297`):
  - Лимит записей: `LIST_MAX = 2000` элементов (`agent.py:16,287-288`).
  - Ответ `200`: `{"path": "<path>", "entries": [{"name": "...", "dir": bool, "size": int|null, "mtime": int|null}]}` (`agent.py:291-294`).
  - Ошибка `404`: `{"error": "<Exception>: <text>"}` (`agent.py:295-296`).
- **`GET /read?path=<path>&offset=<offset>&length=<length>`** (`agent.py:252-263`):
  - Ограничение размера: `min(length, CHUNK)` где `CHUNK = 4194304` (4 МиБ) (`agent.py:16,254`).
  - Ответ `200`: `{"size": <total_size>, "offset": <offset>, "b64": "<base64_data>", "eof": <bool>}` (`agent.py:262`).
  - Ошибка `404`: `{"error": "<Exception>: <text>"}` (`agent.py:260-261`).
