# VPN и ЛВС клиники в v3 (N1a, N1b, N2)

Всё включается только конфигом (`vpn.mode` auto|only, непустой `lan[]` с `share.subnets`) и не при `--safe`/`--no-tun`.
По умолчанию после обновления ничего нового не включается. Адаптеры: `ra3-<8 hex экземпляра>-vpn` (RA3-VPN) и `-lan` (RA3-LAN),
VPN — в ОТДЕЛЬНОМ процессе sing-box, ЛВС — в общем с каналом; записываются трейсом `adapter` до запуска и снимаются cleanup при выходе, падении и старте (остатки прошлого запуска).

Правила VPN (по порядку): процессы v2 Лаборатории (ra-lab, её sing-box) и Happ/Tailscale/xray -> direct; sniff; приватные -> direct;
domain_suffix (vpn.direct.domains) -> direct; rule_set geoip-ru (`state/geoip-ru.srs`, если файл есть) -> direct; остальное -> urltest по vpn.bridges.
route_exclude: приватные сети, 109.199.110.63, IP всех узлов путей из конфига. ЛВС: только подсети lan[] (не пересекающиеся с адресами ПК), через внутренний SOCKS.
Если адаптер RA2-LAN (v2) есть, ЛВС v3 не поднимается: событие `lan.skipped-v2`. Чужой VPN — любой интерфейс, через который ОС ведёт трафик к 1.1.1.1 (не железный и не наш), по имени не ищется: VPN v3 не включается (`vpn.skipped-foreign`, при смене имени); по событию сети (включили/выключили чужой) сторож пересчитывается сам (`foreign-changed`), канал не сбрасывается.
DNS/NRPT/hosts не трогаются.

Fail-open VPN: 1-я неудачная проверка — один повтор через 5 с; 2-я (или падение sing-box с TUN) — перезапуск без TUN VPN (`vpn.failopen`);
3-я — режим off до команды /vpn (`vpn.off`). Возврат из failopen — по смене сети или команде. Состояние: `/state` -> `vpn`, событие SSE `vpn`, агент `/vpn {mode}`.

## Отдельный процесс VPN и конфиг «только VPN» (27.11)
VPN — второй экземпляр sing-box: копия `RemoteAgents-VPN.exe` (на других ОС `ra-vpn`) в `bin`, свой конфиг-файл, свой clash-порт, адаптер `ra3-<id>-vpn`, процесс `singbox-vpn`. Включить = запустить, выключить/чужой VPN/failopen = остановить; sing-box канала и ЛВС не перезапускается. Мосты — напрямую через физический интерфейс (default_interface), журнал sing-box VPN — только warn. Уборка — по трейсам `process`/`adapter` при выходе, падении и старте.
Конфиг «только VPN»: есть `vpn`, нет `server` (и `paths` не нужен). Узлы — `vpn.nodes`: `{имя: "enc1:..."}`, внутри зашифрован outbound sing-box (JSON с `type`); `vpn.bridges` — белый список имён (пусто — все), имена путей из `paths` тоже работают, если они есть. `vpn.mode` по умолчанию `auto`. Канал, ЛВС, Диск, forward не запускаются, страница пишет «канал не настроен», конфиг принимается сразу.

## Живая проверка на ПК (только с «да» владельца; v2 14.3 не трогать)
1. Конфиг с `vpn:{mode:"auto"}`, запустить exe без `--safe`. Ожидать: адаптер `ra3-xxxxxxxx-vpn`, в /state `vpn.state=up`, `vpn.probe-ok` в журнале;
   v2 Лаборатория и канал не оборвались (проверить связь с ПК до и после). Сайт .ru открывается напрямую, внешний IP — выход моста.
2. С запущенным чужим VPN: ожидать `vpn.skipped-foreign`, его адаптеры не тронуты; выключить чужой VPN → `vpn.state=up` без перезапуска; включить → наш снят.
3. Конфиг `lan:[...]` при живой RA2-LAN: `lan.skipped-v2`, RA3-LAN нет. Без RA2-LAN: адаптер `-lan`, подсеть клиники пингуется.
4. Fail-open: убить мост/выдернуть сеть при VPN up -> `vpn.fail`, затем `vpn.failopen`, адаптер -vpn исчезает, канал живёт.
5. Выход из программы и убийство ядра (taskkill): адаптеры/маршруты исчезли (`Get-NetAdapter ra3-*` пусто), при следующем старте cleanup чистый.
Откат: `/vpn off` (агент), убрать `vpn`/`lan` из конфига, либо запуск с `--safe`; аварийно — `leftovers.ps1`.
Не сделано: загрузка geoip-ru.srs (файл кладётся в state вручную/установщиком).
