# Шлюз Telegram Bot API

HTTPS-шлюз на Python 3.10+ (только стандартная библиотека, без pip).
Мастер установки сервера ставит и включает его от рабочего SSH-пользователя
как отдельную фоновую операцию `tg-gateway` вместе с остальными службами.
Проверка состояния ничего не устанавливает. Исходники входят в бандл мастера;
рабочая установка всегда находится в `~/.local/opt/tg-gateway`, вне checkout.

Для отдельной установки или обновления от того же пользователя:

```bash
bash server/tg-gateway/install.sh
# Только проверка службы, автозапуска и локального HTTPS:
bash ~/.local/opt/tg-gateway/install.sh --check
```

Нужны Linux с `/proc`, `/usr/bin/python3`, `openssl`, `ip` (iproute2),
`systemd --user`. Установщик не использует sudo и не ставит системные пакеты.
Он пробует `loginctl enable-linger --no-ask-password <uid>`; отказ даёт
предупреждение, установка продолжается. Без linger служба может остановиться
при выходе пользователя. При недоступном user manager установка сообщает ошибку.

## Адрес, порт и обновление

Адрес выбирается заново при каждой установке:

1. `TG_GW_PUBLIC_HOST`, если задан: IP или DNS-имя без схемы и порта.
2. Публичный IPv4 интерфейса default-маршрута **таблицы main**:
   `ip -j route show table main default` и `ip -j -4 addr`.
   Учитывается метрика маршрутов; исключаются частные и служебные адреса,
   CGNAT `100.64.0.0/10`, loopback, docker/bridge, tun/tap/wg и туннели sing-box.

Таблицы policy routing и `ip route get` не используются: системный TUN
(например, в таблице 2022) не должен подменять адрес сервера.
Если публичного IPv4 на интерфейсе нет (например, NAT), нужна явная настройка:

```bash
TG_GW_PUBLIC_HOST=gateway.example.org bash server/tg-gateway/install.sh
```

Порт: `TG_GW_PORT` → сохранённый `state/settings.json` → первый свободный
в `8444..8499`. Для старой ручной установки без settings сначала переносится
`TG_GW_PORT` из Environment существующего systemd-unit. Занятый сохранённый или
явно заданный порт сохраняется только тогда, когда все слушающие его TCP-сокеты
принадлежат MainPID службы `tg-gateway`. Если порт занят другим процессом,
установка завершается с подсказкой; чужие службы не останавливаются.

`state/settings.json` содержит `{"public_host":"…","port":8444}` с правами 600.
Утилита ключей читает адрес и порт именно из этого файла, рядом с `keys.json`;
переменные адреса/порта в окружении утилиты не меняют данные подключения.

Сертификат самоподписанный, SAN содержит публичный IP (или DNS-имя) и `127.0.0.1`.
При подходящем SAN установщик сохраняет сертификат и закрытый ключ.
При изменении хоста/SAN старая пара сохраняется в `tls/old-<дата UTC>/`,
создаётся новая и печатается предупреждение: **клиентам нужен новый сертификат**.
Неполная или повреждённая существующая пара даёт ошибку без её удаления.
`state/keys.json` никогда не заменяется установщиком.

Обновление атомарно заменяет файлы кода и unit, выполняет `daemon-reload`,
`enable`, `restart`, затем до 10 секунд проверяет HTTPS `/health` через loopback
с проверкой сертификата (без прокси). В конце печатает публичный адрес, порт,
путь сертификата и SHA-256 отпечаток. Для смены адреса/порта повторите установку
с нужными переменными; изменения применяются к установленной службе.

## Ключ для клиента

```bash
~/.local/bin/tg-gateway-keys add client-name
~/.local/bin/tg-gateway-keys add another-client --json
~/.local/bin/tg-gateway-keys list
~/.local/bin/tg-gateway-keys revoke client-name
~/.local/bin/tg-gateway-keys show-cert
```

`add` один раз выводит секретный URL `https://<хост>:<порт>/<ключ>`, PEM,
SHA-256 отпечаток и примеры curl, python-telegram-bot, aiogram, Telegraf,
node-telegram-bot-api. `--json` выводит только один JSON-объект:
`{"base_url":"https://…/<ключ>","ca_pem":"-----BEGIN CERTIFICATE-----\n…","sha256":"AA:BB:…"}`.
Имя: 1–40 символов `a-z`, `0-9`, `.`, `_`, `-`, начало — буква или цифра.
Повторное `add` с тем же именем завершается ошибкой; секрет повторно не выдаётся.

Передайте клиенту эти данные, сохраните PEM как `gw.pem` и подключите его
как доверенный CA в HTTP-клиенте. Проверку TLS оставьте включённой.
Базовый URL содержит секрет и должен храниться как пароль.
На шлюзе хранится только SHA-256 ключа, имя и время создания;
добавление и отзыв применяются без перезапуска (проверка файла раз в 2 секунды).
Файл ключей записывается атомарно под блокировкой, права 600, `state/` — 700.

## API и служба

Разрешены только:

- `/<ключ>/bot<токен>/<метод>` — GET/POST;
- `/<ключ>/file/bot<токен>/<путь>` — GET; сегменты `.` и `..` запрещены;
- `/<ключ>/health` — GET без обращения к Telegram;
- `/health` — GET без ключа только с `127.0.0.1`.

Ключ удаляется перед отправкой в Telegram; query передаётся без изменений.
Неизвестный/отозванный ключ и неверный путь дают одинаковый 404,
неподдерживаемый метод с верным ключом и путём — 405.
Повреждённый файл ключей сохраняет прежний набор; отсутствие файла очищает его.
Тела передаются потоком, предел запроса — 52 МиБ, таймаут — 90 с.
До 256 соединений всего, 16 с одного IP, включая TLS/keep-alive.
По умолчанию разрешены любые IP; `TG_GW_ALLOW` задаёт IP через запятую
(отказ до TLS). Шлюз игнорирует `*_PROXY` и проверяет сертификат Telegram.

Параметры процесса службы (дополнительные значения — через user-unit override):

| Переменная | Значение по умолчанию |
| --- | --- |
| `TG_GW_PORT` | установщик сохраняет выбранный порт в unit; отдельный процесс — 8444 |
| `TG_GW_CERT`, `TG_GW_KEY` | `<каталог кода>/tls/cert.pem`, `tls/key.pem` |
| `TG_GW_KEYS` | `<каталог кода>/state/keys.json` |
| `TG_GW_ALLOW` | пусто (все IP) |
| `TG_GW_PER_IP` | 16 |
| `TG_GW_UPSTREAM_HOST`, `TG_GW_UPSTREAM_PORT` | `api.telegram.org`, 443 |
| `TG_GW_UPSTREAM_CAFILE` | системные корни |

Утилита ключей также поддерживает `TG_GW_KEYS` и `TG_GW_CERT` для отдельных
каталогов состояния/сертификата. Settings ищется рядом с выбранным файлом ключей.
Журналы содержат время, имя клиента, метод, код и длительность;
ключи, токены, пути, query, заголовки и тела не журналируются.
Не включайте внешние access-логи с полными URL.

```bash
systemctl --user status tg-gateway.service
journalctl --user -u tg-gateway.service -f
curl --noproxy '*' --cacert ~/.local/opt/tg-gateway/tls/cert.pem https://127.0.0.1:<порт>/health
# Из корня репозитория:
python3 -m unittest discover -s server/tg-gateway -p 'test_*.py' -v
python3 -m unittest discover -s app/launcher/tests -p 'test_server_operations.py' -v
```

Тесты используют временные HOME/сертификаты, подменённые ip/systemctl/loginctl
и только `127.0.0.1:18xxx`. Telegram и действующая установка не затрагиваются.
